# Систематические ошибки

Повторяющиеся ошибки проектирования и процесса. Файл без лимита строк:
сюда копится всё, что уже случалось минимум дважды или грозит повториться в
любой волне. Этапные, единичные ошибки — в `stages/stage-NN/errors.md`.

Формат: `E-xx · дата · симптом · причина · урок/правило · источник`.

---

## E-01 · Незакоммиченная работа гибнет вместе с песочницей

**Симптом.** Сессия выполнила большой объём работы, но не сделала коммит;
песочница умерла — потеряно всё, включая `/tmp` и логи.
**Случай.** CR-01 PR 4 (октябрь 2026): заново восстанавливали модули по
логам `commands.txt` и `dialog (6).txt`.
**Причина.** Работа считалась сохранённой по индикаторам UI, а не по Git.
**Правило.** В начале задачи — ветка и первый содержательный коммит с
`git push -u origin HEAD`. После каждого логического шага — коммит и пуш.
Проверка сохранности только через `git status --short`, `git log` и
`git rev-parse HEAD` = `origin/<ветка>`.
**Источник.** [`AGENTS.md` §6](../../AGENTS.md), [`handoff/infra-pitfalls.md`](../handoff/infra-pitfalls.md).

## E-02 · Гонка инструментов записи

**Симптом.** Файл после записи оказывается пустым или частичным, хотя
`write_file` вернул успех.
**Причина.** Запись файла и зависящая от неё shell-команда отправлены в одном
блоке и выполняются параллельно.
**Случай.** При восстановлении `planet-geography.ts` дважды терялась часть
файла.
**Правило.** Зависимые шаги — строго разными сообщениями. Не смешивать
`write_file`/`edit_file` с `bash`, который читает этот файл, в одном блоке.
**Источник.** [`handoff/infra-pitfalls.md`](../handoff/infra-pitfalls.md), AGENTS.md §6.

## E-03 · Доверие индикаторам UI вместо Git

**Симптом.** Счётчик изменённых строк зависает на «+712», создаётся
впечатление потери данных.
**Причина.** UI-индикатор не является транзакционным источником правды.
**Правило.** Только `git status`, `git diff --name-only`, `git log`.
**Источник.** [`handoff/infra-pitfalls.md`](../handoff/infra-pitfalls.md).

## E-04 · Слепое доверие сплющенным логам старых сессий

**Симптом.** В восстановленном коде появляются несуществующие имена
(`plateTop1Id` вместо `plateId`) и выдуманные формулы.
**Причина.** `//`-комментарии в логах «съедают» следующий код; конспекты
искажают имена.
**Правило.** Эталоны брать из репозитория, а не из `/tmp`; extracted-код
резать по смыслу и валидировать `tsc` + побитовым FULL EQ.
**Источник.** [`handoff/infra-pitfalls.md`](../handoff/infra-pitfalls.md).

## E-05 · «Эффект Франкенштейна»: параллельные реализации

**Симптом.** После миграции остаются старый `.js`-монолит и новый TS-модуль
с теми же обязанностями; правка попадает только в одну ветку.
**Причина.** Новый код добавлялся рядом, старый не удалялся; не было
инварианта единственного источника.
**Правило.** И-5: новый и мигрированный код — только строгий TypeScript;
параллельные реализации запрещены. Удаление легаси — часть того же PR.
**Источник.** [`plan/cr-01/stack-selection.md`](../plan/cr-01/stack-selection.md) §И-5,
[`AGENTS.md` §4](../../AGENTS.md).

## E-06 · Дрейф идентичности между canonicalV и renderV

**Симптом.** На телефоне/при смене LOD «та же планета» даёт другой ландшафт,
другое число ячеек или разный `generation_key`.
**Причина.** Рендер-разрешение подменяло каноническое `v`; поля считались по
renderV, а не по канону.
**Правило.** И-1/И-2: канонический `v` в контракте и ключе, renderV — только
для отрисовки; поля сэмплируются по направлению и не зависят от `v`.
**Источник.** [`plan/cr-01/stack-selection.md`](../plan/cr-01/stack-selection.md),
[`stages/stage-07/plan.md`](../stages/stage-07/plan.md).

## E-07 · Регрессия из-за замены разметки вместо добавления слоя

**Симптом.** После волны Stage-8.7 кнопка «← На глобус планеты» исчезла:
оверлей квик-навигации занял место `#localMapStage`.
**Причина.** `host.replaceChildren(...)` вместо `host.append(...)`.
**Случай.** Регрессия #204, исправлена Stage-8.7.3.
**Правило.** Новый UI-слой добавляется отдельным узлом и не замещает
существующую разметку; на каждое такое вмешательство — DOM-тест.
**Источник.** [`stages/stage-08/errors.md`](../stages/stage-08/plan.md),
[`handoff/status.md`](../handoff/status-and-state.md).

## E-08 · Документация отстаёт от кода и начинает противоречить

**Симптом.** Числа в гайдлайнере (`186` систем, `1 000` единиц = `1` св.г.,
`L0…L9`) не совпадают с данными и кодом.
**Причина.** Документ правился отдельно от замера; не было обязательной
сверки с `data/*.csv` и тестами.
**Правило.** Каждая редакция чисел подтверждается замером/скриптом и
ссылкой; при расхождении приоритет у кода `main` и явного решения владельца.
**Источник.** [`stages/stage-09-12-sector/errors.md`](../stages/stage-09-12-sector/plan.md),
гайдлайнер §15.

## E-09 · Изменение золотых значений «чтобы тесты позеленели»

**Симптом.** Красные golden-тесты правятся пересчётом эталона, после чего
регрессия маскируется.
**Причина.** Не установлено, чей дрейф: код или эталон.
**Правило.** Сначала измерение и объяснение дрейфа, потом решение.
Пересчёт golden — отдельный коммит с доказательством.
**Источник.** [`stages/stage-08/bugs.md`](../stages/stage-08/plan.md),
[`handoff/infra-pitfalls.md`](../handoff/infra-pitfalls.md).

## E-10 · Смешение уровней документа: план, отчёт и журнал в одном файле

**Симптом.** Файл на 1 800–2 400 строк, в котором перемешаны цели, замеры,
история правок и открытые вопросы; агент читает его целиком и теряет
актуальное.
**Причина.** Не было разделения по типам данных и контексту.
**Правило.** Пять файлов этапа (plan/errors/bugs/decisions/todo) + `notes/`;
каждый ≤ 200 строк; старые пути — короткие хабы.
**Источник.** [`README.md`](../README.md), это решение 26.10.2026.

## E-11 · Гайдлайнер читает код вместо воркера

**Симптом.** Окно оркестратора заполняется исходниками и логами тестов; к моменту постановки
карточки контекст уже перегружен, контракты и журнал решений страдают.
**Случай.** Подготовка карточки `F-3` (26.10.2026): глубокая разведка `src/`, `tests/`,
`tools/` проведена самим `rc-07` вместо спецификации поиска воркеру.
**Причина.** Нарушение иерархии: оркестратор подменил воркера; регламент §4 ограничивал объём
чтения, но явно не запрещал контакт с кодом.
**Правило.** Правило О-5: нулевой контакт Гайдлайнера с кодом. Любой факт о реализации —
через спецификацию поиска воркеру (формат, область, лимит строк); проверка — CI и отдельная
задача `rc-04`, а не собственные прогоны и worktree.
**Источник.** [`waves/protocol.md`](../agents_task_orchestration/waves/protocol.md) §3 О-5,
[`role_cards/rc-07-wave-orchestrator.md`](../agents_task_orchestration/role_cards/rc-07-wave-orchestrator.md) §3 п.9.

## E-12 · «Страница отдаёт 200» ≠ «приёмка пройдена»: ловушки локального стенда

**Симптом.** Собранная страница отвечает `200`, скрипты и стили приходят, а проверяющий
видит битые картинки, пустой экран или «редактор не работает»; у воркера браузера нет, и
увидеть это сам он не может.
**Случай.** Сессия 06.11.2026, карточка секторного редактора (PR #360): стенд поднят
статикой над `.publish/`, `/sector/admin-edit/` отвечает `200`, но у владельца страница
«не работала», а в логе сервера не было ни одного запроса к `/data/`.
**Причина — четыре разные, не путать.**
1. `npm run build` не копирует сгенерированные картинки: `assets/*.webp` делает отдельный
   `npm run assets:build` (`tools/build_assets.py`, нужен Pillow). Без него четыре
   `/assets/*.webp` (`timeline-project-logo`, `koprulu-macket`, `ozd-macket`,
   `galaxy-map-1200`) отдают `404`: в Git лежат только исходники `assets/src/`,
   производные не попадают.
2. `vite dev` непригоден для приёмки: пайплайн публикации подставляет хешированные имена
   (`/shared/app-<hash>.js`), которых в режиме разработки нет — по этому адресу приходит
   HTML приложения. Проверять только собранный `.publish/`. При этом `AGENTS.md:68`
   указывает `npm run dev`, которого в `package.json` нет (дрейф документации;
   зафиксировано, файл вне карточки — не правил).
3. Скрытая панель — штатное поведение, а не поломка: `bindSectorAdminGate` держит
   `[data-admin-editor]` за `hidden` до совпадения публичного тест-кода
   (`KP-ADM-DEMO-27`). На приёмке это читается как «редактор не открылся».
4. **Не подтверждено.** Один раз приложение в браузере не сделало ни одного запроса к
   `/data/` при успешно загруженных скриптах; тот же билд в jsdom стартует без ошибок и
   данные грузит. После исправления картинок и перезагрузки не повторялось — оставлено
   наблюдением, а не диагнозом.
**Правило.** Приёмку UI вести на собранном `.publish/` с картинками и тест-кодом;
отсутствие запросов к данным считать маркером раннего падения, а не «данных нет»;
браузерную ошибку снимать диагностикой (перехват `error`/`unhandledrejection` и
`new Image().src = '/__diag?...'` — строка в логе сервера), а не догадками;
headless-браузера в песочнице нет — см. [`B-S03`](bugs-infra-ci-and-sandbox.md).
**Источник.** PR #360, [`admins/sector-areas-editor.md`](../admins/sector-areas-editor.md),
`tools/build_assets.py`, `vite.config.mts`, [`AGENTS.md` §3](../../AGENTS.md).
