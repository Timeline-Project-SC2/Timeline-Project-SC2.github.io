# Заявка на свойства точек: контракт и отправка

Статус: **код и проверки локальные, ничего не развёрнуто**. Живая отправка
Issue, применение правки и публикация — `HOLD` до отдельного разрешения
владельца. Создание Issue не доказывает ни применение, ни публикацию.

Назад: [свойства объектов и заявка](sector-object-properties-and-issues.md) ·
[OAuth-ядро](sector-issue-oauth-local.md) · [индекс](../README.md).

## Что теперь зафиксировано

| Что | Где | Смысл |
|---|---|---|
| Схема заявки, канонический вид, проверка тела | `src/issue-gateway/property-issue-contract.ts` | Один контракт для браузера и Worker: клиент не может собрать то, что сервер не примет |
| Сообщения GitHub Issues | `src/issue-gateway/github-issues.ts` | Проверка репозитория по ID, поиск уже созданной заявки, отсутствие слепого повтора |
| Сборка заявки из сессии | `src/atlas/sector-property-packet.ts` | `requestId`, заголовок по отпечатку, предупреждения человеку |
| Отправка из редактора | `src/atlas/sector-property-submit.ts` | Один POST без ретраев; «неизвестно» остаётся неизвестным |
| Маршрут шлюза | `worker/src/index.ts` → `POST /issues/submit` | Origin, сессия, формат, затем GitHub |
| Заполнение адреса шлюза | `templates/atlas-shell.html`, `tools/vite/atlas-shell.ts` | Пусто = отправка выключена; только абсолютный https из `ATLAS_ISSUE_GATEWAY_URL` |

Заголовок заявки: `[ADM-ACCESS] свойства точек · <первые 12 символов
отпечатка пакета>`. Маркер нужен, чтобы отделить заявки от обычных Issue; он
**не** является доказательством прав.

## Формат пакета

```json
{
  "type": "sector-property-request",
  "version": 1,
  "requestId": "pr-<время в base36>-<32 hex>",
  "repositoryId": 1421259694,
  "baseRevision": "<64 hex: отпечаток входов сборки>",
  "changes": [
    { "dataset": "systems", "recordId": "1", "field": "description", "before": "старое", "after": "новое" }
  ]
}
```

Тело Issue содержит таблицу «было → стало» для человека и этот же JSON в
ограждении между маркерами `<!-- sector-property-request:v1:begin -->` и
`<!-- sector-property-request:v1:end -->`. Сервер принимает тело, только если
оно **байт-в-байт** совпадает с повторным рендером контракта: другой порядок
ключей, лишние пробелы, CRLF и посторонний текст вокруг блока отклоняются.
Это защищает отпечаток от подмены текста «на глаз».

Ограничения: до 100 изменений, до 50 объектов, значение до 4000 символов
(`source_url` — до 2048), тело до 60 000 байт. `ID` не редактируется,
координаты и связь с системой — отдельные операции, а не поля свойств.

## Защита от дублей и честность результата

- `requestId` фиксируется **до** запроса и сохраняется в редакторе; повтор
  после неизвестного результата идёт с тем же ID.
- Перед созданием шлюз сверяет репозиторий по ID и ищет Issue с этим ID
  (до 5 страниц по 100). Найдено → `existing`, второй Issue не создаётся.
- 3xx, 5xx, 429, таймаут, нечитаемый ответ и несовпадение кода со статусом —
  `unavailable`: заявка могла быть создана. Автоматического повтора нет.
- Созданная Issue сверяется по заголовку и телу; несовпадение — не успех.
- Ответ шлюза: `created` (201) или `existing` (200) с номером и ссылкой.
  Ни токена, ни кода, ни текста заявки в ответах нет.
- Остаточное окно гонки между поиском и созданием: GitHub не даёт атомарной
  операции «создай, если нет». Это ограничение, а не гарантия.

## Безопасность канала

Сайт (`*.github.io`) и Worker — разные сайты, поэтому cookie сессии ставится
`SameSite=None; Secure; HttpOnly`; иначе браузер не приложит её к cross-site
запросу. Взамен:

- `POST /issues/submit` требует точный `Origin` из `SITE_ORIGIN` (без
  `SITE_ORIGIN` маршрут закрыт), JSON-тело и сессию;
- preflight `OPTIONS` отвечает только своему Origin, без wildcard;
- cookie привязки OAuth остаётся `SameSite=Lax` на пути `/auth`.

Не проверено: поведение в реальной сети Cloudflare, платформенные логи,
`Referer`/`history`, отзыв сессии при отзыве токена.

## Защита слоя от синхронизации

`tools/sync.py` слой поправок не пишет, и это теперь закреплено двумя
линиями:

1. `property_overlay_problems()` проверяет `data/sources.json` **до** любой
   записи: если какая-либо цель источника указывает на
   `data/sector-property-overlay.json` (включая вложенные и абсолютные пути),
   sync завершается с ошибкой и ничего не трогает.
2. Шаг «Проверить, что слой поправок не изменён» в
   `.github/workflows/sync.yml` падает, если файл всё же изменился, — вместо
   тихого коммита `git add data/`.

Нераспознаваемый слой (не JSON, не `version: 1`, неизвестный dataset или
поле) sync не перезаписывает, но честно предупреждает, что содержимое не
подтверждено. Тесты: `tests/test_sync.py`, класс
`PropertyOverlayProtectionTest` (7 проверок, включая полный прогон sync с
непустым слоем).

## Чего это не делает

- Не проверяет роль Owner: `tools/issue_owner_check.mjs` остаётся отдельным
  свидетельством для будущего применителя, и он не подключён.
- Не применяет правку: `data/sector-property-overlay.json` пишет только
  человек/будущий применитель после проверки, а не этот путь.
- Не публикует: обновление сайта — отдельная стадия с отдельным статусом.
- Не решает конфликты значений: `src/issue-gateway/property-conflicts.ts`
  остаётся офлайн-оценкой, серверная проверка базы — следующий этап.

## Проверки

| Файл | Что доказывает |
|---|---|
| `tests/issue-property-packet.test.mjs` | Схема, канонический вид, экранирование Markdown, ограждение, блокировка секретов |
| `tests/issue-github-issues.test.mjs` | Фиктивный API: успех, `exists`, неизвестный результат, чужой репозиторий, отсутствие утечек |
| `tests/sector-property-submit.test.mjs` | Клиент: один POST, `credentials: include`, `redirect: error`, «выключено» без шлюза |
| `tests/worker-submit.test.mjs` | miniflare: сессия, Origin/CORS, preflight, дубль, отказ GitHub, logout |

Проверено локально: `node --test` по этим четырём файлам (12 + 10 + 9 + 13
проверок), `tsc`, `eslint`, `npm run build` (с `ATLAS_ISSUE_GATEWAY_URL` тег
заполняется, без неё — пуст), `npm run verify:publish`.
Не проверено: живой GitHub, реальный Cloudflare, браузерная приёмка кнопки.

## Перед включением

1. Владелец подтверждает развёртывание Worker и настройки OAuth App
   (callback, `wrangler secret put GITHUB_CLIENT_SECRET` — не в чате).
2. Сборка сайта получает `ATLAS_ISSUE_GATEWAY_URL=https://<worker-domain>`.
3. Только после этого — отдельное разрешение на пробную живую Issue.
4. Применение правки и публикация остаются выключенными до следующего этапа.
