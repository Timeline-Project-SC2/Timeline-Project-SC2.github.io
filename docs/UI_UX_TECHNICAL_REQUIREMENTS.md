# Технические требования к UI/UX — StarCraft II Web Atlas

**Источник:** Part III (Interaction Design), Part IV (Navigation), Part VII (Apple UI/UX Principles), Part VIII (AI Slop UI) — *UI/UX AI Skill — The Complete Field Manual*.  
**Адаптация:** все примеры интернет-магазинов и мобильных приложений удалены. Требования переписаны под десктопный веб-атлас вселенной StarCraft II.  
**Статус:** операционный протокол для верстки и интерфейсной разработки (`site/`, `templates/`, `src/`). Обязательный минимум перед merge в `main`.

## 1. Взаимодействие: удаление трений (Part III)

### 1.1 Одно доминирующее действие на панели `[☐ todo]`
На каждой панели — **одно** доминирующее действие. Карта — контекст, не панель, поэтому на Sector Map допустимы несколько активных зон (выбор системы, перемещение, зум), но внутри каждой панели (Planet Detail Card, Travel Planner, фильтры) доминирует только одна первичная цель.

- **Planet Detail Card:** первичное действие — «Центрировать на карте» или «Добавить в маршрут». Остальное — справочная информация.
- **Travel Planner:** первичное действие — подтверждение маршрута («Построить» / «Полёт»). Поля ввода — вспомогательные.
- **Панель фильтров:** первичное действие — применение или сброс фильтра, не несколько равнозначных кнопок действий.

### 1.2 Поиск — момент намерения `[✓ impl]`
Поиск по Sector Map не должен быть пустым полем. Реализовано в `site/shared/styles.css` (`.search-wrap`, `.suggestions`).

- При фокусе на поисковой строке показываются: недавние системы, популярные регионы, персонализированные подсказки.
- Подсказки поддерживают навигацию клавиатурой (`↑`/`↓` для перехода, `Enter` для выбора, `Esc` для закрытия).
- Фокус на поиске — по клавише `/` (уже реализовано). `Cmd/Ctrl+F` оставляем нативному поиску браузера, не перехватываем.
- Пустой результат поиска — не мёртвый конец: конкретное сообщение + действие (например: «Систем не найдено. Попробуйте другой запрос или сбросьте фильтры»).

### 1.3 Распознавание вместо воспоминания `[✓ impl]`
Системы и планеты показываются через иконку/цвет/глиф, а не через абстрактные ID, которые пользователь должен запомнить. Реализовано в `.row-glyph`, `.row-status`, цветных чипах фракций.

- Каждый hotspot на Sector Map имеет визуальный маркер.
- В Planet Detail Card тип мира и фракция отображаются цветным чипом, а не только текстом.

### 1.4 Пустые состояния — возможности, не тупики `[☐ todo]`
Если в Sector Map не найдено систем по фильтру, или в Travel Planner нет маршрута, экран не пустой:

- конкретный заголовок (например: «Систем не найдено»),
- краткое пояснение,
- конкретное действие («Сбросить фильтры», «Задать начальную точку», «Открыть каталог систем»).

Также к пустым состояниям относится потеря контекста WebGL (context lost) — пользователь должен видеть понятное сообщение и действие («Перезагрузить сцену»), а не пустой холст. Применяется к `/sector/` и `/planet-globe/`.

### 1.5 Пользователь не начинает с нуля `[☐ todo]`
При открытии Travel Planner:

- точка отправления (А) предзаполняется текущей выбранной системой,
- точка назначения (Б) остаётся открытой для выбора с выпадающим списком недавних/популярных целей.

Пустая форма — запрещена.

### 1.6 Мгновенная обратная связь `[✓ impl] / [☐ todo]`
Каждое действие даёт визуальный отклик в течение 100–300 мс. Реализовано для `:hover` и `.selected` в `styles.css`. Требуется добавить:

- toast-уведомление после успешного построения маршрута или ошибки расчёта в Travel Planner `[☐ todo]`,
- состояние загрузки (скелетон/спиннер) при загрузке карты и каталога `[☐ todo]`.

## 2. Навигация Sector Map (Part IV)

### 2.1 Состав навигации `[✓ impl]`
В навигацию входят только **3–5 основных целей** (адаптировано под десктоп):

1. Sector Map (обзорная карта / возврат к карте),
2. Каталог систем (левая панель),
3. Planet Detail Card (досье выбранного объекта),
4. Travel Planner (планирование маршрута),
5. Справка / настройки (вторично, через иконку).

Не входят: разделы помощи как отдельные пункты навигации, выход, юридические страницы, логотип как навигационный элемент.

### 2.2 Размеры целей и зона нажатия `[✓ impl] / [☐ todo]`
Минимальный размер интерактивной цели — **44×44 CSS px** (уровень WCAG 2.1 AAA, правило 2.5.5). На десктопе с точным указателем (`pointer: fine`) допустимо снижать до 32×32 CSS px, но не ниже 24×24 CSS px (уровень AA, правило 2.5.8). На вебе используются CSS-пиксели, не iOS-points; не смешивать `pt` и `px`.

Кнопки управления картой (зум, слои) и элементы Planet Detail Card не могут быть меньше 32×32 CSS px. В Travel Planner поля ввода и кнопки подтверждения — не менее 35–44 px по высоте.

### 2.3 Активное состояние `[✓ impl]`
Активный элемент навигации имеет **не менее двух одновременных визуальных изменений**:

- заливка → контур (или наоборот),
- сдвиг цвета (на `var(--accent)` или `var(--accent-outline)`),
- более темный/жирный текст.

Только изменение текста считается недостаточным.

### 2.4 Разделение панели и контента `[✓ impl]`
Навигационная панель (topbar / left-panel / detail-panel) отделяется от карты:

- 1 px обводка (`var(--line)` / `var(--line-strong)`),
- или панель на темном фоне (`var(--panel)`),
- или мягкая тень без жёстких краёв.

Жёсткие тени, отвлекающие внимание с карты, запрещены.

### 2.5 Управление с клавиатуры `[✓ impl] / [☐ todo]`
Весь интерфейс атласа управляется с клавиатуры без мыши:

| Клавиша | Действие |
|---------|----------|
| `Tab` | Следующий интерактивный элемент (topbar → поиск → левая панель → карта → Planet Detail Card → Travel Planner) |
| `Shift+Tab` | Предыдущий элемент |
| `Enter` / `Space` | Активировать выбранный элемент |
| `Esc` | Закрыть панель, сбросить поиск, отменить маршрут в Travel Planner |
| `/` | Фокус на поиске (уже реализовано) |
| `W/A/S/D` или стрелки | Перемещение по карте `[☐ todo]` |
| `+` / `-` | Масштаб карты `[✓ impl] / [☐ todo]` |
| `Cmd/Ctrl+F` | **Не перехватывать** — оставляем нативному поиску браузера |

**Техническое условие для хоткеев:** все однобуквенные хоткеи (`/`, `W/A/S/D`, `+`, `-`) обязаны игнорироваться, если фокус находится внутри `input`, `textarea`, `select` или `[contenteditable]`, чтобы не блокировать ввод текста в поиск и поля маршрута.

**Tab по карте:** сцена Sector Map должна быть одним фокусируемым контейнером (`tabindex="0"`). Внутри сцены навигация между hotspot-маркерами идёт стрелками / W-A-S-D, а не последовательным `Tab` по каждой звезде. При наличии более 10 маркеров на экране — добавить паттерн пропуска, чтобы `Tab` перепрыгивал от левой панели к открытой карточке планеты.

`:focus-visible` всегда виден: `outline: 1px solid var(--accent-outline)`, `outline-offset: 3px` (уже задано в `styles.css` `[✓ impl]`).

### 2.6 Управление картой `[✓ impl] / [☐ todo]`
Sector Map поддерживает:

- перетаскивание мышью (реализовано) `[✓ impl]`,
- перемещение клавишами `W/A/S/D` или стрелками `[☐ todo]`,
- масштабирование колесиком и клавишами `+` / `-` `[✓ impl] / [☐ todo]`,
- центрирование на выбранной системе через Planet Detail Card `[✓ impl]`,
- подсветку текущего сектора и доступных направлений полёта `[✓ impl]`.

## 3. Принципы Apple для веб-атласа (Part VII)

Современные принципы проектирования (адаптация под проект). Не подаются как давно установленная классика — это адаптация идей из WWDC-лекций под задачи веб-атласа.

### 3.1 Три классических принципа + контракт слоёв

| Принцип | Требование |
|---------|------------|
| **Clarity** | Досье системы читаемо с первого взгляда; действия однозначны; никакого шума в Planet Detail Card. Текст понятен без пояснений. |
| **Deference** | Карта и глобус — контент. Навигация (topbar, панели, элементы управления) отступает, не перекрывает звёздные системы. Каждый пиксель статического логотипа — пиксель, не потраченный на контент. |
| **Depth** | Слои и движение показывают иерархию: планета перед сектором, Planet Detail Card поверх карты, Travel Planner поверх карточки. Пользователь всегда знает, где находится. |

**Контракт слоёв (z-index):** на экранах шириной 1024–1366 px одновременное открытие левого каталога, правой карточки планеты и поверх неё планировщика маршрутов перекроет 80% карты (нарушает Deference). Travel Planner открывается **вместо** Planet Detail Card (переключение режима правой панели) или в компактном слоте — не накладывается поверх открытой карточки.

### 3.2 Восемь современных принципов (адаптация под проект)

| Принцип | Техническое требование |
|---------|------------------------|
| **Purpose** | Каждый экран имеет одно назначение. Каждый элемент в Planet Detail Card или Travel Planner служит этому назначению. |
| **Agency** | Пользователь может отменить маршрут, сбросить фильтры, вернуться к Sector Map. Интерфейс направляет, не ставит на рельсы. |
| **Responsibility** | Источники данных досье указаны (канон vs фанон). Никаких выдуманных отзывов, статистики или «Trusted by». |
| **Familiarity** | Адаптация: паттерны соответствуют вебу — Enter для подтверждения, Esc для отмены, `/` для поиска, стандартные элементы управления картой. (Оригинальный Apple-принцип шире — консистентность вида и поведения элемента по всему дизайну.) |
| **Flexibility** | Работает при разных размерах окон, с мышью и клавиатурой, при `prefers-reduced-motion`. |
| **Simplicity** | Каждый элемент оправдан. В Travel Planner — только поля маршрута и кнопка подтверждения. |
| **Craft** | Отступы, выравнивание, формулировки, анимация доведены до конца. Списки отсортированы, текстовые блоки выровнены по левому краю, `max-width: 65ch` для длинных абзацев. |
| **Delight** | Удовольствие ≠ декор. Чувство присутствия во вселенной StarCraft II через палитру и типографику (конкретные решения — в `DESIGN.md`, не в протоколе). |

### 3.3 Измеримые правила (опора на CSS-переменные репозитория)

Все цвета и токены берутся из `site/shared/styles.css` и `site/shared/timeline-skin.css`. Жёсткие hex-коды inline запрещены.

| Правило | Спецификация | Переменная |
|---------|--------------|------------|
| Цель нажатия | минимум 44×44 CSS px (AAA); не ниже 24×24 CSS px (AA); десктопный компромисс 32×32 px | — (размер элемента) |
| Текст, основной | `#e7edf5` | `var(--text)` |
| Текст, приглушённый | `#8996a8` | `var(--muted)` |
| Текст, неактивный / крупный | `#667386` — контраст 4.07:1 на `var(--panel)`, допустим только для меток ≥18px или неактивных состояний | `var(--muted-2)` |
| Акцент (подписи, иконки) | `#b5d3fa` | `var(--accent)` |
| Акцент обводки | `#b5d3fa` | `var(--accent-outline)` |
| Фон панели | `rgba(6, 12, 21, .94)` | `var(--panel)` |
| Фон панели 2 | `rgba(10, 18, 29, .96)` | `var(--panel-2)` |
| Линия границы | `rgba(172, 194, 221, .16)` | `var(--line)` |
| Линия Strong | `rgba(172, 194, 221, .28)` | `var(--line-strong)` |
| Фон topbar | `rgba(5, 10, 17, .92)` | `var(--topbar-bg)` |
| Линия topbar | `rgba(172, 194, 221, .28)` | `var(--topbar-line)` |
| Моноширина | — | `var(--mono)` |
| Sans-serif | — | `var(--sans)` |
| Акцент Travel Planner | `#2ef5e6` | `var(--timeline-cyan)` |
| Focus ring | `outline: 1px solid var(--accent-outline); outline-offset: 3px` | `var(--accent-outline)` |
| Контраст тела текста | минимум 4.5:1 (Apple HIG / WCAG AA) | — проверять `var(--muted)` на `var(--panel)` |
| Контраст крупного текста / неактивных меток | минимум 3:1 | — проверять `var(--muted-2)` на `var(--panel)` |
| Анимация панели | `<1 s`, ease-out, прерываемая, учитывает `prefers-reduced-motion` | — |
| Анимация при `prefers-reduced-motion` | отключить переходы и анимацию полёта | — |

**Анти-шлок (структурные запреты, Part VIII):**

- **Запрет карточек внутри карточек:** в Planet Detail Card секции разделяются линией `1px solid var(--line)` и отступами, а не вложенными боксами с фоном.
- **Запрет эмодзи вместо иконок:** только SVG-иконки, никаких 🚀 ✨ ⚡ в заголовках, списках и кнопках.
- **Запрет `backdrop-filter: blur()` над тяжёлым WebGL-канвасом:** просаживает FPS на 3D-глобусе (`/planet-globe/`).

## 4. URL-схема и deep linking `[☐ todo]`

Атлас без закладок на конкретную планету — неполноценный атлас. Требуется:

- URL-схема вида `/sector/?system=mar-sara` для прямой ссылки на систему,
- При открытии такого URL — автофокус системы на карте и открытие Planet Detail Card,
- Состояние Travel Planner сохраняется в query-параметрах (маршрут, точка А, точка Б).

---

## 5. Адаптивность и отзывчивость `[✓ impl] / [☐ todo]`

Desktop-first не означает «только 1920px». Требуется:

- При ширине 1024px и менее — панели схлопываются (уже частично реализовано в `@media (max-width: 980px)` и `(max-width: 700px)` в `styles.css`) `[✓ impl] / [☐ todo]`,
- При ширине 768px и менее — левая панель и Planet Detail Card переходят в нижнее положение или выезжающие панели `[☐ todo]`,
- Карта остаётся доступной для навигации при любом размере окна.

- [ ] Sector Map: не более 3–5 целей навигации; каждая цель ≥ 32×32 CSS px (допустимо), предпочтительно 44×44 CSS px; активное состояние ≥ 2 визуальных изменения.

- [ ] Весь интерфейс доступен с клавиатуры (Tab, Enter, Space, Esc, `/`, W/A/S/D, `+`/`-`).
- [ ] Хоткеи `/`, `W/A/S/D`, `+`, `-` игнорируются при фокусе в `input`/`textarea`/`select`/`[contenteditable]`.
- [ ] `:focus-visible` везде: `outline: 1px solid var(--accent-outline)`, `outline-offset: 3px`.
- [ ] `Cmd/Ctrl+F` не перехватывается; поиск фокусируется по `/`.
- [ ] Все цвета через CSS-переменные; нет жёстких hex inline; нет смешивания `pt` и `px`.
- [ ] Контраст тела текста ≥ 4.5:1, крупного ≥ 3:1. `var(--muted-2)` (#667386, 4.07:1) допустим только для меток ≥18px или неактивных состояний; для основного текста использовать `var(--muted)` или осветлить токен до #6d7b8f.
- [ ] Пустые состояния (нет систем, нет маршрута, WebGL context lost) имеют действие, не являются тупиками. Применяется к `/sector/` и `/planet-globe/`.
- [ ] Поиск показывает подсказки при фокусе; навигация `↑`/`↓`/`Enter` работает.

- [ ] URL-схема `/sector/?system=...` работает и открывает Planet Detail Card.
- [ ] Адаптивность: 1024px, 768px — панели схлопываются или перестраиваются.
- [ ] Нет языкового мусора: только русский, термины из §0, CSS-свойства и переменные.
- [ ] Анти-шлок: нет карточек внутри карточек, нет эмодзи вместо SVG, нет `backdrop-filter: blur()` над WebGL-канвасом.
- [ ] Контракт слоёв: Travel Planner не накладывается поверх открытой Planet Detail Card.
- [ ] Нет примеров интернет-магазинов, мобильных приложений, paywall-механик или выдуманной статистики.
- [ ] Проверено на реальном устройстве с клавиатурой и мышью.
