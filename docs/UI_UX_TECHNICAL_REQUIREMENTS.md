# Технические требования к UI/UX — StarCraft II Web Atlas

**Источник:** Part III (Interaction Design), Part IV (Navigation), Part VII (Apple UI/UX Principles) — *UI/UX AI Skill — The Complete Field Manual*.  
**Адаптация:** все примеры интернет-магазинов и мобильных приложений удалены. Требования переписаны под десктопный веб-атлас вселенной StarCraft II.  
**Статус:** техническое задание для верстки и интерфейсной разработки (`site/`, `templates/`, `src/`). Не является финальным дизайном — является обязательным минимумом передmerge в `main`.

## 0. Терминология проекта

| Термин | Значение в проекте |
|--------|--------------------|
| **Sector Map** | Основная сцена карты сектора Копрулу — обзор звёздных систем, регионов, hotspot-маркеров, полёта между секторами (`/sector/`, `/minimal/`). |
| **Planet Detail Card** | Карточка досье планеты/системы — выезжающая правая панель с названием, типом мира, фракцией, координатами, описанием, кнопкой центрирования на карте. |
| **Travel Planner** | Режим планирования маршрута между системами — лента маршрута, поля ввода точки отправления/назначения, расчёт времени перелёта, подтверждение полёта. |

## 1. Взаимодействие: удаление трений (Part III)

Требования этого раздела касаются всего интерфейса атласа: Sector Map, Planet Detail Card, Travel Planner.

### 1.1 Одна точечная цель на экран
На каждом экране должна быть **одна** основная цель (CTA), которая визуально доминирует. Второстепенные действия отступают.

- **Sector Map:** основное действие — выбор системы или запуск Travel Planner. Все остальные кнопки (фильтры, слои, ayuda) вторичны.
- **Planet Detail Card:** основное действие — «Центрировать на карте» или «Добавить в маршрут». Остальное — справочная информация.
- **Travel Planner:** основное действие — подтверждение маршрута («Построить» / «Полёт»). Поля ввода — вспомогательные.

### 1.2 Поиск — момент намерения
Поиск по Sector Map не должен быть пустым полем.

- При фокусе на поисковой строке показываются: недавние системы, популярные регионы, персонализированные подсказки.
- Подсказки поддерживают навигацию клавиатурой (↑/↓ для перехода, Enter для выбора, Esc для закрытия).
- Пустой результат поиска — не мёртвый конец: дружелюбное сообщение + действие («Очистить фильтр», «Открыть каталог систем»).

### 1.3 Распознавание вместо воспоминания
Системы и планеты на карте и в списках показываются через иконку/цвет/галиф, а не через абстрактные ID или координаты, которые пользователь должен запомнить.

- Каждый hotspot на Sector Map имеет визуальный маркер (row-glyph / секторная иконка).
- В Planet Detail Card тип мира и фракция отображаются цветным чипом, а не только текстом.

### 1.4 Пустые состояния — возможности, не тупики
Если в Sector Map не найдено систем по фильтру, или в Travel Planner нет маршрута, экран не пустой:

- дружелюбный заголовок,
- краткое пояснение,
- конкретная acción («Сбросить фильтры», «Задать начальную точку», «Открыть каталог»).

### 1.5 Пользователь не начинает с нуля
При открытии Travel Planner или Planet Detail Card поля заполняются дефолтами, где это уместно (последняя просмотренная система, текущий сектор, последний маршрут). Пустая форма = запрещено.

### 1.6 Обратная связь мгновенная
Каждое действие с картой или панелью даёт визуальный отклик в течение 100–300 мс:

- выделение hotspot при наведении,
- изменение состояния кнопки при нажатии,
- уведомление (toast) после успешного построения маршрута или ошибки расчёта.

## 2. Навигация Sector Map (Part IV)

Навигация атласа десктопная, поэтому правила нижней панели переносятся на верхнюю панель, левую панель каталога и правую Planet Detail Card с учётом мыши и клавиатуры.

### 2.1 Состав навигации
В навигацию входят только **3–5 principais целей**:

1. Sector Map (обзорная карта / возврат к карте),
2. Каталог систем (левая панель),
3. Planet Detail Card (досье выбранного объекта),
4. Travel Planner (планирование маршрута),
5. Настройки / справка (вторично, через иконку).

Не входят в навигацию: разделы помощи как отдельные пункты, выход, юридические страницы, логотип как навигационный элемент.

### 2.2 Размеры целей и зона нажатия
Минимальный размер интерактивной цели — **44×44 px** (Apple HIG, адаптировано к вебу). Кнопки управления картой (зум, слои) и элементы Planet Detail Card не могут быть меньше.

- В Travel Planner поля ввода и кнопки подтверждения — не менее 35–44 px по высоте.
- Горячие клавиши дублируют мышь (см. раздел 4).

### 2.3 Активное состояние
Активная вкладка/элемент навигации должна иметь **не менее двух одновременных визуальных изменений**:

- заливка → контур (или наоборот),
- сдвиг цвета (на `--accent` или `--accent-outline`),
- более темный/жирный текст.

Только изменение текста считается недостаточным.

### 2.4 Разделение панели и контента
Навигационная панель (topbar / left-panel / detail-panel) отделяется от карты:

- 1 px обводка (`var(--line)` / `var(--line-strong)`),
- или светлая панель на темном фоне (`var(--panel)`),
- или мягкая тень (`box-shadow` без жёстких краёв).

Харшные тени, крадущие внимание с карты, запрещены.

### 2.5 Клавиатурная навигация
Весь интерфейс атласа управляется с клавиатуры без мыши:

- `Tab` перемещает фокус по интерактивным элементам в логическом порядке (topbar → поиск → left-panel → карта → detail-panel → Travel Planner).
- `Enter` / `Space` активируют выбранный элемент.
- `Esc` закрывает открытую панель, сбрасывает поиск, отменяет маршрут в Travel Planner.
- Стрелки навигации между секторами на Sector Map доступны через клавиатуру (вЫбор направления → Enter для перехода).
- `:focus-visible` всегда виден: `outline: 1px solid var(--accent-outline)` с `outline-offset: 3px` (уже задано в `styles.css`).

### 2.6 Управление картой
Sector Map поддерживает:

- перетаскивание (drag) мышью и перемещение клавишами `W/A/S/D` или стрелками,
- масштабирование колесиком мыши и клавишами `+` / `-`,
- центрирование на выбранной системе через Planet Detail Card,
- подсветку текущего сектора и доступных направлений полёта.

## 3. Принципы Apple для веб-атласа (Part VII)

Применяются к каждому экрану: Sector Map, Planet Detail Card, Travel Planner.

### 3.1 Три классических принципа

| Принцип | Требование для Sector Map / Planet Detail Card / Travel Planner |
|---------|-----------------------------------------------------------------|
| **Clarity** | Досье системы читаемо с первого взгляста; действия unambiguous; никакого шума в Planet Detail Card. Текст понятен без пояснений. |
| **Deference** | Карта и глобус — контент. Навигация (topbar, панели, элементы управления) отступает, не перекрывает звёздные системы, не доминирует экрана. Каждый пиксель статического логотипа — пиксель, не потраченный на контент. |
| **Depth** | Слои и движение показывают иерархию: planeta перед сектором, detail-panel поверх карты, Travel Planner поверх detail-panel. Пользователь всегда знает, где находится и что интерактивно. |

### 3.2 Восемь современных принципов

| Принцип | Техническое требование |
|---------|------------------------|
| **Purpose** | Каждый экран имеет одно четкое назначение. Каждый элемент в Planet Detail Card или Travel Planner служит этому назначению. |
| **Agency** | Пользователь может пропустить наboarding, отменить маршрут, сбросить фильтры, вернуться к Sector Map. Интерфейс направляет, но не ставит на рельсы. |
| **Responsibility** | Источники данных досье указаны (канон vs фанон). Разрешения и запросы контекстны, минимальны, с объяснением. Никаких выдуманных отзывов или статистики. |
| **Familiarity** | Паттерны соответствуют вебу: Enter для подтверждения, Esc для отмены, `Cmd/Ctrl+F` для поиска, стандартные элементы управления картой. |
| **Flexibility** | Работает на разных размерах окон, с мышью и клавиатурой, при уменьшенном движении (`prefers-reduced-motion`). |
| **Simplicity** | Каждый элемент оправдан. В Travel Planner — только поля маршрута и кнопка подтверждения. В Planet Detail Card — только досье и действие центрирования. |
| **Craft** | Отступы, выравнивание, формулировки, анимация — доведены до конца. Несортированные списки, невыровненные текстовые блоки, недоделанные состояния кнопок запрещены. |
| **Delight** | Чувство присутствия во вселенной StarCraft II (брифинговый стиль, цвет фракций), но не в ущерб удобству. Делライт ≠ декор. |

### 3.3 Измеримые правила (используются существующие CSS-переменные)

Все значения ниже опираются на `site/shared/styles.css` и смежные файлы репозитория.

| Правило | Спецификация | CSS-переменная |
|---------|--------------|----------------|
| Цель нажатия | минимум 44×44 pt/px | — (размер элемента, не переменная) |
| Текст, основной | `--text: #e7edf5` | `var(--text)` |
| Текст, приглушённый | `--muted: #8996a8`, `--muted-2: #667386` | `var(--muted)` |
| Акцент (подписи, иконки) | `--accent: #b5d3fa` | `var(--accent)` |
| Акцент обводки | `--accent-outline: #b5d3fa` | `var(--accent-outline)` |
| Фон панели | `--panel: rgba(6, 12, 21, .94)` | `var(--panel)` |
| Линия границы | `--line: rgba(172, 194, 221, .16)` | `var(--line)` |
| Линия границы Strong | `--line-strong: rgba(172, 194, 221, .28)` | `var(--line-strong)` |
| Фон topbar | `--topbar-bg: rgba(5, 10, 17, .92)` | `var(--topbar-bg)` |
| Линия topbar | `--topbar-line: rgba(172, 194, 221, .28)` | `var(--topbar-line)` |
| Моноширинный шрифт | `--mono` | `var(--mono)` |
| Без засечек | `--sans` | `var(--sans)` |
| Focus ring | `outline: 1px solid var(--accent-outline); outline-offset: 3px` | `var(--accent-outline)` |
| Анимация панели | `<1 s`, easе-out, прерываемая | — |
| Акцент Travel Planner | `--timeline-cyan: #2ef5e6` (из `timeline-skin.css`) | `var(--timeline-cyan)` |

Цвета не задаются жёсткими hex-кодами inline — только через переменные выше. Палитра не инвертируется простым переключением светлого/тёмного режима (dark mode у проекта один, но новые темы должны следовать той же семантике).

## 4. Управление с клавиатуры — сводка

| Клавиша | Действие в Sector Map | Действие в Planet Detail Card | Действие в Travel Planner |
|---------|----------------------|------------------------------|---------------------------|
| `Tab` | Следующий интерактивный элемент | Следующий элемент карточки | Следующее поле / кнопка |
| `Shift+Tab` | Предыдущий элемент | Предыдущий элемент | Предыдущее поле |
| `Enter` | Выбрать систему под фокусом | Активировать кнопку (центрирование / маршрут) | Подтвердить маршрут |
| `Esc` | Снять выделение, закрыть поиск | Закрыть карточку | Отменить маршрут |
| `W/A/S/D` или стрелки | Перемещение по карте | — | — |
| `+` / `-` | Масштаб карты | — | — |
| `Cmd/Ctrl+F` | Фокус на поиске | Фокус на поиске | Фокус на поиске |

Все интерактивные элементы имеют `:focus-visible` с `var(--accent-outline)`.

## 5. Чеклист перед merge в `main`

- [ ] Sector Map: не более 3–5 целей навигации; каждая цель ≥ 44×44 px; активное состояние ≥ 2 визуальных изменения.
- [ ] Planet Detail Card: одна основная CTA; досье читаемо без пояснений; кнопка центрирования на карте.
- [ ] Travel Planner: поля ввода заполнены дефолтами, где уместно; подтверждение маршрута — единственное доминирующее действие.
- [ ] Весь интерфейс доступен с клавиатуры (Tab, Enter, Space, Esc, W/A/S/D).
- [ ] `:focus-visible` везде: `outline: 1px solid var(--accent-outline)`, `outline-offset: 3px`.
- [ ] Все цвета через CSS-переменные из `styles.css` / `timeline-skin.css`; нет жёстких hex inline.
- [ ] Пустые состояния (нет систем, нет маршрута) имеют действие, не являются тупиками.
- [ ] Поиск показывает подсказки при фокусе; навигация ↑/↓/Enter работает.
- [ ] Анимации панели < 1 с, respeктят `prefers-reduced-motion`.
- [ ] Нет примеров интернет-магазинов, мобильных приложений, paywall-механик или выдуманной статистики.
- [ ] Проверено на реальном устройстве с клавиатурой и мышью.
