# Документация TIMELINE PROJECT — карта и правила

Этот файл — единственная точка входа в документацию. Здесь описано, **как
устроены документы**, где лежит нужный контекст и куда писать новое знание.

## 1. Четыре регистра и паспорт

Каждый этап описан пятью файлами в `docs/stages/stage-NN/`:

| Файл | Тип | Что внутри | Лимит |
|---|---|---|---|
| [`plan.md`](stages/README.md) | **ПЛАН** | паспорт этапа: цель, границы, вход/выход, артефакты, гейты, статус | 200 строк |
| `errors.md` | **ОШИБКИ** | ошибки проектирования и реализации: симптом → причина → урок → исправление | 200 строк |
| `bugs.md` | **БАГИ** | дефекты среды, выполнения, данных и нестыковки контрактов | 200 строк |
| `decisions.md` | **РЕШЕНИЯ** | ADR-записи: ID, дата, решение, причина, альтернативы, источник | 200 строк |
| `todo.md` | **TODO** | что работает, что в работе, что предстоит, что заблокировано | 200 строк |
| `notes/*.md` | **ПРИЛОЖЕНИЕ** | детальные отчёты, замеры и исторические журналы по контексту | 200 строк |

`plan.md` — паспорт (точка входа). Остальные четыре файла — регистры данных.
Паспорт ссылается на приложения, приложения — обратно на паспорт.

### Различие «ошибка» и «баг»

- **Ошибка** — неверное решение или реализация внутри этапа: регрессия,
  неверное допущение, пропущенный инвариант. Исправляется изменением кода или
  плана, урок остаётся в `errors.md`.
- **Баг** — сбой внешней среды или стыка: CI, GitHub Pages, песочница,
  Google Sheets, браузер, версии инструментов, рассинхронизация данных.
  Часто не зависит от кода этапа и повторяется в разных волнах.
- Повторяющиеся ошибки → [`registers/errors-systemic.md`](registers/errors-systemic.md)
  (без лимита размера). Повторяющиеся баги → `registers/bugs-*.md` по темам,
  каждый файл ≤ 200 строк.

## 3. Правила ведения

1. **Один файл — один контекст.** Не более 200 строк; если контекст больше,
   добавляйте под-файл в `notes/` с именем по смыслу, а не по дате.
2. **Заголовок и навигация.** У каждого файла есть H1 и строка «Назад» на
   паспорт этапа или индекс. Новые файлы ссылаются на источники.
3. **Без дублей.** Одно число, правило или решение живёт в одном месте
   (SSoT). Остальные документы ссылаются, а не копируют.
4. **Регистры обновляются в том же PR,** что и работа. Закрытый пункт TODO
   переносится в «Работает» с датой и ссылкой на PR.
5. **Проверка перед PR.** `npm run verify:docs` (он же шаг CI) проверяет лимит
   200 строк и отсутствие битых относительных ссылок.
6. **Ошибки не прячутся.** Откат, регрессия и неверная гипотеза фиксируются
   в `errors.md` с уроком; если ошибка повторилась — в систематический регистр.
6. **Ссылки обязательны.** PR, коммит, файл кода, замер и решение — со
   ссылкой. Если ссылки нет, пункт считается недоказанным.
7. **Язык — русский.** Тексты, заголовки и комментарии.

## 4. Жизненный цикл записи

```text
идея/требование → plan.md (границы и гейт)
   → decisions.md (выбранный вариант)
   → выполнение → bugs.md / errors.md (что сломалось)
   → todo.md (что работает, что осталось)
   → notes/ (замеры и подробности)
```

Если этап завершён, `plan.md` получает статус «завершён», а незакрытые
пункты переезжают в `todo.md` следующего этапа или в общий
[`registers/todo.md`](registers/todo.md).

## 5. Проверка

```bash
python3 tools/check_docs.py      # лимит строк, H1, битые ссылки
npm run verify:docs              # то же через npm
```

CI выполняет проверку в каждом PR. Исключение по размеру только одно —
[`registers/errors-systemic.md`](registers/errors-systemic.md).
