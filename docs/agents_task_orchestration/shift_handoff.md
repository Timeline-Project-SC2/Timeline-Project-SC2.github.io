не повторять. Он **переписывается** при каждой передаче, а не дописывается историей: история живёт
в [`CHANGELOG.md`](../../CHANGELOG.md), [`docs/HANDOFF.md`](../HANDOFF.md) и регистрах.

## 4. Первые десять минут смены (шаг 0)

1. `git rev-parse --abbrev-ref HEAD` — ветка сессии, не `main`; `git status --short` — чисто.
2. `git fetch -q origin main && git log --oneline -1 origin/main` — база. Ожидается `0f58970` или новее.
3. Гейты кода и база падений снимаются с последнего CI на `main` (`gh run list --branch main`,
   `gh pr checks` последнего слитого PR) и/или отдельной задачей воркеру/`rc-04`: локально
   Гайдлайнер код не запускает (правило О-5). Узкое разрешённое исключение — доковый гейт
   `npm run verify:docs` для собственных документов.
4. База падений (сейчас **`8` известных**: Stage-8.5, Stage-8.10b ×2, A-17 ×2, W26b ×2, контракт
   ядра) ведётся по именам из отчёта CI/воркера. Норма для любой карточки — «ни одного нового»,
   а не «ноль».
5. Только после этого — выдача следующей карточки (`F-3`; `F-2` принят, PR #308).

## 7. Как проверять и как сливать

- По правилу О-5 Гайдлайнер не исполняет кодовые команды сам: зелёный статус подтверждается через
  CI и отчёт воркера/`rc-04`; собственными остаются только `git diff --check` и
  `npm run verify:docs` (доковый гейт).
- Зелёные обязательны (подтверждает CI/воркер): `git diff --check`, `npm run verify:docs`, `npm run typecheck`, `npm run lint`,
  `npm run build`, `npm run verify:publish`, `npm run verify:address`, `npm run verify:sector-core`,
  `npm run verify:no-raster`.
- `npm test` — сравнение с базой из §4 по **именам** падений, а не по счётчику.
- Job «Скрипты сайта» красный на всех PR из-за тех же восьми падений: шаги после `npm test`
  в `check.yml` не выполняются (решение №14 `F-1`, правка `check.yml` — отдельная микрозадача).
  Поэтому `lint` и `check:planet-core` гонять локально.
- Слияние: `gh pr merge <N> --squash --admin` (или REST-мерж с `merge_method`). `BLOCKED`
  в `gh pr view` — ожидаемое состояние ruleset, а не запрет: подробности —
  [`handoff/infra-pitfalls.md`](../handoff/infra-pitfalls.md).
- `verify:docs` (`tools/check_docs.py`) держит: `≤ 200` строк на файл, один `H1` в первых 12 строках,
  без прыжков уровней заголовков, живые ссылки и якоря, ни одного файла-сироты без входящей ссылки.

## 8. Грабли, на которых уже теряли время

- **Shallow-клон.** `git rev-parse --is-shallow-repository` → `true`; `git fetch --deepen=5 origin main`,
  при `fatal: refusing to merge unrelated histories` — `git reset --hard origin/main`, если своих
  коммитов нет (они уже в `main` через squash).
- **`/tmp` и песочница эфемерны.** Одноразовые скрипты правок живут только на один шаг; всё, что
  нужно позже, — в репозиторий.
- **Логи Actions.** `gh run view --log-failed` часто падает с `EOF`, `gh run rerun` отвечает
  «cannot be rerun». Рабочая замена — `gh pr checks <N>` плюс локальный прогон той же команды.
- **Параллельные вызовы.** В одном блоке нельзя писать файл и читать его: `bash` выполнится
  параллельно и увидит пустоту.
- **Документация разукрупнена.** `stage-9-12-sector-deep-render-plan.md` — короткий хаб; числа ищутся
  в паспорте этапа и `notes/*`, а не по старому файлу.
- **Ручные `?v=`** в HTML/TS запрещены: контент-хэши ставит сборочный конвейер.
