# Внешний аудит CI-гейта 26.10.2026: «привычно красный CI» в `check.yml`

**Дата:** 26.10.2026. **Статус:** закрыто по форме — карточка [`CI-1`](wave_cards/CI-1.md)
принята 26.10.2026 (PR #316, squash `e798eff`): 4/4 джобы CI зелёные, претензии 1–3 устранены,
претензия 4 учтена как постоянное правило. Тем же днём решением владельца режим решения E2
изменён: восемь падений переводятся в runner-level карантин ([`CI-2`](wave_cards/CI-2.md),
пункт этапа [`S8-Q1`](../stages/stage-08/todo.md)); бинарный гейт E1 и страж целостности
сохраняются.
**Источник:** оценка стороннего ИИ-агента по запросу владельца, передана текстом в чат;
внешнего репозитория и коммита у источника нет (в отличие от
[аудита `agency-agents`](external_agency_agents_audit.md)), поэтому фиксируем только формулировки
и выводы, атрибуция кода невозможна и не требуется.

## 1. Метод проверки (граница О-5)

Проверка велась только с разрешённой Гайдлайнеру поверхности: статусы и шаги прогонов через
Actions API (`gh api .../actions/runs/<id>/jobs`), метаданные Git, структура workflow и конфигов
как артефакты CI. Глубокая проверка поведения (TAP-имена падений, находки ESLint на `tools/`/
`tests/`, готовность planet-core к прогону в CI) делегирована воркеру — шаг 0 `CI-1`,
спецификация поиска без правок. Локальных прогонов кода Гайдлайнер не делал (О-5).

## 2. Претензии и вердикты

| № | Претензия внешнего агента | Вердикт | Доказательство |
|---|---|---|---|
| 1 | `check:planet-core` и `npm run lint` в CI не исполняются: красный `npm test` обрывает `run:`-блок (`bash -e`) | **Подтверждена** | В джобе `scripts` всё лежит в одном шаге «Синтаксис и необъявленные переменные». API прогонов (#313, run `40345874841`): шаг `failure`, после него только `Post`-шаги, отдельных шагов линта и planet-core в джобе нет вообще. Комментарий в самом workflow признаёт частичную меру (верификаторы подняты выше `npm test`), но два нижних шага остались за обрывом |
| 2 | «Разбитое окно»: плашка красной джобы одинакова при 8 известных и при 9-м, новом падении; слияния идут `--admin` | **Подтверждена** | Все PR `F-1…F-3` имеют идентичную картину 3/4 с красной джобой на одном шаге; различить «базовые 8» и новое падение по CI невозможно. Норма «девятое падение блокирует» существует только в документации и дисциплине приёмки, механически CI её не enforcing |
| 3 | `tools/*.mjs` и `tests/*.mjs` не охвачены `tsc`/`eslint`; опечатка в верификаторе ловится только при исполнении ветки | **Подтверждена с уточнением** | `lint` = `eslint site src`; `node --check` в workflow — только `site/**/*.js` плюс один `.js`-тест. Уточнение: тесты исполняются в `npm test`, а верификаторы — явными командами, то есть нулевого покрытия нет, но статической проверки `no-undef` (которая исторически поймала поломку перетаскивания карты) на 21 `tools/*.mjs` и 36 тест-файлах действительно нет |
| 4 | Бенчмарки на облачных раннерах нельзя запирать миллисекундными порогами впритык | **Принято как правило, изменений не требует** | `planet-perf` уже устроен консервативно: frame time намеренно не меряется (комментарий в workflow), пороги — через baseline-файл и reps/seeds. Действие: пороги не ужесточать, зафиксировано в не-целях `CI-1` |

Внешний агент неточен в деталях: его сниппет опускает `typecheck`, `node --check` и уже
сделанный частичный перенос верификаторов выше `npm test`. Суть претензии от этого не меняется.

## 3. Решения

| № | Решение |
|---|---|
| E1 | CI становится **бинарным**: монолитный `run:`-блок джобы `scripts` режется на именованные шаги; каждая проверка видна в API отдельным `success/failure` |
| E2 | Известные 8 планетарных падений **не скипаются и не маркируются `todo`**: полный набор тестов исполняется всегда, но вводится страж базы (`tools/check_test_baseline.mjs` + `tools/known-test-failures.json`), который краснеет только на новом падении или на устаревании базы. Норма «девятое блокирует» становится механикой CI, а не устной нормой. **Изменено решением владельца 26.10.2026 (`CI-2`):** тесты остаются нетронутыми, но пропускаются на уровне раннера по реестру; полный прогон живёт в `test:raw`, страж целостности усилен |
| E3 | ESLint расширяется на `tools/**` и `tests/**` тем же единственным правилом `no-undef`; новые стилевые правила не вводятся, ослабление правил запрещено |
| E4 | `node --check` расширяется на все `tools/**/*.mjs` и `tests/**/*.{mjs,js}` |
| E5 | `check:planet-core` и `lint` становятся отдельными обязательными шагами и доказательно зелёные в CI PR карточки |
| E6 | Бенчпороги не трогаем; 8 планетарных падений не чиним в этой карточке (граница `И-11`, отдельный долг владельца) |

## 4. Отклонённые альтернативы

| Вариант | Почему отклонён |
|---|---|
| Пометить 8 тестов `skip`/`todo` с номером задачи | Теряется сигнал регрессий внутри самих этих тестов; правки в планетарном контуре нарушают `И-11`; переименования ломают скип-паттерны. Страж базы сохраняет полное исполнение. **Уточнение `CI-2`:** владелец выбрал не source-level пометку, а runner-level `--test-skip` от реестра — исходники тестов не редактируются, а риск переименований закрывает страж целостности («КАРАНТИН НЕ ПРИМЕНЁН») |
| `continue-on-error` на шаге `npm test` без стража | То самое разбитое окно: девятое падение по-прежнему неотличимо снаружи |
| Отдельный workflow для «красных» тестов | Два списка тестов неминуемо расходятся; единственный источник — один прогон + база |
| Чинить планетарные тесты заодно | Расширение scope, чужой контур (`rc-02`), карточка про гигиену гейта, а не про контент падений |
