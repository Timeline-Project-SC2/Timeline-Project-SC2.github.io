# Единица длины 1000 единиц = 1 св.г. (отменено §17.24)

> Источник: `agents_task_orchestration.md`, строки 1879–1980 (редакция до разукрупнения).
> Назад: [оркестрация](../agents_task_orchestration.md) · [этапы](../../stages/README.md) · [документация](../../README.md).

### 17.23. Единица длины: `1000` единиц карты = `1` световой год (25.10.2026)

Владелец: «наша математика должна была быть около таких значений — центры систем эталон
пикселя, `1 000` пикселей = расстояние между двумя системами; в экран должно умещаться на
границах две системы на границе видимости; можно составить погрешность глубины
приближения слегка выше изначального, чтобы было немного пространства по краям; и соотв.
`1 000` пикселей = `1` световой год».

#### 17.23.1. Проверка по данным — вариант владельца единственный сходящийся

Медиана расстояний по всем парам `173` систем: **`990,4`** единицы. То есть «`1 000`
пикселей между двумя системами» — это буквально наш шаг сетки систем.

Проверил три возможных прочтения по критерию владельца «в кадре на упоре две системы»:

| Прочтение | Поле | Шаг систем | Кадр на упоре (`1 св.г.` до границы) | Шагов в кадре | Вердикт |
|---|---:|---:|---:|---:|---|
| `1` ед = `1` св.г. (то, что в коде сейчас) | `10 000` св.г. | `990` св.г. | `2` св.г. | **`0,002`** | ✗ не то |
| клетка `322,58` ед = `150` св.г. (легенда эталона) | `4 650` св.г. | `461` св.г. | `4` св.г. | **`0,009`** | ✗ не то |
| **`1 000` ед = `1` св.г. (владелец)** | **`10` св.г.** | **`0,99` св.г.** | **`2` св.г.** | **`2,02`** | ✓ **сходится** |

Дополнительное подтверждение: при этой модели процент зума на упоре становится **`532 %`**
вместо сегодняшних `531 915 %`. Прежнее число было абсурдным ровно потому, что единицу
карты считали световым годом.

Итоговые числа, которые получаются сразу и совпадают с ожиданием владельца:

| Величина | Значение |
|---|---:|
| Поле сектора | **`10` св.г.** (`10 000` единиц) |
| Медиана шага систем | `0,990` св.г. |
| Медиана ближайшего соседа | `0,101` св.г. |
| `fitScale` (вся карта, `1920 × 1080`) | `0,10152` px/ед (`101,52` px/св.г.) |
| Предел на упоре `1,00 св.г.` | `0,54` px/ед = **`540` px/св.г.** |
| Кадр на упоре | `3 556 × 2 000` ед = `3,56 × 2,00` св.г. |
| Систем в кадре на упоре | `3,59` по ширине, **`2,02` по высоте** |
| Клетка сетки эталона `31 × 31` | `0,3226` св.г. |

«Погрешность слегка выше изначального» из сообщения владельца реализована уже сейчас:
на упоре по высоте ровно `2,00` св.г. (две системы), по ширине `3,56` св.г. — то самое
пространство по краям.

#### 17.23.2. Что это меняет в коде (одна константа и её производные)

Единственное новое понятие — `UNITS_PER_LY = 1000`. Единица хранения координат остаётся
`0…10 000`, меняются только **именованные в световых годах** величины:

| Место | Сейчас | Станет |
|---|---|---|
| `level-ladder.ts`: `TARGET_EDGE_LY = 1` | трактуется как `1` единица | `1` св.г. = **`1 000` единиц** |
| `maxScaleForTargetEdge(viewport, …)` | `short / 2 / 1` = `540` | `short / 2 / 1 000` = **`0,54`** |
| `edgeDistance(viewport, scale)` | `short / 2 / scale` (в «св.г.») | `short / 2 / scale / 1 000` |
| `MIN_CLAMP_EDGE_LY = 0,5` | `0,5` единицы | **`500` единиц** |
| `visibleWidthForLevel(n)` | в единицах (не меняется) | плюс `visibleWidthLyForLevel(n) = / 1 000` |
| `sector-units.ts` | `formatDistanceLy(ly)` | плюс `unitsToLy(units)`, `UNITS_PER_LY` |
| `coords-readout.ts`, `dossier-card.ts`, `sector-arrows.ts` | передают единицы как св.г. | передают `unitsToLy(единицы)` |

Отображение при этом **не ломается**: `edgeDistance` делится на `1 000` и `scale` тоже
делится на `1 000`, поэтому строка `1,00 св.г. до границы` остаётся ровно `1,00`.

#### 17.23.3. Точность подписи: правило `§6.5.1` больше не работает

По `§6.5.1` до `100 св.г.` печатается один знак после запятой. При новой единице типичные
расстояния — `0,088…4,17` св.г., и правило даёт `0,1 св.г.` вместо `0,088`, то есть
теряет различимость соседей Корхала (`Райдин 0,088` / `Мистафф 0,091`).

Предлагаю заменить пороги на лестницу точности (и это же войдёт в режим `'label'`):

| Диапазон | Формат | Пример |
|---|---|---|
| `< 1` св.г. | `3` знака | `0,088 св.г.` |
| `1 … 9,99` | `2` знака | `1,52 св.г.` |
| `10 … 99,9` | `1` знак | `90,8 св.г.` |
| `100 … 9 999` | целое с разрядным пробелом | `1 303 св.г.` |
| `≥ 10 000` | `≥ 10 000 св.г.` | — |

Проверочные значения на реальных данных: Корхал → Райдин `0,0884` → `0,088 св.г.`;
Корхал → Мория `0,304` → `0,304 св.г.`; Корхал → Айур `1,524` → `1,52 св.г.`;
Корхал → Слейн `3,911` → `3,91 св.г.`; Корхал → Тарсонис `0,275` → `0,275 св.г.`.

#### 17.23.4. Долг документации

План `docs/stages/stage-9-12-sector-deep-render-plan.md` в `§3.1`, `§3.2` и `§5.1`
подписывает единицы карты как световые годы: «поле сектора `10 000 св.г.`», «Корхал ↔
Умоджа `403,7 св.г.`». Это те же числа, но световых лет в них `0,404`. План —
источник чисел для всех карточек, поэтому его надо править **до** следующей волны
карточек, иначе воркеры снова получат неверные единицы. Ставится в `D`-волну
документации отдельным пунктом.
