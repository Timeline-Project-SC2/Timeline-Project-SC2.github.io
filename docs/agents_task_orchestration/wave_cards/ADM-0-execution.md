## 2. Схемы и связи одной строкой

- `systems`: `name,system_id,type,x,y,faction,net_id,net_confront_id,description,`
  `source_url`; все координаты внутри `0…10000`; `type=none` отображается как standard.
- `places`: `name,ID,type,system_id,x,y,faction,description,source_url`; допустим
  `system_id` **или** самостоятельные `(x,y)`, не одновременно.
- `factions`: `faction,color,short,order,source_url`; цвет `#rrggbb`, у нейтрали
  обязателен только цвет.
- `planet_generation`: 37 колонок контракта; обязательны `place_id, profile_status,
  profile_revision, preset_id, surface_class`. Защищённые/производные по валидатору:
  `generation_key`, `master_seed_hex`, grid/noise/geography/preset-версии и поля
  утверждения frozen-профиля. Их нельзя принимать как обычный свободный ввод.
- `sector-bounds`: kind `sector|halo|nebula`; координаты finite `0…10000`;
  sector/nebula замкнуты и имеют не менее четырёх точек, halo не замкнут и имеет не
  менее двух. Существующий парсер не доказывает уникальность `id`, простоту полигона и
  ориентацию — Гайдлайнер не додумывает эти инварианты задним числом.
- Связи результата проверяются целиком: `places.system_id`, обе `faction`, сетевые
  `net_id/net_confront_id`, `planet_generation.place_id`. Сейчас дыр по FK не найдено.
  Сайт местами молча деградирует, sync часть FK не проверяет — именно поэтому нужен
  отдельный offline-гейт `ADM-1`.

## 3. Канон и валидаторы

CSV: UTF-8, запятая, `QUOTE_MINIMAL`, LF; сортировки строк нет. JSON: indent 2,
`ensure_ascii=False`, финальный newline, порядок ключей сохраняется. Применитель обязан
дать нулевой diff при round-trip неизменных живых файлов: канонизация не является
поводом переписать весь датасет.

Принятые существующие доказательства для будущего pre-commit набора: PG `validate`,
Python tests, `factions`/`place-types`/`sector-bounds` Node tests, после сборки —
`verify:publish` и `verify:contract`. `tools/sync.py` в publisher запрещён: сеть,
запись и Sheets-семантика. Недостающий offline-контур систем/мест/связей — задача
`ADM-1`, а не повод ослабить гейт.

## 4. GitHub-факты приёмки

- Pages: `pages.yml` на `push: main`; `build_type=workflow`; весь `data/` копируется в
  `.publish/data`. Прямой push GitHub App этот deploy запускает, `GITHUB_TOKEN` — нет.
- Sheets-sync: cron каждые 6 часов, dispatch и `repository_dispatch`; пишет через
  `SYNC_BOT_TOKEN`. Минимальный срез переключения — запретить пишущий шаг/триггеры;
  чтение сайта от Sheets не зависит.
- Ruleset `BotsOverwrite` ограничивает ref updates; нового ADM App в bypass сейчас нет.
- Issue-шаблонов нет; единственная issue-автоматизация — failure-issue sync. Publisher
  обязан быстро отфильтровываться по служебному маркеру и не образовывать цикл.
- Замеры воркера: одна запись координат — URL 814 B; десять полных записей — 8342 B;
  одна типичная граница — 1469 B. Значит, протокол обязан быть patch-операциями, а не
  полными строками там, где обновляется одно поле.

## 5. Решения владельца и Гайдлайнера

| № | Решение |
|---|---|
| ADM-D1 | **Полный CRUD с предохранителями.** Новые числовые ID — только `max+1` от базы пакета, без дыр и повторного использования; rename ID запрещён; delete запрещён при входящих связях; нейтральная фракция не удаляется. |
| ADM-D2 | **Planet-generation входит в v1.** Но сначала [`ADM-0P`](ADM-0P.md): редактор присылает только редакционные поля, seed/key/версии вычисляет доверенный существующий генератор внутри Actions. До принятого отчёта профиль в протоколе не замораживается. |
| ADM-D3 | Владелец разрешил будущий **bypass `BotsOverwrite` для отдельного ADM GitHub App**. App и секреты заводит владелец перед `ADM-2`; `SYNC_BOT_TOKEN` и PAT человека не переиспользуем. |
| ADM-D4 | Точную ревизию даёт publish-only артефакт сборки `/_admin/revision.json`: commit SHA и хэши опубликованных копий allowlist-датасетов. В git такой файл не коммитится; suggestion воркера писать его в `data/` отклонён как самоссылочный. |
| ADM-D5 | До живого измерения клиентский лимит prefilled URL — **7000 байт на весь URL**. Оценка 8192 как «безопасная» не принята: это кромка отказа, не запас. Подъём лимита — только по no-submit пробе в `ADM-2`/`ADM-3`. |
| ADM-D6 | Редактор — изолированный `/admin`; общие файлы волны F не трогаем. Одна минимальная точка входа «Доступ администратора» определяется точной матрицей `ADM-3`, а не заранее обещанным файлом. |
| ADM-D7 | `sector-overlays`, templates/archetypes, `sources`, `meta`, upstream manifest и отсутствующие JSON-каталоги не являются входом v1. |

## 6. Оговорки вердикта

1. `ADM-0P` обязателен: без жизненного цикла профиля нельзя честно задать create/update,
   freeze/delete и производные поля.
2. Политика `data/meta.json` разведана не до полей и формул. `ADM-1` начнётся со
   стоп-проверки: каждый потребитель и поле meta; если результат CSV-правки обязан
   менять meta, применитель возвращает её только как детерминированный производный
   файл, а не как поле ввода. Если это не укладывается в матрицу — стоп Гайдлайнеру.
3. Семантики, которых нет в действующих валидаторах (уникальность `factions.order`,
   простота полигона, уникальность bounds id вне нового гейта), `ADM-1` не ужесточает
   молча: либо находит источник инварианта, либо выносит предложение в свой отчёт.
4. Черновик воркера «только update, PG вне v1» **отклонён** решениями ADM-D1/ADM-D2;
   остальные факты и матрицы приняты как вход, а не как готовая карточка.
