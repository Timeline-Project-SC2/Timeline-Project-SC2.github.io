## 2. Условный код и реальные права

**Код в браузере — не защита.** Его и содержимое статической страницы можно извлечь
или обойти. Это только барьер от случайного посетителя, а не вход в учётную запись.
Не использовать настоящий пароль, токен, секрет GitHub или другое важное значение;
не выдавать открытый код за секрет. Конкретное условное значение и способ его замены
определяются при подготовке реализации, для проверок используется тестовое значение.

Форма должна появляться и при прямом открытии административного адреса. Состояние
открытия интерфейса в браузере не подтверждает личность и не даёт права записи.
При неверном коде панель не открывается; при изменении ввода можно повторить попытку.
Обход этой формы не должен давать возможности публиковать данные. Проверить, что
уведомление о «расширенных правах» сопровождается постоянным пояснением о демо-режиме.

Для настоящей публикации нужна **независимая проверка личности и прав на стороне
GitHub**. Пока она не создана и не проверена, кнопки сохранения и отправки изменений
отключены с понятным объяснением. Страница и её исходники остаются публичными.

## 3. Структура редактора и будущие изменения

Оболочка показывает карту и место для управления модулями, свойствами, черновиком и
историей изменений. Неактивные возможности обозначаются как будущие, а не выглядят
работающими. Управление модулем использует его собственные данные и функции; общий
редактор не подменяет их копией. Связи данных, пространственное влияние и порядок
отрисовки остаются раздельными согласно [концепции](../../concepts/module-interaction-rules.md).

Направление будущего формата: версия схемы и исходного снимка, логический модуль и
набор данных, стабильный идентификатор объекта, вид операции, изменённые значения и
понятная сводка. Это **не утверждённая схема**: точные поля, поддержка геометрии,
проверки и границы модулей определяются после разведки и согласования. Не принимать
произвольные пути, конфигурацию, исполняемый код или изменения служебных файлов.

Перед применением будущий исполнитель обязан проверять права, допустимые операции,
связи, актуальность исходной версии и целостность всего результата; при конфликте или
ошибке не применять пакет частично. Предусмотреть предпросмотр, историю и понятный
отчёт об успехе или отказе. Данные разных модулей не перезаписываются молча.

Сейчас Google Sheets остаётся источником синхронизируемых таблиц. Снимки и порядок
синхронизации не меняются; планетарное направление остаётся на паузе до отдельного
указания владельца.

## 4. Найденная прежняя разведка

В закрытом без слияния **черновике** —
[PR #323](https://github.com/Timeline-Project-SC2/Timeline-Project-SC2.github.io/pull/323)
от 26–27.10.2026 — описан вариант без отдельного сервера: публичный редактор готовит
пакет, администратор подтверждает его как служебное обращение в GitHub Issues, а
GitHub Actions проверяет права и данные и публикует результат. В черновике записаны
прошлые решения владельца о полном наборе операций, профилях планет и узком исключении
для отдельного GitHub App из правила ветки. Это запись прежней работы, **не доказательство
существующего подключения** и не разрешение включать живую запись сейчас.

Тогдашняя разведка `ADM-0` принята с оговорками на базе `2fd9eb0`; профильная
разведка `ADM-0P` остановлена без принятого результата. Её прежний гейт на выдачу
протокола данных не снимается этой карточкой. Более поздняя пауза планетарных задач
сохраняется. Факты старого отчёта о путях, правах и настройках необходимо сверить с
текущим состоянием отдельным исполнителем.

Прежний вариант предлагал изолированный `/admin`; новое пожелание — страница с картой
сектора. Условный адрес из §1 нужно подтвердить. Issues в публичном репозитории также
публичны: в них нельзя помещать секреты или непубличные сведения. Ограничение размера
ссылки и применимость старого формата к большим контурам надо проверить отдельно.

## 5. Что может потребоваться от владельца позже

Сейчас менять настройки не нужно. После подготовки и проверки схемы публикации
владелец, вероятно, выполнит следующие шаги по отдельной инструкции:

1. Подтвердит, какие аккаунты GitHub могут применять изменения. В старом черновике
   проверялось активное членство администратора организации; актуальность правила надо
   подтвердить до выдачи прав.
2. Создаст и установит отдельное приложение GitHub только для нужного репозитория.
   Точный минимальный набор разрешений сначала проверяет исполнитель; в прежнем
   предложении указаны чтение участников организации и запись содержимого и обращений.
3. Внесёт служебные значения приложения непосредственно в защищённые настройки
   GitHub Actions. Секреты нельзя присылать в чат, класть в код или выдавать браузеру.
4. Отдельно рассмотрит настройки защиты ветки и способ публикации. Прежнее разрешение
   на исключение для приложения записано в черновике, но применять его без актуальной
   проверки и отдельного согласования запуска нельзя.
5. Если будет утверждён переход источника данных со Sheets на GitHub, согласует
   остановку правок в таблице, итоговый снимок, отключение записи синхронизации,
   проверку и возможность отката. До этого ничего не отключается.

## 6. Последовательность работ и границы

| Шаг | Результат | Ограничение |
|---|---|---|
| Разведка оболочки | Фактические пути, стыки и проверки; предлагаемая матрица файлов | Только чтение, никаких изменений и запуска сборки |
| Оболочка | Кнопка, условная форма, страница с общей картой и неактивной панелью | Слита в PR #335; без настоящей авторизации и правок данных, визуальная приёмка открыта |
| Протокол и защита записи | Версионированные изменения, проверка прав и целостности, пробный запуск | [ADM-ACCESS](ADM-ACCESS.md), независимая проверка; старые гейты не отменяются |
| Включение публикации | Настройка владельцем, контрольный пакет и понятный откат | Только после отдельного согласования; до этого Sheets остаётся источником |

Перед реализацией назначить одного владельца каждому изменяемому файлу, проверить
отсутствие пересечений с другими задачами и сформулировать точные контракты. Независимый
проверяющий воспроизводит проверки; визуальная приёмка — за владельцем.
