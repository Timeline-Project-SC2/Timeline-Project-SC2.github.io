## 1. Что выбрано владельцем

1. **Сканирование на модули для редактора:** найти всё существующее — оболочку, доступ, модели данных, геометрию, отрисовку, заготовки черновика — с точными `путь:строка`, отделив рабочее от заглушек.
2. **Команда на имплементацию и сразу «превращение» в примерный конечный и рабочий вид** из имеющихся модулей. Одним проходом, без отдельного этапа согласования схемы и без «плана на потом»: показанное как работающее должно работать офлайн. Не имитировать готовое сохранение и не выдавать заглушку за функцию.
3. **Связи «по смыслу»:** модули не перечисляются по алфавиту, а группируются по трём независимым плоскостям — связи данных, пространственное влияние, порядок отрисовки — плюс контуры доступа и черновика. Одна числовая шкала приоритетов не вводится; исходные данные и контуры сохраняются; связи направленные.
4. Карточка [ED-1](ADM-EDITOR-BUBBLE-CUT.md) убрала визуальный слой баблов, но **сохранила** модули границ, гало и градиента: здесь они подключаются как модели редактора, а не как боевой рендер.

## 3. Карта смысловых связей

- Три плоскости из [концепции](../../concepts/module-interaction-rules.md) не смешивать: «система содержит планету» — связь данных, а не правило рисовать планету сверху; маска границы меняет только производный показ, не исходный контур.
- Для каждой пары связанных модулей указать направление и тип: сосуществовать / накладываться визуально / обрезать только производный показ / явно получить производную геометрию / оставить на ручное разрешение. Безопасное значение по умолчанию — исходники целы, конфликт показан, а не решён молча.
- Не сливать связанные модули в один файл и не вводить общий числовой приоритет. Общий редактор — управляющая поверхность, он не владеет геометрией модулей.

## 4. Имплементация: «превращение» в примерный конечный рабочий вид

1. **Собрать один рабочий контур** на `/sector/admin-edit/` из найденных модулей: список модулей из реального реестра (не из жёстко заданного списка-заглушки), выбор модуля → его реальные свойства и данные через собственные функции модуля, предпросмотр «было → стало» на карте, отмена/повтор, история версий правил в рамках сессии, черновик изменений и понятный статус «демо, не отправлено».
2. **Конечный вид:** финальная компоновка (шапка, список модулей, свойства, предпросмотр, черновик, история, статус), русский язык, работа с клавиатуры и на телефоне, спокойное мигание с уважением к `prefers-reduced-motion`, честные состояния «не подключено» с причиной вместо кнопок, которые ничего не делают. Всё, что выглядит включённым, должно работать офлайн.
3. **Не подключать:** GitHub API, OAuth, App, секреты, workflow, сервер, базу, запись в issue, отправку черновика, Sheets/sync, правку `data/*`, планеты, публикацию и вторую модерацию. Кнопки сохранения/отправки отключены с пояснением ([ADM-UI §2](ADM-UI.md)); условный код не даёт прав.
4. **Минимальность:** адаптеры к существующим модулям, а не переписывание рендерера карты. `OWNED_FILES` фиксируется по итогам скана до первой правки; `FORBIDDEN_FILES`: `data/*`, `.github/*`, `package.json`, `tests/*`, `tools/*`, `docs/HANDOFF.md`, `CHANGELOG.md`, `docs/registers/*`, планеты/галактика, PR #348.
5. `git commit` + `git push` после каждого завершённого шага (`AGENTS.md` §6), работа только в своей активной ветке, без `reset`/force-push.

## 5. Режим проверок: только критический минимум

**Решение владельца 05.11.2026:** тесты и проверки на текущем этапе **практически убираем** — они сильно замедляют работу. Оставить только критичное для работоспособности сайта и функций редактора:

| # | Оставить | Критерий |
|---|---|---|
| 1 | `npm run build` (типы + статика) | сборка зелёная; иначе сайт и редактор не открываются — чинить **сейчас** |
| 2 | Ручной smoke редактора, 3–5 минут: `/sector/admin-edit/` открывается, панель и условный код работают, список модулей заполнен реальными модулями, выбор показывает свойства, предпросмотр/отмена/история/черновик работают офлайн, статус «не отправлено», нет ошибок в консоли и сетевых запросов на запись; `/` и `/sector/` не сломаны | любая поломка редактора или белый экран — чинить **сейчас** |
| 3 | `git diff --check`, `git status --short`, `git diff --name-only origin/main...HEAD` | затронуты только свои файлы |

**Не запускать сейчас, не добавлять тестов:** `npm test`, `npm run test:py`, `npm run lint`, `npm run build:wasm`, `npm run verify:publish`, `npm run verify:contract`, `python3 tools/sync.py --strict`, валидаторы планет и ассетов, бенчмарки и бюджет кадра, headless-браузерные сценарии, a11y/телефон/красную тему, визуальную приёмку владельцем, независимого критика, повторную сверку CI 4/4. Не править `package.json`, `check.yml`, ruleset и настройки ради скорости; CI на PR запускается сам — не ждём, некритичные падения → `TODO`. Посторонние дефекты не чинить, пометить `TODO`.
