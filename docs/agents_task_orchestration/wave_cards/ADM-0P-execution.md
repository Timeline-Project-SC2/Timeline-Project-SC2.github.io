## 1. Что принято из частичного отчёта

Факты ниже приняты как предварительные доказательства с привязками воркера; в `R1`
их нужно подтвердить в полной матрице, а не пересказывать как готовый контракт:

- Контракт содержит ровно 37 полей; статусы — `draft`, `review`, `frozen`, `disabled`
  (`src/contracts/planet-generation-contract.json:5–49`).
- `generation_key` считается от географического манифеста и для frozen сверяется с
  вычисленным значением; render- и approval-поля в географический ключ не входят
  (`tools/planet_generation.py:15–18,400–438,774–785`).
- `master_seed_hex` рождается через `secrets.token_bytes(8).hex()`
  (`tools/planet_generation.py:394–397`). Это допустимый источник только при условии,
  что seed затем хранится в данных и повторный запуск не перегенерирует существующий
  профиль; `R1` обязана доказать оба свойства на фикстурах.
- Версии по умолчанию названы отчётом как `goldberg-gp-v1`,
  `planet-noise-simplex3d-v1`, `c100-soft-v2` и `planet-presets-v1`.
- Интерфейс — CLI `seed`, `draft-row`, `key`, `freeze-row` и функции модуля; у скрипта
  есть живые пути по умолчанию от собственного `ROOT`, а freeze пишет в `args.output`
  (`tools/planet_generation.py:39–43,1112,1124–1186`). Прямой запуск из checkout без
  явных временных путей запрещён.

## 2. Что не принято

- Полная обязательность полей по статусам, переходы, unfreeze и delete-семантика не
  установлены.
- Источник личности и времени approval не доказан: наличие `prepare_freeze_row` не
  отвечает, можно ли доверенно подставить автора и `created_at` служебного issue.
- Пять сценариев P3 не запускались. Предложения P4 из частичного отчёта остаются
  гипотезами воркера, а не замороженным интерфейсом `ADM-1`.
- Не доказано отсутствие сетевых, временных и GPU-зависимостей на всём пути генератора.

## 3. Исправление выдачи `R1`

1. **Самодостаточность.** Полный текст задания передаётся одним промптом в чат; воркеру
   не нужны PR #323, ветка карточек и проверка статуса PR. Гайдлайнер отдельно
   подтверждает: PR #323 на момент перевыдачи — `OPEN`, draft, не слит.
2. **Сеть.** После получения промпта сеть запрещена полностью: ни fetch, ни GitHub API,
   ни Sheets. База фактов — уже имеющийся локальный `origin/main = 2fd9eb0`.
3. **Четыре негатива P3 названы явно:** дубль `place_id`; недопустимый тип места;
   frozen-ключ не совпал после изменения входа ключа без пересчёта; попытка задать
   производное поле как редакционное. Для четвёртого воркер обязан различить, что
   ловит нынешний валидатор, а что должен будет ловить будущий allowlist `ADM-1`.
4. **Безопасный прототип.** Перед запуском воркер перечисляет все default-входы и
   выходы; сценарии идут только на временной реплике вне репозитория с явными путями
   внутри неё. После каждого сценария — чистое `git status --short` живого дерева.
5. **Гейт не сдвинут.** `ADM-1` по-прежнему не выдаётся до полного принятого отчёта
   `ADM-0P-R1`.

## 4. Урок оркестрации

Карточка, существующая только в неслитом draft PR, не является доступным входом для
изолированного воркера. Если docs-PR ещё не в `main`, промпт обязан быть
самодостаточным либо явно разрешать ровно один fetch документа до начала офлайн-фазы.
Смешивать оба режима в одном промпте запрещено.
