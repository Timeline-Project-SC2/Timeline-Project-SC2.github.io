# ADM-SECTOR-R2-FUNCTION (Р2): разведка функционала

> **ID:** `ADM_SECTOR_R2_FUNCTION_V1` · **Место:** 2 из 3, отчёт → Р3 и (дословно) → Р4.
> **Вход:** **только отчёт Р1**. Карточка Р1, её файлы и критерии тебе не передаются; детали своей карточки Р3 и Р4 не раскрываешь — «без деталей второго».
> **База:** `origin/main = 3554e92`; активная ветка сессии, работа только в своей ветке.
> **Адресат:** назначается владельцем при выдаче. Язык — русский.
> **Режим:** read-only по коду; короткий ручной smoke страниц допустим, если окружение позволяет, без новых сервисов и без публикации.

## 1. Цель

Проверить, **что реально работает у пользователя** в редакторе границ и на карте сектора, и отделить работающее от заявленного, неработающего, непроверенного и отложенного. Выводы делать по отчёту Р1 и по наблюдаемому поведению, не по догадкам о коде.

## 2. Что проверить

| Контур | Что подтвердить |
|---|---|
| Публичная карта `/sector/` | области видны только для чтения; нет панели, кисти, записи; карта, поиск, полёт и стрелки не сломаны |
| Админская копия `/sector/admin-edit/` | вход по тестовому коду; панель свёрнутая/развёрнутая; «Рисовать границы», режим, кисть, привязка |
| Ввод | левая кнопка тянет контур и создаёт область; щелчок левой только выделяет; правая и колесо остаются карте; `Esc`, `F`, `Ctrl+Z`/`Ctrl+Shift+Z`; жест не начинается на органе панели |
| Свойства и состояния | выбор области, имя/цвет, закраска последним мазком, сводка вершин/площади/адреса; удаление не трогает дочерние без подтверждения |
| Черновик и выгрузка | черновик в браузере, «Скачать JSON»/«Скопировать», «Материал заявки»; загрузка чужого или битого JSON отклоняется валидатором |
| Журнал и история | последние двенадцать событий, новая правка очищает повтор, отмена не прыгает через действия |
| Не сделано | правка вершин мышью, выбор фракции/задачи в свойствах, анимации режимов, публикация/PR-workflow, автоматическая заявка |
| `HOLD` | живая запись и публикация, Sheets/sync, планеты, OAuth/App/секреты/workflow/сервер, вторая модерация, PR #348 |

## 3. Что должно быть в отчёте

- Таблица `контур | работает / не работает / не проверено / HOLD | как проверено | где расхождение с отчётом Р1`.
- Явные расхождения между кодом (отчёт Р1) и поведением: что заявлено, но не наблюдается; что наблюдается, но в отчёте Р1 не описано.
- Список того, что **не проверялось** и почему (нет браузера, нет телефона, нет визуальной приёмки владельца).

## 4. Формат отчёта

До **30 строк**, только текст, метки `доказано / наблюдение / предложение / выбрано`. Начинать с базы, `HEAD` и пометки «вход: отчёт Р1». HTTP `200` не считается доказательством работы интерфейса. Не добавлять выводы о документации — это следующий этап.

## 5. Чего не делать

- Не править код, данные, тесты и документы; не создавать новые тесты и задачи.
- Не запускать полный набор тестов/сборок: только критический минимум (`npm run build` при необходимости, короткий smoke, `git diff --check`).
- Не передавать Р3 или Р4 свою карточку и её детали — только отчёт.

## 6. Проверки и останов

`git status --short`, `git diff --name-only origin/main...HEAD` (пусто), `git diff --check`. Останов: отчёт готов, дерево чистое. Отчёт передаётся **Р3**; владелец сохраняет дословную копию для **Р4**.
