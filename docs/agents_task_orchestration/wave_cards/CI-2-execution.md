| **5** | Полный прогон §6, отчёт §8, **стоп перед merge**. | CI 4/4; diff ровно 5 OWNED; красные пути доказаны пробами/фикстурами |

## 6. Гейты и доказательства

**База:** на `main` страж `CI-1` зелёный при 8 фактических падениях, CI 4/4. Эта карточка не
чинит падения, она переводит их из «исполняются и изолируются стражем» в «пропускаются раннером
по именному карантину», сохраняя страж целостности. Node локально 22.22.3 vs Node 24 CI —
флаг определяется автодетектом по `node --help` (F2-6).

**Обязательные локальные команды (воркер, после `npm ci`):**

```bash
npm run test:raw                 # прежнее поведение: те же 8 fail по именам
npm test                         # два прогона стража: exit 0, N2 = N1 − 8, 0 not ok в карантинном
node --test tests/check-test-baseline.test.mjs
npm run lint && npm run typecheck && npm run build
npm run check:planet-core
npm run verify:docs
git diff --check
git diff --name-only origin/main...HEAD
```

**CI-доказательство:** ID прогона PR + выгрузка `gh api .../actions/runs/<id>/jobs`, где все
9 шагов джобы `scripts` `success`, а шаг тестов называется по §4.4. Остальные джобы без регрессий.

## 7. Риски (векторы отказа, `rc-08`)

| № | Vector отказа | Что делаем заранее |
|---|---|---|
| 1 | Имя skip-флага различается между Node 22 и 24 | Автодетект по `node --help` (`--test-skip` → `--test-skip-pattern`), ошибка если флага нет; CI Node 24 — финальный арбитр на шаге 3 |
| 2 | Спецсимволы TAP-имён (`()#·≤%`, кириллица) ломают regex | Экранирование + anchors, self-test на реальных строках реестра; red-проба с устаревшим именем |
| 3 | Паттерн матчит лишнее (частичное совпадение) | Якоря `^…$` по полному имени; арифметика `N2 = N1 − 8` — лишняя фильтрация сразу краснит прогон 2, случай покрыт self-test'ом |
| 4 | Переименование теста в будущем делает карантин фиктивным | Прогон 1 без флагов: имя реестра обязано падать; не падает → exit 1 «КАРАНТИН НЕ ПРИМЕНЁН». Вариант B («отсутствует = пропущен») из эскалации отклонён именно поэтому |
| 5 | Соблазн расширить реестр, чтобы позеленить новое падение | Прямой запрет §2; любое новое `not ok` в прогоне 1 краснит страж, реестр меняется только решением владельца |
| 6 | Self-test сам попадает в карантинный прогон и обязан пройти | Его нет в реестре, он исполняется обычно; в гейтах §6 отдельный вызов `node --test` по нему |
| 7 | Различия TAP на Node 22 и 24 (нумерация, вложенность, имена план-строк) | Парсер на структуре (`ok/not ok`, имена после ` - `), а не на локали; фикстуры обоих форматов; CI Node 24 — финальный арбитр |
| 8 | Потеря сигнала внутри 8 тестов воспринимается как «их можно забыть» | Пункт `S8-Q1` этапа 8 с условием снятия; `test:raw` как аварийный люк; реестр с `meta` и датами |
| 9 | Два прогона удваивают время шага тестов | Принято в CI2-7 как цена сохранения инвариантов; таймаутов джобы с запасом, других шагов изменение не касается; склейка в один процесс запрещена (вернёт разбитое окно) |

## 7b. Красные пути стража — требование §1 п.2 детально (редакция CI2-7, два прогона)

| Событие | Прогон | Ожидаемый исход |
|---|---|---|
| Прогон 1: ровно 8 реестровых `not ok`; прогон 2: 0 `not ok`, `N2 = N1 − 8` | оба | exit 0, строка «8/8 реестровых падений; отфильтровано 8, not ok 0; новых падений нет» |
| Новое `not ok` (любое имя вне реестра) | 1 | exit 1, «НОВЫЕ ПАДЕНИЯ:» + имена |
| Имя реестра перестало падать (тест починен/переименован) | 1 | exit 1, «КАРАНТИН НЕ ПРИМЕНЁН: устаревшие имена …» |
| Skip-паттерн не сматчился или широкий: `not ok` в прогоне 2 либо `N2 ≠ N1 − 8` | 2 | exit 1, «КАРАНТИН НЕ ПРИМЕНЁН:» + арифметика `N1/N2` |
| Любой из процессов умер без TAP-итогов | любой | exit 1, сообщение о крэше с номером прогона, под реестр не маскируется |

Код выхода процесса прогона 1 в оценке не участвует (восемь падений ожидаемы) — сигналом
служит только разбор TAP; код выхода прогона 2 обязан быть `0`.

## 8. Формат отчёта Гайдлайнеру (10–15 строк)

```text
Воркер CI-2 · PR #N · ветка <имя> · HEAD == origin/<ветка>
OWNED_FILES: <5 файлов из git diff --name-only>
Шаг 0 факты: флаг Node 22 <имя> · фильтрация без # SKIP подтверждена · 8 имён совпали да/нет ·
  других skip в репо N · вызовы npm test: <где>
Шаги: 1 … 5 | коммит | суть
Страж: прогон 1 — 8/8 реестровых not ok; прогон 2 — N2 = N1 − 8, not ok 0, exit 0;
  test:raw: те же 8 fail
Красные пути: чем доказаны (self-test N/N + откаченные пробы)
CI: run id, jobs API — 9 шагов scripts success, 4/4 джобы
Локальные гейты §6: результаты построчно
Не проверено: —
Открытые вопросы и эскалации: …
Стоп перед merge — готов к приёмке Гайдлайнером
```

## 9. Эскалация и стоп

- Node 24 не поддерживает ни один из известных skip-флагов или паттерны не матчат полные
  кириллические имена — **стоп и вопрос**, никаких file-level skip и правок тест-исходников.
- Третья неудачная попытка — владельцу по §18.6 [`../waves/f-gates.md`](../waves/f-gates.md).
- **Стоп перед merge:** до зелёного карантинного прогона и вердикта `rc-07` карточка `F-4`
  не выдаётся.

## 10. Журнал решений Гайдлайнера

| № | Вопрос | Решение и причина |
|---|---|---|
| CI2-1 | Где живёт скрытие | На уровне раннера (выбор владельца): тест-исходники не редактируются, граница `И-11` цела; source-level `test.todo` отклонён, т.к. требует правки планетарных файлов и размазывает карантин по коду |
| CI2-2 | Имена файлов стража и реестра | Сохраняются (`check_test_baseline.mjs`, `known-test-failures.json`) — на них ссылаются 15 docs-мест и `check.yml`; меняется режим, не имена |
| CI2-3 | Аварийный люк | `test:raw` дословно повторяет прежний `npm test`: полное исполнение и видимость восьми падений в любой момент без снятия карантина |
| CI2-4 | Как не дать карантину стать фиктивным | Страж целостности: устаревшее имя реестра и лишний skip краснят так же, как новое падение; молча удалить запись нельзя |
| CI2-5 | Разные флаги Node 22/24 | Автодетект по `node --help`, без хардкода версии; поведение на Node 24 доказывает CI PR |
| CI2-6 | Потеря регрессионного сигнала | Принята владельцем как цена чистых отчётов; компенсации — `S8-Q1` с условием снятия, `test:raw`, страж; решение о снятии карантина — за этапом 8/владельцем, не за CI |
| CI2-7 | Эскалация воркера: `--test-skip*` фильтрует тесты до исполнения, TAP-строк `# SKIP` не бывает — буквальный §4.2 неисполним | **Принят вариант A: страж в два прогона.** Прогон 1 (без флагов) хранит все инварианты целостности (ровно 8 реестровых падений, новое и устаревшее имя различимы); прогон 2 (8 якорных флагов) даёт чистый отчёт, а арифметика `N2 = N1 − 8` доказывает точечность фильтра. B («отсутствует = пропущен») отклонён — устаревание имени неотличимо, карантин стал бы фиктивным (нарушает §1 п.2б/CI2-4). C отклонён — 8 `not ok` остаются в TAP, противоречит директиве владельца «не маячить в отчётах» (это статус-кво `CI-1`). D не нужен: матрица 5 файлов и все инварианты сохранены, правка контракта делается на месте. Цена — ~2× времени шага тестов (риск 9), TAP-skip семантика заменена фильтрацией |
