## 6. Гейты и доказательства

**База:** норма `npm test` — те же 8 планетарных падений (Stage-8.5, Stage-8.10b ×2,
A-17 ×2, W26b ×2, контракт ядра); в CI джоба `scripts` красная штатно, но по одному
монолитному шагу — это и есть закрываемый долг. Node локально `v22.x` против `.nvmrc` 24 —
известный не-блокер (F2-6), версия в отчёт.

**Обязательные локальные команды (воркер, после `npm ci`):**

```bash
node tools/check_test_baseline.mjs          # выход 0, в логе 8/8 по базе
node --test tests/check-test-baseline.test.mjs
npx eslint site src tools tests
npm run check:planet-core
npm run typecheck
npm run build
npm run verify:docs
git diff --check
git diff --name-only origin/main...HEAD
```

**Доказательство красного пути стража (без мусорных коммитов):** временная мутация фикстуры в
self-test уже покрывает новое падение и устаревшую базу; дополнительно — один локальный прогон
с временно добавленной строкой в базу (откатить, в diff не попадает), зафиксировать выход 1
и секцию «БАЗА УСТАРЕЛА» в отчёте.

**CI-доказательство:** ID прогона PR и выгрузка `gh api .../actions/runs/<id>/jobs`, где у
джобы `scripts` все шаги `success`, включая «Линт ESLint» и «planet-core». Остальные три джобы
без регрессий (перф-джоба в тех же пределах baseline).

## 8. Формат отчёта Гайдлайнеру (10–15 строк)

```text

Шаг 0 факты: TAP-имена 8 падений (список) · sourceType travel-planner ·
  глобальный test да/нет · находки eslint N · lint после npm ci да/нет · planet-core да/нет
Шаги: 1 … 5 | коммит | суть
Страж: зелёный прогон 8/8; красные пути (новое/устаревшее/крэш) — чем доказаны
Линт: scope site/src/tools/tests, число находок и как закрыты
CI: run id, jobs API — все шаги scripts success; прочие джобы без регрессий
Локальные гейты §6: результаты построчно
Не проверено: — (GPU/визуал карточки не касается)
Открытые вопросы и эскалации: …
Стоп перед merge — готов к приёмке Гайдлайнером
```

## 10. Журнал решений Гайдлайнера

| № | Вопрос | Решение и причина |
|---|---|---|
| CI1-1 | Как изолировать известный долг, чтобы гейт стал бинарным | Страж базы поверх полного прогона: тесты не скипаются, сигнал регрессий внутри самих 8 тестов сохраняется; альтернативы `skip/todo` и `continue-on-error` отклонены (аудит §4) |
| CI1-2 | Где живёт список известных падений | Отдельный `tools/known-test-failures.json` с именем, файлом и меткой этапа; комментарий в коде теста нарушил бы границу `И-11` и разъехался бы с TAP-именем |
| CI1-3 | Откуда страж берёт список тестов | Из `scripts.test` в `package.json` + `--test-reporter=tap`: единственный источник, нулевой дрейф; свой список файлов запрещён |
| CI1-4 | Реакция на исчезновение базового падения | Красный шаг с требованием обновить базу в том же PR: «молчаливое» позеленение скрывает и починку, и переименование |
| CI1-5 | Объём ESLint-расширения | Только `no-undef` на `tools/**` и `tests/**` — исторически единственное правило репо, ловит класс поломки с удалённой переменной; стилевые правила — отдельное решение владельца, не этот PR |
| CI1-6 | Порядок относительно `F-4` | `CI-1` первой: её результат — бинарный гейт, под которым `F-4` уже не сможет тихо принести девятое падение; файловых пересечений с `F-4` нет |
| CI1-7 | Открытый вопрос воркера: §4.4 называл для `tools/tests` только `globals.node`, а `bench_planet_baseline.mjs` требует браузерных глобалов (32 ложных `no-undef`) | **Принят отдельный узкий блок flat-config с `globals.node + globals.browser` ровно на один файл.** Греп подтвердил: `window/document/navigator/requestAnimationFrame` там исключительно внутри колбэков puppeteer `page.evaluate` (строки 236–264), то есть исполняются в браузере; Node-часть файла сохраняет node-глобалы, правило `no-undef` не ослаблено, на остальные 57 файлов блок не распространяется |
| CI1-8 | Имя шага `npm ci` | Принято «Установка зависимостей (npm ci)» — русское имя в стиле джобы `build`; контракт §4.1 предписывал отдельный шаг, имя не регламентировал |

`tests 437, fail 8`; self-test `16/16`; ESLint 0 находок после правок; `check:planet-core`,
`typecheck`, `build`, все верификаторы и `verify:docs` — зелёные. Сырой лог CI из песочницы
недоступен (хост логов вне белого списка) — доказательством служит jobs API; вывод стража в
CI однозначен, поскольку шаг зелёный только при точном совпадении множества падений с базой.

**Следствие для всех следующих карточек:** красная джоба «Скрипты сайта» больше не штатная.
Норма «девятое падение блокирует» механически исполняется стражем; `--admin` остаётся только
для ruleset-ограничения ветки, а не для маскировки красного CI. Новая норма внесена в
[`f-gates.md` §18.5](../waves/f-gates.md) и [`shift_handoff.md` §7](../shift_handoff.md).

## 12. Преемственность: карточка `CI-2` (решение владельца 26.10.2026)

Решение E2 (восемь тестов исполняются всегда, страж ловит новое падение) **изменено по прямой
директиве владельца**: падения временно скрываются на уровне раннера через `--test-skip` от
реестра `known-test-failures.json`, чтобы не маячить в отчётах. Что из вердикта `CI-1` остаётся
в силе: бинарный гейт (E1), именованные шаги, ESLint на `tools/tests` (E3), `node --check`
(E4), planet-core отдельным шагом (E5), страж как механика — он переведён в режим целостности
карантина. Что осознанно принято в жертву (журнал `CI2-6`): сигнал регрессий внутри восьми
тестов до снятия карантина; компенсации — `npm run test:raw`, пункт этапа
[`S8-Q1`](../../stages/stage-08/todo.md) с условием снятия и красные пути стража. Историческая
запись §11 не переписывается: на момент слияния `CI-1` всё в ней было истинно.
