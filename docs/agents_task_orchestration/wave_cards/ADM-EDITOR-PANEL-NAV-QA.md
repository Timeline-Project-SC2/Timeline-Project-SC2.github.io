# ADM-EDITOR-PANEL-NAV-QA: независимая проверка навигационной панели

> **Статус:** карточка подготовлена; запускается только после реализации `ADM-EDITOR-PANEL-NAV`.
> **Роль:** независимая проверка (`rc-04`), без исправлений и коммитов.
> **Вход:** PR реализации, отчёт исполнителя и текущие критерии [`ADM-EDITOR-PANEL-NAV.md`](ADM-EDITOR-PANEL-NAV.md).

## 1. Границы

- Не изменять файлы, не коммитить и не запускать новый Pages deploy.
- Проверять именно кандидатный HEAD PR, сверяя SHA с отчётом исполнителя и статусами CI.
- Разделять доказанные результаты, наблюдения и непроверенное. Отчёт — компактный, без дампов кода и логов.
- Визуальную приёмку не выполнять за владельца и не заменять ею функциональные проверки.

## 2. Проверки

1. Сверить `OWNED_FILES` и diff PR: разрешены только UI, CSS, UI-тест и руководство плюс унаследованные изменения PR #362; геометрия, контракт, снап, рендер и реестр не должны получить новые изменения.
2. Проверить PR/CI и локальные результаты исполнителя; убедиться, что нет красных обязательных проверок и что SHA совпадает.
3. По отчёту браузерной проверки или доступному preview проверить: карта остаётся видимой и интерактивной; выбор системы открывает один соответствующий экран; граф не раскрыт постоянно; переходы по зависимостям работают.
4. Отдельно проверить верхний слой левой панели «Системы»: открыть каждый другой редакторский экран/панель, убедиться, что навигация остаётся поверх, видна и кликабельна; повторить на узком viewport. Если проверка была только статическим просмотром CSS/DOM, явно так и указать — не заявлять runtime-проверку.
5. Проверить клавиатурную навигацию, подписи, горизонтальное переполнение и сохранность прежних команд рисования/привязки/создания области/undo-redo по тестам и отчёту исполнителя.
6. Выдать единый вердикт: `PASS`, `PASS WITH NOTES` или `HOLD`; сгруппировать замечания как `blocker`, `suggestion`, `nit`. При `HOLD` не исправлять код, а дать точные пути/сценарии и остановиться.

## 3. Отчёт

Указать PR и проверенный SHA; CI; какие сценарии реально выполнены, каким способом; результаты по верхнему слою, навигации, карте и адаптивности; ограничения; итоговый вердикт. После отчёта остановиться перед merge. Слияние возможно только после визуального решения владельца.
