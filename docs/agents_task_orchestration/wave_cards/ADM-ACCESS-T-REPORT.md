## 1. База и факты со слов воркера 2

Воркер сообщил чистый worktree; его HEAD — `661165bdc8bff9ff35a30ef9ba40b819460f9f2d`,
`origin/main` и реально прочитанный снимок — `70cd3c19f98faac79974fd9b5cc258976acf1a92`.
Гайдлайнер сверил актуальный remote `main` по Git-метаданным, исходники не читал.

| Workflow / job | Явные права и предполагаемые операции по отчёту |
|---|---|
| `assets.yml` / `build` | Ручной запуск; `contents: read`, checkout, сборка и артефакт (`:7–25`). |
| `check.yml` / `build`, `scripts`, `planet-perf` | PR и ручной запуск; на уровне workflow `contents: read`, три job наследуют права; выполняются код PR, тесты и сборка (`:8–50,67–142`). |
| `pages.yml` / `deploy` | Push в `main` и ручной запуск; `contents: read`, `pages: write`, `id-token: write`; сборка и Pages (`:3–11,28–29,78–90`). |
| `sync.yml` / `sync` | Расписание, ручной и `repository_dispatch`; `contents: read`, `issues: write`, checkout с `persist-credentials: false`; запросы GitHub, сообщения при ошибке и push (`:3–12,23–26,30–53,65–70`). |

По воркеру, остальные checkout используют стандартное сохранение credentials. В
`tools/sync.py:120–130,657,695–710` есть запросы со встроенным токеном, а push использует
**отдельный секрет**, не `contents: write` встроенного токена. Названия, значения и
наличие секретов не устанавливались. Реальное выполнение, права и организация не
проверены. Для fork PR обычно действует дополнительное ограничение токена и секретов;
внутренние PR и секретный job требуют отдельной оценки.

## 2. Что означает снижение default

По отчёту воркера, все четыре workflow уже объявляют права на уровне workflow, а
шесть job наследуют их. Переключение **значения по умолчанию** на read-only само по
себе не должно убрать явно запрошенные `pages: write` или `issues: write`; фактические
права зависят от политик и событий. Это не снимает явно выданные write-права и не
доказывает работу публикации и sync. Смена default может ограничить будущие job без
собственных прав, но не является защитой `.pem` или разрешением на живую запись
[1](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#permissions).

По отчёту, `.github/workflows/actions.lock` в проверенном снимке отсутствует, а `uses`
ссылаются на теги. GitHub документирует lockfile как возможный способ закрепления
покрытых actions; на практике эта база, по воркеру, им не покрыта
[2](https://docs.github.com/en/actions/concepts/security/workflow-dependency-lockfiles).
До независимой проверки не включать глобальное требование полного SHA.

## 3. Вердикт и следующий шаг

Воркер оставил изменение default на `HOLD`: статический анализ не заменяет реальной
проверки CI, Pages, прав организации, источников, обработки ошибок и push. Он предлагает
независимую проверку и, после отдельного разрешения, испытание на изолированных
фиктивных данных без производственных секретов и записи. Внешний тестовый репозиторий
ещё не выбран и не создавался; копирование боевых workflow или запуск sync запрещены.

Воркеру 1 подготовлена [независимая сверка и план изоляции](ADM-ACCESS-T-REVIEW.md).
Результат оценивается по документам, затем при необходимости независимым `rc-08`.
`STORE`, реальный тест App и автоматическое применение остаются на прежних отдельных
`HOLD`; ни секрет App, ни настройки, ни рабочие данные помощник не менял.
