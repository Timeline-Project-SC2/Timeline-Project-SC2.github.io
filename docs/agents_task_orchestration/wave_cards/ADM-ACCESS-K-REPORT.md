## 1. База и границы отчёта

Воркер указал `origin/main = 70cd3c19f98faac79974fd9b5cc258976acf1a92`, свой
`HEAD = 661165bdc8bff9ff35a30ef9ba40b819460f9f2d`. Способ чтения конкретного
снимка он не уточнил. Гайдлайнер сверил Git-метаданные: `661165b` — предок `70cd3c1`,
между ними менялась **только документация**, не код или workflow. Это не проверка
внешних настроек и не самостоятельное чтение исходников. Полный транзитивный аудит
зависимостей и реальные секреты/запуски воркер не проверял.

## 2. Факты со слов воркера 2

- `check.yml:8–13,24,33–50` на PR выполняет checkout и сборку кода PR; этот код и
  зависимости недоверенны. Секрет App в существующих workflow воркер не обнаружил.
  Fork PR обычно не получает обычные секреты, но это не защита от обладающих записью.
- На проверенной базе воркер не нашёл workflow на `issues`, `pull_request_target` или
  `workflow_run`, а также прямой shell-подстановки текста issue/PR в просмотренных
  блоках. Это не доказательство безопасности будущего job или всех зависимостей.
- `sync.yml:23–34` по отчёту берёт `main` без сохранения checkout credentials;
  `tools/sync.py:120–130` ограничивает отправку токена хостами и redirect. В
  `sync.yml:38–49,53–70` есть другие секреты и push-токен; их наличие и реальные
  запуски не проверены. Названия/значения секретов здесь не приводятся.
- Воркер отметил версии actions по тегам, не полным SHA (`check.yml:24–29`,
  `pages.yml:28–34`); `npm ci` и Pillow — риск цепочки поставок. `assets.yml:25`
  создаёт артефакт, `pages.yml:34–41,70–90` использует cache и публикует артефакт.
  Загрузку чужого артефакта на этой базе воркер не нашёл.
- По отчёту, доступные правила `main` показывали лишь creation/deletion; полные
  branch protection, политика Actions и default token вернули `403`. Доступное
  окружение `github-pages` имело protected branches и обход администратором; это не
  доказывает условия будущего окружения с ключом.

## 3. Сверка метаданных и ограничения

На момент приёмки Гайдлайнер через read-only GitHub API также увидел в доступном
ruleset `main` только creation/deletion. Ранее перед слиянием #341 тот же запрос
показывал больше правил; причина и время различия не установлены. Полная защита ветки
и разрешённые авторы workflow от этого **не доказаны**; настройки не менялись.

Установка App на показанном владельцем экране имеет `Read access to members` и
`No repositories`, но аккаунт установки на кадре не указан. Владелец сообщил, что
скачал `.pem`; сам ключ помощник не видел, создание Actions-секрета не подтверждено.
Чтение Members охватывает организацию, не только выбранный репозиторий.

## 4. Кандидат, не решение

Воркер предлагает отдельное окружение с секретом и разрешённой веткой `main`, **без
обязательного reviewer на каждую заявку**, с защитой изменений workflow и вызываемого
кода. Права на изменение, bypass и `workflow_dispatch` ещё надо проверить. Окружение
ограничивает доступ к секрету job, ссылающейся на него, но не защищает от изменения
доверенного workflow, опасного кода на `main`, недоверенных входов или администраторов.
`Protected branches only` нельзя считать эквивалентом выбранной `main`: при отсутствии
branch protection GitHub описывает допуск всех веток. Маскировка логов не гарантирована
[1](https://docs.github.com/en/actions/reference/security/secure-use)
[2](https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments).

Для App без прав репозитория кандидат — явный выбор установки организации, JWT App
и временный installation token с `Members: read`; фактическая установка и выполнение
не проверялись. У `actions/create-github-app-token` пустые `owner`/`repositories`
нацелены на текущий репозиторий, а явный `owner` без списка — на все доступные
установке репозитории; по умолчанию токен наследует все права установки
[3](https://github.com/actions/create-github-app-token/blob/main/README.md#inputs).
Расширение прав App позже может расширить последствия утечки долгоживущего ключа.

План отзыва требует отдельной проверки: `DELETE /installation/token` отзывает токен,
которым вызван endpoint, а не доказанно все неизвестные токены
[1](https://docs.github.com/en/rest/apps/installations).
При подозрении на утечку приостановка установки — документированный кандидат блокировки
[5](https://docs.github.com/en/apps/maintaining-github-apps/suspending-a-github-app-installation),
но процедуру восстановления и подтверждение воздействия ещё нужно согласовать.
