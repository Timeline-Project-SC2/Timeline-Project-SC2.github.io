## Что реализовать

Один чистый модуль без CLI и побочных действий. У него ровно такой экспорт:

    export async function assessIssueOwner(eventName, event, getMembership)

Результат — объект только с одним полем status, одно из четырёх значений:
- ignored — событие не issues.opened либо явно из другого репозитория;
- owner_role_evidence — переданное членство согласуется с активной ролью Owner;
- not_owner — достоверные распознанные данные говорят, что активной роли Owner нет;
- indeterminate — данных недостаточно, противоречие, неподдержанный ответ или ошибка.

Это классификация переданных свидетельств, НЕ авторизация заявки и НЕ разрешение
что-либо записывать. Вызвавшая сторона обязана отдельно удостовериться в происхождении
GitHub-события и ответа API. В этой задаче такого вызывающего production-кода нет.
Не проверяй историю правок, очередь и версию данных фальшивым «успехом»; по-прежнему
открыты исходный снимок, edit→restore, порядок Submit, повторы и гонка отзыва роли.

Контракт входа и отказов:
1. eventName должен быть issues, event.action — opened. Сопоставь full_name
   Timeline-Project-SC2/Timeline-Project-SC2.github.io без зависимости от регистра,
   repository.id 1421259694, organization.id и repository.owner.id 343675816;
   организация — Timeline-Project-SC2, тип владельца — Organization. Эти публичные
   ID проверены Гайдлайнером через GitHub API; ручной ID автора не нужен.
2. issue.id и issue.number — положительные безопасные целые числа JS, state в событии
   open. sender и issue.user — User с совпадающими положительными безопасными ID.
   Логин для API берётся из event.issue.user.login, а не из заголовка или тела;
   проверь безопасный непустой формат GitHub-логина. Несовпадение, bot, пропуски,
   небезопасные числа и прочие противоречия дают indeterminate, без запроса членства.
3. getMembership — доверенная асинхронная зависимость, а не данные из issue. Вызови
   её не более одного раза и только после всех локальных проверок, с аргументами
   ("Timeline-Project-SC2", login_автора). Результат: объект GitHub membership с
   user.id, organization.id, state и role. Нет callback, ошибка, timeout, 403/404/429,
   отсутствие данных, неподдержанные значения и несовпадение ID → indeterminate.
   Таймаут будущего API-адаптера должен приводить к отклонению callback; здесь он
   имитируется отклонением. Сам модуль таймер не создаёт: незавершившийся callback
   не проверен и требует ограничения в будущей интеграции. Сравни ID без потери
   точности; не пытайся лечить большие числа преобразованием.
4. Только state=active и role=admin → owner_role_evidence. Распознанные state
   active/pending и role admin/member, кроме active/admin, → not_owner. Для любого
   неизвестного значения — indeterminate. Репозиторный админ без Owner не проходит.
5. Для явно чужого репозитория или других событий → ignored и callback не вызывать.
   Если вход неоднозначный, не превращай его в owner_role_evidence. Заголовок и тело
   не исполняй и не интерполируй в команды; никакой ввод не должен стать кодом.
   Не выводи текст issue, логины, секреты, токены или полные API-ответы.

Модуль не делает HTTP, не открывает файлы и не запускает процессы. getMembership
передаётся вызывающим кодом; в этой задаче он всегда фиктивный, в памяти. Никаких
настоящих issue, запросов GitHub, App, секретов, сетевых вызовов или записи данных
во время тестов. Формат заявки и маркер [ADM-ACCESS] пока не утверждены: фильтр,
комментарии и действующий workflow в рамках этой карточки не добавляй.

## Граница приёмки

PR не подключает модуль к настоящей issue или App. Перед дальнейшей интеграцией нужна
соразмерная независимая проверка безопасности и согласование незакрытых решений;
зелёный тест положительного случая сам по себе не разрешает живую запись. Очередь,
состояния issue, Discord и переход от Sheets к данным репозитория — последующие этапы.
