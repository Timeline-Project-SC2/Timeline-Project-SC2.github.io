## 2. Что выбрано владельцем 02.11.2026

1. Снят прежний запрет на внешний сервис/доступ через zapret **в части этого сценария**. Админы обеспечивают доступ к `*.workers.dev`; вопрос «что именно добавлять в zapret» отложен владельцем и в эту карточку не входит.
2. Подключается **Cloudflare Worker как узкий OAuth-посредник**: только для входа в GitHub и автоматического создания/отправки issue после подтверждения в панели. Не прокси всего сайта, не постоянный рантайм Pages, не отдача контента.
3. Лимит Workers Free **доказан**: **100 000 запросов в день**, сброс в 00:00 UTC, бесплатный план без платы за duration [Limits](https://developers.cloudflare.com/workers/platform/limits/) [Pricing](https://developers.cloudflare.com/workers/platform/pricing/). Первоначальная формулировка владельца «100 000 в месяц» уточнена: скриншот панели на вкладке `Daily` показывает `Requests today 0 / 100,000` за 02.11.2026 — это **наблюдение**, а официальная документация фиксирует именно дневной лимит. `Observability events 0 / 200,000` — отдельный счётчик, не лимит запросов. Задача воркера «сверить лимит» снята как выполненная.
4. Целевой UX не меняется: правки → подтверждение в панели → вход/разрешение GitHub при необходимости → автоматическое создание issue → проверки → автоматическое применение и публикация **без второй ручной модерации**. Автоматизация — «насколько это возможно»; неподтверждённые шаги не выдавать за готовые.
5. Ручная предзаполненная форма GitHub — не выбранная замена. Общая корневая issue и общий код группы не предполагались; код issue не авторизация.
6. Позже 02.11.2026 владелец отдельно реактивировал A0-P по новой карточке [ADM-ACCESS-A0-P-REACTIVATION.md](ADM-ACCESS-A0-P-REACTIVATION.md). Это отдельная линия офлайн-слоя `А`: не отмена CF Worker, не замена выбранного UX и не разрешение запускать агентов/автоматизацию.
7. Правило доставки: правки и доп. руководства выдавать **ссылкой сразу на ветку** `arena/911dc5ef-timeline-project-sc2-github-io` **или заносить в `main`**. «Иной вид» — [карточка-редирект](ADM-ACCESS-CARDS-REDIRECT.md) с вложенным блоком автопарсинга.

**Наблюдение:** без zapret/VPN тестовый `*.workers.dev` даёт `ERR_CONNECTION_RESET`; по словам владельца, с доступом работает. Скриншот панели Cloudflare от 02.11.2026 на вкладке `Daily`: `Requests today 0 / 100,000`, `Observability events today 0 / 200,000`. Сеть в этой задаче не проверять.

**Доказано только по документации/метаданным:** обычный web-flow GitHub App требует `client_secret` и callback URL; installation token приписывает действие боту App, user token — человеку и App; SPA-режим roadmap #1153 остаётся `Paused`; Workers Free — 100 000 запросов в день, сброс 00:00 UTC [Limits](https://developers.cloudflare.com/workers/platform/limits/) [Pricing](https://developers.cloudflare.com/workers/platform/pricing/); факт живой реализации в проекте отсутствует.

## 4. Что нужно выяснить воркеру

1. Указать базу `origin/main` и фактический HEAD, с которым работал. Без этого остановиться.
2. По актуальному `main` найти точки админ-панели, демо-входа, заготовок редактора и их тесты: точные `путь:строка`, отделить рабочее от заглушек. Демо-код не считать GitHub-авторизацией. Дать непересекающиеся кандидаты файлов для будущего шага, **не назначая OWNED_FILES**.
3. Описать узкую схему CF Worker: GitHub App web flow → `state`/PKCE → callback на Worker → обмен `code` на user access token с `client_secret` в секрете Worker → создание issue пользовательским токеном с `title`/`body`. Ни секретов, ни токенов, ни OAuth-кода в браузерном коде, URL, issue и логах. Worker не проксирует сайт и не трогает данные.
4. Подготовить **список настроек для владельца без значений**: точные поля GitHub App, callback URL, необходимые права (`Issues: read and write`, `Members: read`), истечение/обновление/отзыв токенов, названия секретов/переменных Worker, разрешённые origin. Лимит **уже подтверждён**: Workers Free — 100 000 запросов в день, сброс 00:00 UTC; отдельно `Observability events` 200 000/день. Повторно «проверять 100 000 в месяц» не требуется. Не запрашивать и не выводить ключи, токены, пароли, приватные URL.
5. Перечислить открытые блокеры, не решая их за владельца: реальный отправитель B в issue A, активный Owner **организации**, правка `title/body` после Submit → новая issue, отсутствие доказательства неизменности → стоп, первая отправленная заявка, публичность issue и предупреждение до отправки, результат в той же issue, комментарий от бота App.
6. Не определять список доменов/IP для zapret, не предлагать новые внешние сервисы помимо выбранного CF Worker, не подключать OAuth/настройки, не создавать PR с реализацией/issue/App/секреты/workflow/сервер/тестовые данные; docs-PR #349 по команде владельца уже существует. Не запускать код, тесты, сборки, рабочие workflow, sync и не обращаться к содержимому реальных заявок.
7. A0-P реактивирована владельцем отдельной карточкой [ADM-ACCESS-A0-P-REACTIVATION.md](ADM-ACCESS-A0-P-REACTIVATION.md); в эту задачу её не включать. PR #348 не мёржить, не закрывать, историю силовыми методами не править; по метаданным он `draft`, `dirty`, без CI-сводки.

## 6. Критерии будущего теста — не запускать сейчас

Тест только после отдельного сигнала владельца о готовности редактора; сервер в песочнице не поднимать.

1. С настроенным доступом `*.workers.dev` открывается; без доступа остаётся наблюдавшийся `ERR_CONNECTION_RESET`.
2. Вход → GitHub → согласие → callback без ошибок.
3. В URL, логах, issue и браузерном коде нет `client_secret`, приватного ключа, токена, OAuth-кода и непубличных данных.
4. После подтверждения в панели issue создаётся автоматически; автором показан человек, не бот.
5. Проходит только активный Owner организации; repo-админ, неактивный и не-Owner не проходят.
6. До Submit черновик правится; после Submit правка блокирует старую заявку → нужна новая issue; без доказательства неизменности — стоп.
7. Результат виден в той же issue, комментарий от бота App; при успехе нет второй ручной модерации, при сбое — честный статус без слепого повтора.
8. Сайт остаётся доступен без Worker; Worker не отдаёт контент и не проксирует весь домен.
