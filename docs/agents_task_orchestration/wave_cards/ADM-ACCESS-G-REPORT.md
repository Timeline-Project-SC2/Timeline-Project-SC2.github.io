## 2. Блокер: автор заявки и автор изменения

Автор issue может оставаться владельцем организации, даже когда её описание изменил
другой человек с правом редактирования. GitHub допускает изменение issue не только
автором, но и сотрудником с правом записи [1](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/editing-an-issue).
Поэтому повторная проверка **только исходного автора** на `edited`/`reopened` может
ошибочно подтвердить изменённое содержимое. Этот вектор не считается закрытым одним
хешем или повторным чтением: правка могла произойти до первого чтения или после него.

Критик подтвердил блокер и потребовал уточнить контракт. Владелец выбрал новую issue
для исправленного содержания и результат в самой заявке. Сравнение снимков и гонки
пока не решены: подробности — в [разборе критики](ADM-ACCESS-R-REPORT.md) и
[черновике контракта](ADM-ACCESS-CONTRACT.md). Комментарий описывает только прошедшую
проверку; будущему применению нужны актуальные данные и новая проверка прав.
