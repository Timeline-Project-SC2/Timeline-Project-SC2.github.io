# Правила заполнения Google Sheets

Единая актуальная инструкция для вкладок `systems` и `places`. Источник данных сайта — опубликованные листы Google Sheets; `data/systems.csv` и `data/places.csv` — синхронизируемые снимки, вручную их не редактируйте.

Книга содержит два отдельных листа: `systems` — звёздные системы, `places` — планеты и другие места. Каждый лист публикуется отдельно в формате CSV; адреса и листы заданы в `data/sources.json`.

## Заголовки и структура

Синхронизация и интерфейс читают значения по именам колонок, поэтому порядок колонок не влияет на работу. Сохраняйте привычный порядок по шаблонам и не переименовывайте рабочие заголовки.

Сейчас в снимках таблицы находятся такие заголовки:

| Лист | Текущие заголовки из `data/*.csv` | Рекомендуемый шаблон |
|---|---|---|
| `systems` | `name,system_id,x,y,faction,description,source_url` | `id,name,type,x,y,faction,description,source_url` |
| `places` | `name,ID,system_id,x,y,faction,description,source_url` | `id,name,type,system_id,x,y,faction,description,source_url` |

В коде `systems.system_id` и `systems.id` — допустимые имена ID-колонки; для мест допустимы `ID` и `id`. Поэтому при заполнении уже работающей таблицы не меняйте текущие ID-заголовки: добавьте недостающую колонку `type`. Шаблоны показывают рекомендуемую структуру для новых таблиц. Не добавляйте второй ряд заголовков или поясняющие строки в диапазон опубликованного листа.

### Колонки `systems`

| Колонка | Как заполнять |
|---|---|
| `name` | Название системы; отображаемый текст. |
| `system_id` или `id` | Стабильный уникальный ID системы. В текущем листе используется `system_id`; не меняйте ID существующих строк. Значения должны совпадать с `places.system_id`. |
| `type` | Необязательный тег: `none`, `capital` или `unknow`. Если колонки или значения нет, интерфейс трактует систему как `none`. Для новых/обновлённых строк лучше явно указать `none`, если особой метки нет. Код также распознаёт `unknown`, но для единообразия используйте `unknow`. |
| `x`, `y` | Координаты узла на карте. Для отображения системы указывайте оба числа. Допустимая система карты — от 0 до `mapSize` (сейчас 10 000). |
| `faction` | Название фракции; необязательно. |
| `description` | Описание; необязательно. Не вставляйте в ячейку переносы строк: текущий браузерный CSV-разбор не поддерживает многострочные поля. |
| `source_url` | URL источника; необязательно. |

### Колонки `places`

| Колонка | Как заполнять |
|---|---|
| `ID` или `id` | Стабильный уникальный ID места. В текущем листе заголовок — `ID`; не меняйте ID существующих строк. |
| `name` | Название места. |
| `type` | Один тип: `planet`, `moon`, `asteroid`, `station`, `platform` или `other`. Сейчас колонка отсутствует в снимке таблицы, но есть в шаблоне. Если её не добавить/не заполнить, интерфейс по умолчанию считает каждую запись планетой. |
| `system_id` | ID родительской системы; должен совпадать с её `system_id`/`id`. Пустое значение оставляет место без связи с системой. Синхронизация не проверяет, существует ли такая система. |
| `x`, `y` | Необязательные числовые поля. Текущий интерфейс отображает координату связанной системы; собственные `places.x` и `places.y` не ставят место отдельной точкой на карте. Не используйте их как замену координатам системы. |
| `faction`, `description`, `source_url` | Необязательные сведения о месте. Для `description` не используйте переносы строк. |

Типы вводите латиницей, строчными буквами, без списков через запятую или точку с запятой. Значения перечисленных типов совпадают с каталогом сайта; синк Google Sheets не проверяет допустимость enum, поэтому опечатка может попасть в сайт.

## Координаты

- Вводите `x` первым, `y` вторым. Shift+клик по карте сектора копирует целые X и Y через табуляцию — вставка заполняет две соседние ячейки, например колонки `x` и `y`.
- Координатная сетка интерфейса — `0…mapSize`; сейчас `mapSize` равен 10 000. Начало сетки находится в левом верхнем углу подложки: X растёт вправо, Y — вниз.
- Можно вводить целые или дробные числа; для дробей используйте точку (`123.45`), а не запятую. В Google Sheets задайте этим ячейкам числовой формат, не текст с единицами измерения.
- Для `systems` заполните оба значения. Пустые или нечисловые значения код интерфейса не отклоняет как ошибку: система может получить координату `0,0`, поэтому проверяйте их вручную.
- Не переворачивайте Y и не масштабируйте координаты самостоятельно. Сейчас в `data/sources.json` `flipY` выключен, масштаб равен 1. Изменение преобразования источника — задача разработчика.
- Ожидаемый диапазон — `0 ≤ x,y ≤ mapSize`. Важно: для Google Sheets текущая версия `tools/sync.py` не проверяет диапазон и корректность чисел. Значения вне диапазона синк может принять, но они будут за пределами карты.

## ID и связи

- Сохраняйте существующие ID; новые делайте непустыми и уникальными в пределах своего листа. В Google Sheets задавайте колонке ID формат «Обычный текст», если важны ведущие нули. Текущие данные используют короткие числовые ID, но менять их нельзя.
- Связь места с системой задаётся через `places.system_id`. Совпадение ID необходимо для группировки места в досье системы.
- Синк проверяет дубли ID, только если в заголовках есть узнаваемая ID-колонка; он не проверяет наличие всех обязательных полей и не проверяет ссылочную целостность `system_id`. Не полагайтесь на автоматическую проверку этих условий.

## Публикация и CSV

1. В Google Sheets откройте **Файл → Поделиться → Опубликовать в интернете**.
2. Опубликуйте лист `systems` как CSV, затем отдельно лист `places` как CSV. Не выбирайте публикацию всей книги одним листом.
3. После правок дождитесь очередного запуска синхронизации (раз в 6 часов) или откройте **Actions → Sync upstream map data → Run workflow**.

Используйте экспорт Google Sheets в CSV, не собирайте CSV вручную. Запятые в текстовых ячейках допустимы: корректный CSV-экспорт заключает их в кавычки, а парсер сайта обрабатывает стандартное экранирование. Кодировка — UTF-8. Синк проверяет, что ответ непустой, не является HTML-страницей и похож на CSV; при отсутствии публикации Google обычно отдаёт HTML вместо CSV.

Если запуск синхронизации завершается ошибкой, workflow не выполняет шаг коммита в Git, и опубликованный сайт остаётся на последних закоммиченных данных. Но синк не проверяет все правила заполнения, перечисленные выше; корректность типов, обязательных полей, координат и связей проверяйте вручную.

## Чек-лист перед публикацией

- [ ] Редактируется Google-таблица, а не выгрузки `data/*.csv`.
- [ ] В каждой опубликованной вкладке первая строка — заголовки; рабочие имена колонок не переименованы.
- [ ] Все системы имеют стабильный ID, название и числовые `x`,`y` в диапазоне `0…10 000`.
- [ ] В `systems.type` указано `none`, `capital` или `unknow`.
- [ ] У мест указаны стабильные уникальные ID и названия; для `type` выбран один из шести поддерживаемых вариантов.
- [ ] `places.system_id` точно совпадает с ID системы, если место должно быть с ней связано.
- [ ] В дробных координатах используется точка; описания не содержат переносов строк.
- [ ] Оба листа опубликованы отдельно как CSV.
