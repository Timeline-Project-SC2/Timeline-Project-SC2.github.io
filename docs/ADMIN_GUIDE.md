# Правила заполнения Google Sheets

Единая актуальная инструкция для вкладок `systems`, `places` и новой вкладки профилей планет `planet_generation`. При росте файла новые разделы выносятся по контекстам вкладок в [`docs/admins/`](admins/README.md), а не ужимаются здесь (лимит 200 строк). Источник данных сайта — опубликованные листы Google Sheets; `data/systems.csv`, `data/places.csv` и `data/planet-generation.csv` — синхронизируемые снимки, вручную их не редактируйте.

В `data/sources.json` включены три листа одной книги: `systems` — звёздные системы, `places` — планеты и другие места, `planet_generation` — рецепты процедурных планет. Книга опубликована в интернете целиком с автопубликацией изменений; каждый CSV-адрес выбирает нужную вкладку параметром `gid`. Не отменяйте и не пересоздавайте публикацию без разработчика — адрес с токеном `2PACX-…` может смениться, и синхронизация остановится. Сайт пока не отображает профили планет: для этого нужны боевые страницы следующих этапов.

## Заголовки и структура

Синхронизация и интерфейс читают значения по именам колонок, поэтому порядок колонок не влияет на работу. Сохраняйте привычный порядок по шаблонам и не переименовывайте рабочие заголовки.

Сейчас в снимках таблицы находятся такие заголовки:

| Лист | Текущие заголовки из `data/*.csv` | Рекомендуемый шаблон |
|---|---|---|
| `systems` | `name,system_id,type,x,y,faction,description,source_url` | `id,name,type,x,y,faction,description,source_url` |
| `places` | `name,ID,type,system_id,x,y,faction,description,source_url` | `id,name,type,system_id,x,y,faction,description,source_url` |
| `planet_generation` | В снимке пока только заголовок из 37 колонок; профилей нет | См. `data/planet-generation-template.csv` |

В коде `systems.system_id` и `systems.id` — допустимые имена ID-колонки; для мест допустимы `ID` и `id`. В текущих снимках обоих листов колонка `type` уже есть. При редактировании существующей таблицы сохраняйте её ID-заголовок и не меняйте ID строк. Если в рабочей вкладке `type` отсутствует, добавьте колонку с этим заголовком. Шаблоны показывают рекомендуемую структуру для новых таблиц. Не добавляйте второй ряд заголовков или поясняющие строки в диапазон опубликованного листа.

### Колонки `systems`

| Колонка | Как заполнять |
|---|---|
| `name` | Название системы; отображаемый текст. |
| `system_id` или `id` | Стабильный уникальный ID системы. В текущем листе используется `system_id`; не меняйте ID существующих строк. Значения должны совпадать с `places.system_id`. |
| `type` | Необязательная характеристика: `capital` («Столица») или `unknow` («Неизвестный тип»). Пустое значение и старое значение `none` трактуются как стандартная система; вручную `none` указывать не нужно. Код также распознаёт `unknown`, но для единообразия используйте `unknow`. |
| `x`, `y` | Явные координаты системы на схеме. Чтобы показать маркер, заполните обе ячейки числами в диапазоне `0…mapSize` (сейчас 10 000). Если одна координата отсутствует, значение нечисловое или пара вне диапазона, система останется в каталоге без маркера. Не ставьте предполагаемые точки: координаты должны быть явно нанесены на карту. |
| `faction` | Название фракции; необязательно. Оставьте пустым, если фракция не указана; `none` при чтении считается пустым значением. |
| `description` | Описание; необязательно; выводится в карточке системы. Пустая ячейка или `none` означает, что в таблице описание не задано. Не вставляйте в ячейку переносы строк: текущий браузерный CSV-разбор не поддерживает многострочные поля. |
| `source_url` | Полный URL источника с `https://` или `http://`; необязательно; выводится в карточке системы как ссылка. Пустая ячейка или `none` означает, что в таблице ссылка не задана. |

### Колонки `places`

| Колонка | Как заполнять |
|---|---|
| `ID` или `id` | Стабильный уникальный ID места. В текущем листе заголовок — `ID`; не меняйте ID существующих строк. |
| `name` | Название места. |
| `type` | Один тип: `planet`, `moon`, `asteroid`, `station`, `platform` или `other`. Колонка присутствует в текущем снимке таблицы и шаблоне. Пустое значение, `none` или отсутствие колонки означает стандартный тип — планету. |
| `system_id` | ID родительской системы; должен совпадать с её `system_id`/`id`. Пустое значение или `none` означает, что связь с системой не задана; место станет самостоятельной точкой только при наличии обеих координат `x`,`y`. Синхронизация не проверяет, существует ли указанный ID. |
| `x`, `y` | Если `system_id` указан, эти значения не создают отдельную точку: место относится к системе. Если `system_id` пуст и обе координаты заданы числами в диапазоне карты, место отображается как самостоятельная точка интереса (POI). Пустая ячейка или `none` означает, что координата не задана; без полной пары запись остаётся только в каталоге. |
| `faction`, `description`, `source_url` | Необязательные сведения о месте. Описание и ссылка показываются в карточке места. Для незаполненного значения оставьте ячейку пустой; старое значение `none` читается как пустое. Для `source_url` указывайте полный URL с `https://` или `http://`; в `description` не используйте переносы строк. |

Типы вводите латиницей, строчными буквами, без списков через запятую или точку с запятой. Пустое значение и `none` обрабатываются по умолчанию каждого поля: для системы это стандартная «Система», для места — «Планета», для необязательных текстовых полей — отсутствие значения. Для ID и названия такой подстановки нет: они обязательны и должны содержать реальные значения. Пустые необязательные текстовые поля не затирают сведения, уже пришедшие из основного каталога; они лишь означают, что таблица не добавляет для поля новое значение. Для `systems` и `places` синк по-прежнему не проверяет все enum и связи, поэтому опечатка может попасть на сайт. Для нового листа `planet_generation` правила строже: его проверяет отдельный валидатор, и ошибочная строка останавливает синхронизацию целиком.

## Лист `planet_generation`

Этот лист не заменяет `places`. Он хранит рецепт процедурной поверхности только для тех мест, которым нужен глобус. Связь задаётся колонкой `place_id`: её значение должно посимвольно совпадать с `places.ID`. Одна строка профиля — на одно место.

### Как лист подключён

1. Вкладка `planet_generation` уже создана в общей книге (`gid=1183479406`), а её источник включён в `data/sources.json`.
2. В живой вкладке импортирован заголовок из [`data/planet-generation-template.csv`](../data/planet-generation-template.csv); профилей пока нет. Первая строка — только заголовки; поясняющие строки внутрь диапазона не добавляйте.
3. Перед первым заполнением задайте колонкам `place_id`, `master_seed_hex` и `generation_key` формат **«Обычный текст»**, чтобы Google Sheets не превратил ID и seed в числа и не отбросил ведущие нули.
4. Служебные колонки `master_seed_hex`, `grid_version`, `noise_version`, `geography_version`, `preset_version` и `generation_key` желательно защитить от случайного редактирования.
5. Отдельно публиковать вкладку не нужно: книга уже опубликована целиком с автопубликацией изменений, а CSV-адрес синка выбирает вкладку по `gid`.
6. Если вкладку придётся пересоздать, её `gid` сменится. Сразу передайте разработчику новую edit-ссылку, чтобы он обновил `data/sources.json`; до обновления синк будет обращаться к старой вкладке.

Точный заголовок можно также получить командой `python3 tools/planet_generation.py header`. Порядок колонок в листе допустим любой, но имена должны быть ровно теми же, без пропущенных, лишних и повторных колонок.

### Что заполняет администратор

Для обычного черновика достаточно шести полей:

| Поле | Что писать |
|---|---|
| `place_id` | Точный `ID` существующей строки из `places` |
| `profile_status` | На старте — `draft` |
| `profile_revision` | `1` для нового профиля |
| `preset_id` | Готовый шаблон мира из списка ниже |
| `surface_class` | Тип поверхности из списка ниже |
| `radius_km` | Радиус числом в километрах, если известен; для черновика можно оставить пустым |

Профили нужны местам типов `planet` и `moon`. Тип `other` валидатор примет только как сознательное ручное указание тела с поверхностью и покажет предупреждение. Станциям и платформам профиль не создавайте. Астероиды в текущем MVP валидатор отклоняет: для них позже понадобится отдельный контракт геометрии.

Статусы:

- `draft` — черновик, параметры и seed можно менять;
- `review` — вариант готов к проверке владельцем/ответственным админом;
- `frozen` — утверждённая местность; обязательны радиус, seed, все версии, ключ, `approved_by` и `approved_at`;
- `disabled` — профиль явно отключён. Только с этим статусом допустим `surface_class=no_surface`.

Пресеты: `earthlike_balanced`, `earthlike_archipelago`, `ocean_world`, `desert_dry`, `ice_world`, `volcanic_active`, `barren_moon`, `gas_giant_bands`.

Типы поверхности: `terrestrial`, `ocean`, `desert`, `ice`, `volcanic`, `barren`, `gas_giant`, `no_surface`. Для `gas_giant` используйте пресет `gas_giant_bands`; локальной поверхности у такого мира не будет.

### Пустые числа и процентили

**Пустая необязательная ячейка — норма.** Она означает «взять значение пресета». Не заполняйте все 19 географических чисел ради полноты строки и не пишите туда `none`.

Процентиль — это порог в процентах распределения. Например, `ocean_pctl=70` означает, что примерно нижние 70% поверхности по высоте окажутся ниже уровня моря, а `mountain_land_pctl=92` — что горами будет считаться верхние 8% суши по высоте. Все процентили — числа от 0 до 100 с точкой в дробной части.

Валидатор требует естественный порядок:

- `shelf_below_pctl <= ocean_pctl <= shelf_above_pctl`;
- `highland_land_pctl <= mountain_land_pctl`;
- `arid_land_pctl <= wet_land_pctl`;
- `cold_pctl <= hot_pctl`;
- `stream_flow_pctl <= major_river_flow_pctl`.

Поля `coast_soft_width_cells`, `continent_soft_width_cells` и `biome_soft_width_cells` — плавность переходов в ячейках глобуса; обычно их тоже оставляет пресет. В `notes_admin` не используйте переносы строк.

### Seed, версии и заморозка

`master_seed_hex`, версии генератора и `generation_key` вручную не придумывают и не правят. Их выдаёт инструмент `tools/planet_generation.py`:

1. Администратор создаёт `draft` и выбирает пресет/тип/радиус.
2. Разработчик или ответственный оператор формирует seed и смотрит предпросмотр, когда страница предпросмотра появится на следующих этапах.
3. После утверждения инструмент раскрывает пресет, фиксирует поддерживаемые версии и вычисляет ключ (`freeze-row` либо `key --format tsv`).
4. Администратор вставляет выданные служебные значения, заполняет `approved_by` и ISO-дату `approved_at`, затем ставит `profile_status=frozen`.
5. Обычная синхронизация пересчитывает ключ. Если после заморозки изменили радиус, seed, пресет, процентиль или версию, старый ключ станет недействительным и синк остановится.

Чтобы изменить замороженную планету: верните статус в `draft` или `review`, увеличьте `profile_revision`, измените параметры, снова проверьте результат и получите новый ключ. Нельзя менять географию и оставлять старый `generation_key`.

После Этапов 3–5 инструмент по умолчанию выдаёт боевые версии `grid_version=goldberg-gp-v1`, `noise_version=planet-noise-simplex3d-v1`, `geography_version=c100-soft-v2` и `preset_version=planet-presets-v1`. Версия v2 — это полный рецепт поверхности: поля и C100 `c100-soft-v1` внутри плюс гидрология и биомы Этапа 5. Явная `c100-soft-v1` валидатором ещё поддерживается как legacy только для полей/C100, но синонимом v2 не является: для рек, озёр и биомов такому профилю нужна новая ревизия с v2 и новым ключом. Явная историческая `goldberg-gp-v0` для сетки также остаётся legacy, а прототипные шум/география/пресеты v0 не принимаются. Пресеты v1 перекалиброваны под каноническую Землю v=128; например, у `earthlike_balanced` теперь `continent_mean_cells=400`, `ocean_basin_mean_cells=6000`, `drainage_mean_cells=72`. Вручную эти версии и ключ по-прежнему не заполняют. Этап 6 добавляет боевой стенд глобуса `/planet-globe/`, где пресеты, seed и радиус можно посмотреть визуально, но он пока не читает строки `planet_generation` и не является страницей планеты из карты. Поэтому массовую заморозку профилей не начинают до визуальной приёмки глобуса и подключения профилей на Этапе 7.

### Если синхронизация упала на профиле

Откройте лог **Actions → Sync upstream map data**. Валидатор пишет номер строки, `place_id`, поле и ожидаемый ключ, если проблема именно в нём. Исправьте Google-лист и запустите синк снова. Прежний снимок сайта при ошибке не заменяется: синк сначала проверяет все URL-листы в памяти и записывает файлы только после успешной проверки.

## Будущие листы архетипов и кастомизации

Для дальнейшей разработки в той же книге уже подготовлены вкладки `planet_archetypes` и `planet_customizations` по макету [`docs/stages/planet-sheet-layout.md`](stages/planet-sheet-layout.md) и шаблонам в `data/`. Это пока **не источники сайта**: синк их не читает, а правки в них ни на что не влияют. `planet_archetypes` — каталог архетипов без `place_id` (привязка к месту остаётся через `planet_generation.preset_id`), `planet_customizations` — будущие индивидуальные render-настройки по `place_id`. Они находятся под общей публикацией книги, но разработчик включит их в `data/sources.json` только после расширения валидатора, синка и runtime.

## Координаты

- Для самостоятельных мест вводите `x` первым, `y` вторым. `Shift+клик` по карте сектора открывает **карточку точки**: адрес `KP·REQHC`, `x` и `y` с одним знаком после запятой, ближайшая система и расстояние до неё, расстояние до ядра сектора, уровень глубины и номинальная видимая ширина кадра. Копирование — тремя кнопками: адрес; `x⇥y` (табуляция, вставка заполняет две соседние ячейки); вся строка `адрес ⇥ x ⇥ y`. `Esc` закрывает карточку и возвращает фокус на карту.
- Адресные буквы — латиница `A…Y`, разделитель `·`. При вводе допустимы `-` и пробел, регистр не важен, префикс сектора `KP` можно опустить: `KP·REQHC`, `KP-R-E-Q-H-C` и `REQHC` — один и тот же узел. Поиск каталога показывает такой запрос отдельной подсказкой «Адрес» и ведёт камеру к узлу; совпадения по именам остаются в списке ниже.
- Под процентом приближения в правом нижнем углу карты выводится расстояние от цели в центре кадра до ближайшей границы кадра. Это та самая метрика требования «1 св.г. до границы»: на пределе приближения строка читается как `1,00 св.г. до границы`.
- Ссылки на кадр карты: `?at=KP·REQHC` ставит камеру в центр узла, `&lw=39` задаёт ширину кадра по горизонтали в световых годах (дробная часть — через точку или запятую). Адрес понимает все три записи выше; без `lw` остаётся обычное приближение к точке.
- `?coords=1` — админ-режим: координаты наведения включены сразу, а `Shift+клик` работает по-старому и копирует `x⇥y` через табуляцию, без карточки точки. Нужен, когда координаты вставляют в таблицу десятками, а адресные буквы только мешают.
- `#system=<id>&frame=<S|O>` — обратная ссылка на систему с указанием кадра (`S` — секторный, `O` — системный). Параметр пока только читается и запоминается: системный кадр рисует волна `SW-5`, до неё вид карты не меняется.
- Предел приближения задаёт рендерер: `maxScaleForTargetEdge = min(w, h) / 2`. На упоре до ближайшей границы кадра ровно `1,00 св.г.` по короткой оси — именно это число и печатает readout под процентом зума.
> **Запланировано (волна `F-1`, гайдлайнер версии 4.0 от 26.10.2026).** Единица карты станет равной одному световому году напрямую (`1` ед = `1` св.г., без множителя `1 000`), а предел приближения будет задан свойством пикселя: `0,002` св.г. на CSS-пиксель, то есть `500` px/св.г. на любом экране. После этого строка под процентом зума на упоре покажет `1,08 св.г. до границы` на `1920×1080` (половина высоты кадра), и это останется **справочной** величиной: пределом будет `0,002` св.г./px. Правила заполнения `x`, `y`, режим `?coords=1` и копирование `x⇥y` не меняются.

- Минимальная достижимая ширина кадра — `2 · w / min(w, h)` световых лет: `3,56 св.г.` на 1920×1080 и `2,00 св.г.` на 390×844. Если в `&lw=` указать меньше, кадр упирается в кламп, и readout показывает фактическое расстояние до границы, а не заказанное. Ширина считается по горизонтали, поэтому на непрямоугольном экране высота кадра отличается от неё в `h / w` раз (`21,94 св.г.` против `39` на 1920×1080).
- Для записи `places` без `system_id` заполните обе координаты, чтобы создать отдельную точку интереса. Самостоятельная точка появляется только при отсутствии `system_id` и наличии обеих координат в пределах карты. Если `system_id` есть, `x`,`y` не создают отдельный POI; строгий синк считает заполненный `system_id` вместе хотя бы с одной ручной координатой конфликтом и перечисляет такую строку в ошибках.
- Координатная сетка интерфейса — `0…mapSize`; сейчас `mapSize` равен 10 000. Начало сетки находится в левом верхнем углу подложки: X растёт вправо, Y — вниз.
- Можно вводить целые или дробные числа; для дробей используйте точку (`123.45`), а не запятую. В Google Sheets задайте этим ячейкам числовой формат, не текст с единицами измерения.
- Для `systems` заполняйте оба поля `x`,`y` только для систем, положение которых явно нанесено на схему. При пустой или некорректной паре система остаётся в каталоге, но не получает маркер; код не подставляет предполагаемые координаты.
- Не переворачивайте Y и не масштабируйте координаты самостоятельно. Сейчас в `data/sources.json` `flipY` выключен, масштаб равен 1. Изменение преобразования источника — задача разработчика.
- Для явных координат систем и самостоятельных мест ожидаемый диапазон — `0 ≤ x,y ≤ mapSize`. Обычный запуск синка сохраняет прежний мягкий режим и не блокирует строки из-за нечисловых координат или выхода за границы; для предварительной строгой проверки запустите `python3 tools/sync.py --strict`. В строгом режиме непустые `x` и `y` должны быть числами в диапазоне `0…mapSize` из `data/sources.json` или `data/meta.json`; проверяются также таблицы `systems`, `places` и остальные URL-источники Google Sheets. Ошибки перечисляются вместе, снимки не заменяются.

## ID и связи

- Сохраняйте существующие ID; новые делайте непустыми и уникальными в пределах своего листа. В Google Sheets задавайте колонке ID формат «Обычный текст», если важны ведущие нули. Текущие данные используют короткие числовые ID, но менять их нельзя.
- Связь места с системой задаётся через `places.system_id`. Совпадение ID необходимо для группировки места в досье системы.
- Связь профиля планеты с местом задаётся через `planet_generation.place_id` → `places.ID`. Эту связь, дубли профилей и допустимый `places.type` синк проверяет обязательно.
- При обычном синке URL-источников прежняя проверка дублей распознаваемого ID сохраняется. Режим `--strict` дополнительно проверяет дубли непустых основных ID во всех синхронизируемых URL-таблицах и в локальном снимке отключённого источника (`systems.id/system_id`, `places.id/ID`, `planet_generation.place_id`); пустые ID не считаются дублями. Наличие всех обязательных колонок и ссылочную целостность `places.system_id` строгий режим не проверяет.

## Публикация и CSV

1. Книга уже опубликована: **Файл → Поделиться → Опубликовать в интернете** должен показывать «Весь документ» и включённую автопубликацию изменений.
2. Не отменяйте публикацию и не публикуйте отдельные вкладки заново без разработчика. Все CSV-адреса в `data/sources.json` используют один токен `2PACX-…` и различаются `gid`; при смене токена или `gid` разработчик должен обновить конфигурацию.
3. После правок дождитесь очередного запуска синхронизации (раз в 6 часов) или откройте **Actions → Sync upstream map data → Run workflow**.

Используйте экспорт Google Sheets в CSV, не собирайте CSV вручную. Запятые в текстовых ячейках допустимы: корректный CSV-экспорт заключает их в кавычки, а парсер сайта обрабатывает стандартное экранирование. Кодировка — UTF-8. Синк проверяет, что ответ непустой, не является HTML-страницей и похож на CSV; при отсутствии публикации Google обычно отдаёт HTML вместо CSV. Если синк обнаружит HTML, следуйте короткому чек-листу из ошибки:

1. В таблице откройте **Файл → Поделиться → Опубликовать в интернете**.
2. Выберите нужную вкладку и формат **CSV**, затем нажмите «Опубликовать».
3. Откройте URL источника в окне инкогнито: должна загружаться CSV-выгрузка, а не страница входа или запроса доступа.

Для дополнительной проверки координат и ID можно запустить `python3 tools/sync.py --strict`. Обычный запуск без этого флага остаётся в мягком режиме. Строгая проверка сообщает все найденные ошибки в `systems`, `places` и URL-источниках листов и завершает работу с ненулевым кодом до записи новых снимков; подробные правила координат, привязки и ID приведены выше.

Если запуск синхронизации завершается ошибкой, workflow не выполняет шаг коммита в Git, и опубликованный сайт остаётся на последних закоммиченных данных. Более того, URL-листы сначала проверяются все вместе в памяти и только после успеха атомарно заменяют снимки. Обычный мягкий запуск не проверяет все правила заполнения старых листов: типы, обязательные поля и ссылочную целостность проверяйте вручную; `--strict` дополнительно покрывает координаты, дубли ID и конфликт `places.system_id` с ручными координатами. Для `planet_generation` автоматическая проверка профилей полная по контракту валидатора.

## Чек-лист перед публикацией

- [ ] Редактируется Google-таблица, а не выгрузки `data/*.csv`.
- [ ] В каждой опубликованной вкладке первая строка — заголовки; рабочие имена колонок не переименованы.
- [ ] У систем есть стабильный ID и название; положение задаётся только при наличии подтверждённой привязки к карте.
- [ ] В `systems.type` указано `capital` или `unknow`, если нужна особая метка; для обычной системы ячейка оставлена пустой.
- [ ] У мест указаны стабильные уникальные ID и названия; для `type` выбран один из шести поддерживаемых вариантов.
- [ ] `places.system_id` точно совпадает с ID системы, если место должно быть с ней связано.
- [ ] Для каждого профиля планеты `planet_generation.place_id` точно совпадает с существующим `places.ID`; дублей профилей нет.
- [ ] Новый профиль начинается со статуса `draft`; seed, версии и `generation_key` не заполнялись вручную.
- [ ] Пустые процентили оставлены пресету; вручную изменённые процентили не нарушают порядок порогов.
- [ ] В дробных числах используется точка; описания и `notes_admin` не содержат переносов строк.
- [ ] Книга остаётся опубликованной целиком, а `gid` пересозданных вкладок сразу передан разработчику.
