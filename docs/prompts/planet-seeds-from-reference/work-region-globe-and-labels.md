# Пре-сиды: регион, глобус и подписи

> Назад: [шаг 0 консолидации](../../consolidation/README.md) · [документация](../../README.md)

Работа над пре-сидами планет: кадр и рендер региональной карты, глобус и ракурсы, подписи (§5–8).

### 5. Кадр региональной карты (только для R2)

Это самая частая точка провала. Правила:

1. **Нельзя** делать «регион» окном lon/lat на равнопромежуточной
   развёртке: при span 150–200° кадр выходит за полушарие, левый и правый
   края дублируются, у полюсов появляются веерные лучи.
2. Кадр — **азимутальная проекция** (равнопромежуточная по дуге от
   центра): `rho = sin(angle/2)/sin(maxDeg/2) * R`, отсечка `cosT ≤ 0`.
3. **Базис камеры** (здесь легко получить зеркало — проверено на своих
   граблях):

   ```js
   const center = [cos(lat0)*cos(lon0), sin(lat0), cos(lat0)*sin(lon0)];
   const upHint = Math.abs(center[1]) > 0.95 ? [1,0,0] : [0,1,0];
   const east  = normalize(cross(center, upHint));   // по возрастанию долготы
   const north = cross(east, center);                 // вверх по кадру
   ```

   Если поменять местами `cross(upHint, center)` — карта зеркалится, и
   «океан слева» оказывается справа. Проверяй одной точкой: суша с
   `lon > lon0` должна быть справа.

4. **Параметры кадра:** `maxDeg 68–78`, `fill 1.8–2.1` (2.0 — кадр
   заполнен целиком, без пустого диска), `rotDeg` — поворот кадра.
   `rotDeg = 0` держит север сверху: для планет с ледяной шапкой это
   лучший выбор, иначе автоподбор повернёт кадр и шапка уедет вбок.
5. **Автоподбор кадра** — не «на глаз». Перебирай центры-кандидаты
   (суша с глубокой водой рядом, прореживание по сетке 8°, окно широт
   под лор) и поворот, считая композиционный скор:

   ```text
   score = 2.4*waterLeft + 2.2*landRight + 1.1*landCenter
         + iceBonus
         - 1.1*|landFrac - 0.62|
         - 0.8*max(0, iceBottom - iceTop)
         - 0.8*max(0, 0.5 - landCenter)

   iceBonus = 0.8, если 0.05 <= iceTop <= 0.34,
              иначе -2.4*max(0, iceTop-0.40) - 3.0*max(0, 0.04-iceTop)
   ```

   где `waterLeft` — доля воды в левой 22 % кадра, `landRight` — доля
   суши в правых 66 %, `landCenter` — доля суши в центральном окне
   0.3–0.7 × 0.25–0.75, `iceTop/iceBottom` — доля льда в верхних 18 % и
   нижних 18 %.
6. Обязательно посмотри 4–6 верхних кадров глазами: скор не понимает
   «красиво». Отбраковывай кадры, где суша прилипла к краю или где
   ледяная шапка занимает полкадра.

### 6. Рендер региональной карты

Полная палитра — из R2 (см. шаг 2), но вот проверенная механика.
Все числа ниже — рабочие, их можно брать как стартовые.

**а) Цвет суши** — от биома, а не от пикселей референса:

```js
lite = 0.82 + 0.50*(clamp(shade, 0.4, 1.3) - 0.52);  // рельефная подсветка
if (biome === 2 || biome === 4)  → тундра→снег, порог широты 66°, рамп 9°
if (mountainWeightSmooth > 0.52) → high→mount→peak по весу (0.52…1.0)
if (biome ∈ {6,7,8,15})          → forest
if (biome === 5)                 → taiga
if (biome ∈ {9,10})              → plain
if (biome ∈ {11,12})             → steppe
if (biome === 13)                → highland
иначе                            → lowland
```

Два обязательных условия, иначе карта «плывёт»:

- **`mountainWeight` сглаживать** 3 итерациями по соседям перед покраской
  (иначе горы — шумная крупа по одной ячейке, а не цепи);
- **лёд рисовать только в приполярье и на высоких пиках**. Если красить
  `polar_ice`/`sea_ice` «как есть», внутренние холодные области заливаются
  белым и карта теряет климат. Порог: `|lat| ≥ 66` для шапки, плюс
  `lift > 0.72` для снежных вершин.

**б) Вода** — по расстоянию до суши, не по глубине. Глубина даёт кольца:

```js
const dist = distanceField(landMask);            // шамферная, не BFS-4
const t = clamp(dist / shelfPx, 0, 1);           // 0 у берега, 1 — открытая вода
const near = Math.pow(1 - t, 2.0);
const shallow = clamp(1 - depth/0.20, 0, 1);
color = mix(deepColor(depth), shelfColor(depth), near*(0.30 + 0.70*shallow));
```

- `distanceField` — двухпроходная шамферная (диагональ `√2`), **не** BFS
  по 4 соседям: BFS даёт ромбовидные «лучи» от берега.
- `shelfPx ≈ 0.035–0.05` ширины картинки.
- Глубину для цвета ограничивай: `abyss` только при `depth > 0.28`.

**в) Озёра и океан.** Компоненты воды: крупнейшая связная область —
океан, остальные — озёра. Озёра < 160 ячеек в региональном масштабе не
рисуй как воду (иначе карта в крапинку) — они остаются сушей. Озёра
красятся тем же водным градиентом с уменьшенным `shelfPx` (≈0.45 от
морского), без «глубоководной» каймы.

**г) Реки.** `streamWeight > 0.68`, `t = min(0.8, (sw-0.68)*3.2)`. Порог
0.58 даёт «паутину» — слишком густо для карты региона; 0.68 — читаемые
реки без мелкой сетки.

**д) Композит и сглаживание** (иначе видны гексагоны):

- рендерь в 2× разрешении (суперсэмплинг), затем усредняй;
- **маску суши сглаживай по покрытию**, а не по числу попаданий:
  накапливай `covSum` и `covLand` с весом `1 - r²/rpx²` по каждому сплату
  и бери `covLand/covSum`. Тогда берег получается органичным и не зависит
  от z-буфера;
- цветовое поле сглаживай отдельно по суше и по воде (не смешивай их до
  композита), радиус `max(2, round(width/300))`;
- z-буфер оставь только для выбора «кто ближе» в одной точке, а не для
  маски.

**е) Производительность.** Попытка «попиксельно искать ближайшую ячейку»
дала 168 s на 900×620 — так делать нельзя. Рабочая схема: сплат ячеек с
радиусом `rpx` в 2× буфер, композит, карта расстояний по маске. Бюджет:
`v=256` — 10 s генерации, карта 1500×960 — 8–9 s, глобус 760 px — 0.6 s;
весь вариант с автоподбором кадра — 20 s.

**ж) Палитра (рабочая, под тёмный океан + бирюзовый шельф).**
`deep [34,52,80]`, `abyss [24,38,60]`, `slope [40,78,106]`,
`shore [156,232,226]`, `shelfB [96,206,200]`, `shelfD [62,160,176]`,
`lowland [136,158,104]`, `plain [170,182,120]`, `steppe [196,190,136]`,
`forest [98,132,76]`, `taiga [82,110,74]`, `tundra [162,168,142]`,
`high [172,160,132]`, `mount [170,134,110]`, `peak [200,180,162]`,
`snow [244,247,250]`, `river [76,184,196]`.

### 7. Глобус и ракурсы

- Глобус: ортографический рендер с лимбовым затемнением, свет
  `normalize([-0.45, 0.55, 0.70])`, блик только по воде.
- Палитру суши бери с `shade = 0.52` (нейтрально) — не затемняй дважды:
  подсветка рельефа уже внутри цвета, сверху нужен только свет сферы.
- `lit = (0.44 + 0.70*lam) * (0.50 + 0.62*cosT^0.35)`; для воды
  `0.52 + 0.55*lam`, блик `14*lam^14`.
- Три ракурса — вращай **мир** (сдвиг `lon0` на +120°, +240°), а не
  камеру, иначе часть ракурсов уходит в тень.
- Леса/горы слегка пересыщай (`sat 1.10`): на мелком диске светло-зелёный
  вымывается лимбовым затемнением.

### 8. Подписи (labels)

Итальянский serif-курсив на референсе — это оформление карты, а не
«шрифт сайта». В контейнере обычно нет italic-файла — наклоняй
глифы аффинным сдвигом (`shear ≈ 0.22`), а не подменяй шрифт.

Правила, чтобы подписи не превратились в кашу:

- имя региона — 28–44 px, объект — 16–24 px, точка-маркер у точечных
  объектов (гора, озеро, улей);
- каждую подпись окружай светлым ореолом (`MaxFilter` + `GaussianBlur`,
  цвет фона с alpha ≈0.8) — иначе текст теряется на лесу и горах;
- у подписей ульев/точек задавай **разные смещения** по кругу: три
  подписи подряд садятся друг на друга и на горные цепи;
- `HELCENAR` — капитель с трекингом 5–6 px; имена — обычный трекинг 1–2;
- подпись не должна перекрывать берег: если центр объекта у края, сдвигай
  внутрь кадра;
- заголовок карты — мелким serif в левом нижнем углу, не по центру.
