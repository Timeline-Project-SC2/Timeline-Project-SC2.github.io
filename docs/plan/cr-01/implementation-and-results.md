### 9. Реестр подводных камней и инфраструктурных граблей

Ниже перечислены все технические ловушки текущего репозитория, обязательные к контролю:

1. **Жёсткие привязки в `tools/build_assets.py` и `.github/workflows/check.yml`:**
   - В `build_assets.py` словарь `VERSIONED_REFS` ищет `?v=` в 5 конкретных файлах (`site/index.html`, `site/sector/sector.html`, `site/minimal/minimal.html`, `site/shared/links.js`, `site/shared/timeline-loader.js`).
   - В `check.yml` цикл `for f in ... test -s ".publish/$f"` проверяет наличие конкретных имён файлов в `.publish/`.
   - *Защита:* В PR 1 синхронно обновить `check.yml` и `build_assets.py`.
2. **Запрет `SharedArrayBuffer` на GitHub Pages (отсутствие COOP/COEP):**
   - GitHub Pages не отдаёт заголовки `Cross-Origin-Opener-Policy` / `Cross-Origin-Embedder-Policy`.
   - *Защита:* Использовать однопоточный Wasm с **SIMD128** (`+simd128` работает везде без спецзаголовков) внутри Web Worker и передавать готовые буферы через `Transferable` (`postMessage(data, [buffer])`).
3. **Побайтовая совместимость бинарного кэша `GEO\0` в IndexedDB:**
   - Формат `gp-v1-bin:` (32-байтный заголовок `GEO\0`, `paramsHash` SHA-256, `CRC32C`) должен остаться побайтово совместимым, чтобы общая база `planet-spike-cache` в браузере работала без сбоев.
4. **Неприкосновенные UX-инварианты из `AGENTS.md`:**
   - Системный курсор 32×32 px (`cursor-fx`) меняет `style` **только** у элемента под мышью (не на `html`/`body`).
   - Выход при `event.button > 1` во всех обработчиках `pointerdown` всех карт; правая кнопка не тащит карту и не включает крестовину.
   - Карточка `#detailPanel.is-preview` при наведении пропускает мышь сквозь себя (`pointer-events: none`).
   - Порядок слоёв в `#mapLayer` на галактике: `#galaxyMap` → холст `GalaxySpiral` (без `z-index` и без CSS-трансформаций) → `.lag-fx` → квадраты областей.
   - Независимость переменных тайминга (`focusMs`, `focusZoomDelay`, `focusZoomMs`, `focusZoomOutMs`, `diveCenterMs`, `diveZoomDelay`, `diveZoomMs`).
5. **Скорость CI и автономность песочницы:**
   - Скомпилированный бинарник `planet_core_bg.wasm` (~45–60 КБ) хранится в репозитории рядом с исходниками крейта и проверяется на актуальность в CI. Благодаря этому сборка сайта (`pages.yml`) и запуск тестов в любой среде идут за секунды и не требуют перекомпиляции Rust при правках UI или данных.

#### 11.2. Ключевая техническая деталь: AssemblyScript вместо Rust

План раздела 5 изначально рассматривал ядро `planet-core` на **Rust → WebAssembly**. Фактическая реализация выбрала **AssemblyScript**, чтобы обеспечить 100 % автономность сборки внутри npm-тулчейна: в песочнице CI нет внешней зависимости от Rust/Cargo, а компиляция Wasm выполняется тем же `package-lock.json` и командами `npm run build:wasm` / `npm run check:planet-core` без системного тулчейна.

- Единое бинарное ядро `planet-core` — **SIMD128, однопоточный Wasm** (без `SharedArrayBuffer`, так как GitHub Pages не отдаёт COOP/COEP): исходники [`src/planet/assembly/kernels.ts`](../../../src/planet/assembly/kernels.ts), хост-обвязка [`src/planet/planet-core-host.ts`](../../../src/planet/planet-core-host.ts) и байтовый протокол [`src/planet/planet-core-bytes.ts`](../../../src/planet/planet-core-bytes.ts).
- На канонической Земле `v=128` (163 842 ячейки) достигнута медиана **`totalMedian ≈ 812–853 мс`** при пороге гейта **`<= 855 мс`** — ускорение **`> 3,0×`** против baseline **`2 564,7 мс`** (замер `bench_planet_stage5.mjs --seeds=5`: `3,01×–3,16×`).
- При этом зафиксировано **100 % побитовое совпадение (`FULL EQ`) всех 185 контрольных хэшей** (SHA-256 всех 45 массивов географии и поверхности + CRC32C сеток на `v=16, 24, 32, 64, 128`) между эталонным Python-каналом, Wasm-ядром и строгим TypeScript-рантаймом.
- Все инварианты **И-1 … И-6** соблюдаются и удерживаются регрессионными тестами (`npm test`, `npm run verify:contract`, `npm run verify:publish`); легаси-монолиты и `.js`-дубли планетарных модулей удалены по И-5.
