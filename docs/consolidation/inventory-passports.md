# Инвентарь: паспорта этапов по гибриду

> Назад: [шаг 0](README.md) · [вердикт и промпт](../consolidation-plan.md)

Правило части: у каждого этапа остаётся **один паспорт `plan.md`**, куда
секциями `## Ошибки`, `## Баги`, `## Решения`, `## TODO`, `## Журнал`
уходят нынешние регистры и журнал этапа. Оценка — суммарное тело файлов
без шапок плюс служебные заголовки; `plan-source.md` в оценку не входит:
это дословный исходник нынешнего паспорта, действие по нему везде одно —
**УДАЛИТЬ-ДУБЛЬ** после построчной сверки при P2. Если сборка этапа даст
больше 190 строк, крупнейшая секция выносится обратно в отдельный файл —
гибрид это прямо предусматривает.

## 2. Хабы-редиректы этапов в `docs/stages/*.md`

25 файлов по 18–41 строк (`stage-1-spike-report.md`, `stage-8-local-map.md`,
`planet-lod-cascade-2026-10-23.md` и др.) — не кандидаты в склейку:
у 23 из них есть упоминания из кода, `AGENTS.md` или корневых документов,
у остальных — входящие ссылки из `docs/`. Действие везде: **ОСТАВИТЬ-РЕДИРЕКТ**
и в очереди P0 проверить, что каждый хаб ведёт на существующий целевой
раздел, а не на удалённый при P1/P2 файл. Возвращать текст заметок обратно
по этим путям (предложение аудита) нельзя: получится дубль живого файла.
