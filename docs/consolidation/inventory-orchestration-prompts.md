# Инвентарь: оркестрация, промпты, защищённые пути и очередь P0

> Назад: [шаг 0](README.md) · [домены](inventory-domains.md)

Оркестрация — системные инструкции агентов: здесь критерий дробления
не «файл короче 60 строк», а самостоятельная цитируемость роли, волны
и карточки. Поэтому сокращений здесь почти нет, и это осознанный итог:
аудит предлагал склеивать волны, но каждая волна цитируется из `AGENTS.md`,
кода и карточек по номеру раздела отдельно.

## 4. Очередь P0 списком (гигиена без перемещений)

Исполняется одним PR до любых склеек; каждая строка — правка на месте:

1. Входящие ссылки сиротам: `players/README.md` — из `docs/README.md`;
   `stages/evidence/…/README.md` — из `stages/README.md`.
2. Двойные `H1`: `wave_cards/F-1.md`, `waves/protocol.md` — второй
   заголовок понизить до `H2` с сохранением текста.
3. Прыжки `H1 → H3` (51 файл): восстановить пропущенные `H2` по смыслу
   разделов, начиная с файлов, которые читаются на глубине 0–2.
4. Пустые таблицы в `notes/README.md` этапов 01-5, 11, 12: заполнить
   фактическими заметками либо убрать шапку таблицы до появления заметок.
5. Индексы `notes/README.md`: сортировка по логике чтения разделов
   (§0 → §1 → …), а не по латинице имён; вердикт сектора — первым.
6. `docs/README.md`: два пункта «6.» в §3, ссылка `[plan.md]` не на индекс,
   добавить `players/` и папку `consolidation/`.
7. Хабы: `CHANGE_REQUEST_PLAN.md` — добавить `plan/cr-01/journal.md`;
   `stage_patches.md` — вернуть 11 потерянных заметок этапов 1–2;
   `admins/README.md` — метраж 719 вместо 1130; `registers/README.md` —
   серия `F-*` в решениях; хаб оркестрации — `L0…L12` и имя гайдлайнера.
8. Баннер «ОТМЕНЕНО §17.24–25» на `waves/unit-ly.md`; пометка о фактической
   единице на всех местах, где `unit-revision.md` ещё не является первой
   ссылкой читателя.

Гейт P0: `check_docs.py` зелёный, сирот 0, двойных `H1` 0, прыжков меньше
базиса 51, ни один файл не перемещён и не удалён (`git diff --stat`
показывает только правки строк).
