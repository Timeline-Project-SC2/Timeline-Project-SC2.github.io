## A-19. Сборочный конвейер: зафиксировать назначение и ограничения

**Что проверять.** Зачем нужен `TimelinePublishPipeline`
(`tools/vite/timeline-publish-pipeline.ts:133`) и какие у него ограничения при
сборке и разбиении JS на чанки. Проверка — **по результату `.publish/`**, а не по
чтению кода конвейера.

**Что уже известно.** Поиск по репозиторию: класс упоминается только внутри
`tools/vite/timeline-publish-pipeline.ts` (`:133` — объявление, `:431` — фабрика
плагинов). Документированного описания назначения и инвариантов нет — конвейер
известен только тем, кто его правил. При приёмке A-12b проверено практикой:
он публикует каждый `site/**/*.ts` отдельным ассетом, переписывает статические
ссылки и динамические `import()` на hashed-имена, а для непубликуемых путей
возвращает ссылку без изменений.

**Что требуется на выходе.** Короткий раздел в документации с ответами:
1. Какие пути попадают в `.publish/` и по какому правилу.
2. Как вычисляются имена ассетов и от чего зависит хэш.
3. Какие ссылки переписываются (статические, `import()`, `new Worker`,
   `importScripts`) и что происходит с неразрешённой ссылкой.
4. Известные ограничения: ассеты-сироты (публикуется всё, что лежит в `site/`),
   порядок финализации, поведение при неудачном разрешении.
5. Как проверить требование по результату: какие команды и на что смотреть.

**Критерий приёмки.** Раздел существует, каждый пункт подтверждён фактом из
`.publish/`; переписывание конвейера не предлагается.

## A-20. Ошибка загрузки CSV не должна выглядеть как пустой каталог

**Что проверять.** `src/atlas/data-loader.ts` — путь ошибки при получении CSV.

**Что уже видно по коду.** `fetchCSV` (`data-loader.ts:102`) заканчивается
`.catch(function () { return []; })`, а `fetchJSON` (`:66`) — `.catch(() => fallback)`.
То есть сетевой сбой, 404 и битый ответ приводят к тому же результату, что и
честно пустая таблица: интерфейс показывает пустой каталог и молчит.

**Что требуется.** Различить три состояния — «данные есть», «данные пусты»,
«данные не получены» — и показать третье пользователю явно (сообщение в панели
каталога, а не только в консоли). Молчаливый `[]` остаётся допустим только там,
где пустота — законный сценарий (например, вторичный слой).

**Критерий приёмки.** Тест на подменённый `fetch` с ошибкой: пользователь видит
сообщение, отличное от пустого каталога; при живых данных поведение не меняется.

## A-21. Два парсера CSV: правило или общий модуль

**Что проверять.** `src/atlas/data-loader.ts:94` (`parseCSV`) и
`site/planet-globe/planet-globe.ts:2138` (`parseCsv`).

**Что уже видно по коду.** Парсеры ведут себя по-разному:

| Свойство | `data-loader.ts` | `planet-globe.ts` |
|---|---|---|
| Основа | сначала `split(/\r?\n/)`, потом разбор строки | посимвольный разбор всего текста |
| Перенос строки внутри кавычек | **ломается**: строка разрезается до разбора кавычек | **поддерживается** |
| Пустые строки | отбрасываются по `trim()` | отбрасываются по пустым полям |
| Завершающий перевод строки | не создаёт пустую строку | обрабатывается отдельной ветвью |

То есть запрета на многострочные поля нет ни в одном парсере — просто один из
них такие данные испортит молча.

**Что требуется.** Выбрать одно из двух и записать:
1. **Многострочные поля запрещены** — правило зафиксировано в документации и
   **проверяется**: парсер (или тест данных) падает/предупреждает на поле
   с переносом строки, а не режет его.
2. **Многострочные поля допустимы** — общий парсер в одном модуле, оба
   потребителя переходят на него, поведение закрыто тестами на кавычки,
   `""`-экранирование, перенос внутри кавычек, `\r\n`.

**Критерий приёмки.** Правило записано; тест ловит нарушение; расхождения
поведения между двумя страницами больше нет (либо оно объяснено и ограничено).

## A-23. Полный путь помощника перед «Лабораторией планет»

**Что проверять.** Сквозной сценарий помощника: создать настройки → сохранить
черновик → восстановить черновик → передать результат администратору.

**Зачем.** Существующие тесты закрывают детерминизм генерации и контракты
(ключи `PG1`, форматы, FULL EQ), но не покрывают передачу работы между людьми:
помощник создаёт, администратор утверждает. «Лаборатория планет» — Этап 11 —
встанет ровно на этот путь, и если стык «черновик → утверждение» не проверен,
редактор будет строиться на неподтверждённом основании.

**Что требуется.** Сценарий на существующем CLI и снимке таблицы, без нового
интерфейса:
1. создать настройки (seed, профиль, радиус) и получить черновую строку и ключ;
2. сохранить черновик и проверить, что он помечен как черновик и не выдаётся
   за канон;
3. восстановить черновик из снимка и получить те же значения (побайтово/по полям);
4. передать администратору: утверждение меняет статус, ключ переходит из
   `L0 Draft` в `L1 Frozen`, seed после утверждения не меняется без новой ревизии.

**Критерий приёмки.** Сценарий прогнан целиком, шаги и результаты записаны;
на каждый переход есть проверка, падающая при подмене значения. Новых экранов
не делается.
