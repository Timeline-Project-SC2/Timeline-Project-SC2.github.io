Обзор спайка, проверки и обратная связь владельца в одном контексте этапа 01.

## Обзор и итоги спайка

### Что сделано

| Артефакт | Назначение |
|---|---|
| `site/shared/geodesic-grid.js` | Сетка Голдберга GP(v,0) для произвольного целого v: ячейки, углы, соседи, площади, черновые адреса `goldberg-gp-v0/w0/v64/f07/a18/b31` (сегмент `w` — резерв номера тела в кластере, пока всегда 0), пикинг полным перебором, `validate()` |
| `site/shared/planet-noise.js` | Детерминированные поля: два кандидата шума (градиентный simplex и собственный value noise), fBm, касательный domain warp, сэмплер «высота/влажность/температура» по 3D-направлению |
| `site/planet-test/` | Изолированная тестовая страница: WebGL2-глобус (веер из центра ячейки, границы через атрибут веса центра, атмосфера), вращение/зум/pinch, выбор ячейки кликом, панель параметров, статистика и FPS |
| `tools/check_planet_spike.mjs` | Проверка без браузера: топология, детерминированность (golden values), статистика массивов суши и замеры |

Боевые страницы, данные и синхронизация не затронуты.

### Выводы спайка

1. **Собственная топология работает.** Произвольное v строится корректно и быстро; H3 как запасной путь пока не нужен.
2. **Градиентное семейство шума лучше value noise для географии.** У value noise на всех частотах один массив занимает 84–85% суши (почти суперконтинент на каждый seed), у simplex — около 17% и заметно больше отдельных массивов. Точный порт OpenSimplex2S остаётся кандидатом внутри градиентного семейства; заморозка алгоритма — при введении `noise_version`.
3. **Стартовая частота полей 2.2** при 5 октавах и warp 0.35 даёт приемлемую фрагментацию: на медианной планете ~111 физических массивов. Это не идентичности C100 (Этап 4), а проверка когерентности береговой линии.
4. **CPU-бюджет с запасом.** Медианная планета: сетка ~0,25 с один раз на v (кэшируется), поля ~50 мс. Главный остающийся вопрос — GPU/FPS на телефонах владельца.
5. **Пикинг полным перебором** достаточен для спайка; ускорение по граням икосаэдра — Этап 3.

### Что проверить владельцу (гейт G1, визуальная часть)

Открыть `/planet-test/` и оценить:

- [ ] Планеты выглядят как миры, а не шумовые пятна (несколько seed кнопкой ⟳).
- [ ] Плотность сетки v=64 читается как тактическая голограмма, а не «каша».
- [ ] Вращение и выбор ячейки удобны мышью и на телефоне.
- [ ] FPS на основном компьютере и телефоне (значение в левом нижнем углу).
      Частично закрыто 19.10: владелец подтвердил стабильные 50 FPS при v=64
      на i5-8400 + GTX 1050 Ti; остаются телефон и плотности 128/192.
- [ ] Сравнение `simplex` vs `value` на одном seed.

### Известные ограничения спайка

- Адреса ячеек — черновик v0: владелец рёберной вершины — первая грань в фиксированном порядке обхода. Канонизация фиксируется на Этапе 3 до появления публичных ссылок.
- Биомная раскраска — грубая функция высоты/влажности/температуры только для читаемости.
- Рек, водосборов и идентичностей C100 нет — это Этапы 4–5.
- Освещение и атмосфера — минимальные шейдеры без финальной стилизации под брифинг.
- При отсутствии WebGL2 страница показывает сообщение; fallback — отдельная задача Этапа 6.

#### Что построено

- `site/shared/geodesic-grid.js` — Goldberg GP(v,0) для произвольного целого v:
  ячейки, углы, соседи, сферические площади, черновые адреса
  `goldberg-gp-v0/w0/v64/f07/a18/b31` (w — резерв тела, см. п.13), пикинг полным перебором, `validate()`.
- `site/shared/planet-noise.js` — детерминированные поля по 3D-направлению:
  градиентный simplex и собственный value noise, fBm, касательный domain
  warp; сэмплер «высота/влажность/температура».
- `site/planet-test/` — изолированная страница спайка: WebGL2-глобус (веер из
  центра ячейки, граница по весу центра, атмосфера), вращение/зум/pinch,
  выбор ячейки кликом, панель параметров, статистика, FPS.
- `site/planet-test/planet-worker.js` — воркер генерации (см. ниже).
- `tools/check_planet_spike.mjs` — топология, детерминированность (golden
  values), статистика суши. `tools/bench_planet_density.mjs` — модель
  плотности.

#### Решения и установленные факты

- Собственная топология работает на произвольном v; запасной путь H3 не нужен.
- **Шум: simplex, не value.** Value на всех частотах слипается в суперконтинент
  (один массив = 84–85% суши); simplex даёт ~17% на крупнейший массив и ~111
  массивов на медианной планете. Стартовые параметры: freq 2.2, 5 октав,
  gain 0.5, warp 0.35, океан 70%.
- Поля сэмплируются по направлению и **не зависят от v**: одна и та же планета
  на любом разрешении сетки. От v зависят только адресация ячеек и семантика
  «континент из N ячеек».
- Пикинг полным перебором достаточен даже при v=192 (0,94 мс на клик);
  ускорение по граням понадобится только для hover-подсветки каждый кадр.
- Стартовая точка калибровки: Земля v=64 → 40 962 ячейки, средняя ячейка
  12 452 км², ребро ≈ 69 км. Под вопросом (см. модель ×8–9 ниже).

## Обратная связь владельца

#### Обратная связь владельца

- **50 FPS стабильно** при v=64 на i5-8400 + GTX 1050 Ti при множестве
  открытых вкладок.
- ×8 работает; претензия была к ожиданию перед анимацией (закрыто п.4,
  развилка по п.5 открыта).
- Ожидание по мобильным: плавность как на десктопе не гарантируется,
  вероятна поэтапная прогрузка чанками — совпадает с направлением п.5 и
  пропуском обратной полусферы по чанкам-граням.
- Стек для внешних ответов: ванильный JavaScript, WebGL2 + GLSL вручную
  (без Three.js), Canvas для 2D, Python только в служебных скриптах;
  хостинг GitHub Pages, бэкенда нет.
- Тест осколков, первая версия: «выглядит несуразно» + скриншот превью и
  референс уничтожения Шакураса из игры (светящееся ядро и широкое поле
  обломков на несколько радиусов) — доработано в п.15; попутно отмечена
  долгая генерация-загрузка (разобрано в п.15: не осколки).
- Объём осколков: запрошена кнопка «взрыв» (разлёт+рваность вверх, толщина
  вниз); отмечено, что потери визуально идут «только снизу, от центра ядра»,
  а ядро слишком большое — с эталонной таблицей долей радиуса ядра
  (Меркурий 0.8–0.85, Венера ~0.5, Земля ~0.55, Марс ~0.5–0.54). Закрыто в
  п.17: ядро уменьшено до земных 0.55 с ползунком, причина «снизу» — то же
  ядро.
- Скриншот взорванной планеты уже с Pages (PR #115): геометрия низа
  осколков «слегка странноватая» — на кадре видны зонты-веера к одному
  апексу и залитые эмиссией оранжевые диски мелких осколков. Закрыто в
  п.21 закрытой нижней оболочкой постоянной толщины.
- Два скриншота из превью после п.21: «ну почти получилось» — во время
  каскадной сборки ещё не севшая нижняя оболочка висит вокруг планеты
  огромной бледной «призрачной сферой». Закрыто в п.22 (низ проявляется
  только по севшим ячейкам).
- Уточнение по двухслойной подмене прокси: сборка финала должна идти из
  центра планеты и «подменять собой»; отдельно попрошено проверить, нет
  ли фактически двух сфер, с правом самому решить, стоит ли вмешиваться
  ради оптимизации. Закрыто в п.23: рост из центра сделан; постоянной
  второй сферы нет, временный перехлёст на 1.5 с оставлен осознанно,
  внутренний объём при собранной планете больше не рисуется.
