# Боевой глобус: модули, воркер и CPU-гейт

>
> Источник: [`docs/stages/stage-6-webgl-globe.md`](../../stage-6-webgl-globe.md) · строки 1–135.
> Назад: [паспорт этапа](../plan.md) · [индекс документации](../../../README.md).

Дата: 21 октября 2026 года.

## Результат

Впервые полная боевая цепочка планеты видна на одном экране:

```text
goldberg-gp-v1
  → planet-noise-simplex3d-v1
  → c100-soft-v1 (поля, плиты, C100, бассейны)
  → planet-hydrology-v1 (сток, реки, озёра, дренажные регионы)
  → planet-biomes-v1 (16 мягких биомов)
  → planet-globe-v1 (WebGL2-глобус)
```

Новая страница `/planet-globe/` — это боевой рендер и стенд приёмки
поверхности, а не спайковые поля страницы `/planet-test/`. Она показывает
настоящие биомы, реки, озёра, континенты и drainage regions из
`c100-soft-v2`.

## Что добавлено

### `site/shared/planet-globe.js`

Изолированный модуль `planet-globe-v1` с двумя слоями:

- чистые строители для Node/worker:
  - `buildGlobeGeometry(grid, surface, options)`;
  - `buildCellColors` / `buildVertexColors`;
  - `cellPolygon` для контура выбранной ячейки;
  - `buildEquirectPreview` для fallback без WebGL2;
  - восемь слоёв: биомы, реки и озёра, высота, влажность, температура,
    континенты C100, дренажные регионы, горы и швы;
- браузерный `createPlanetGlobe(canvas, options)`:
  - индексированная fan-геометрия ячеек одним VAO;
  - chunk-диапазоны и отсечение обратной стороны по bounding spheres;
  - границы гексов через edge-фактор веера в A-канале цвета;
  - мягкий терминатор и rim-подсветка;
  - собственная low-poly UV-сфера атмосферы, не зависящая от `v`
    поверхности;
  - вращение с инерцией, колесо, touch-drag и pinch;
  - hover/select только направлением луча: точный pick остаётся на CPU;
  - выделение ячейки заливкой и контуром;
  - порционная заливка GPU-бандла по частям, пока старый глобус
    продолжает рисоваться;
  - адаптивный внутренний масштаб рендера по p95 кадра;
  - восстановление после потери WebGL-контекста;
  - HUD-статистика p50/p95/p99 и счётчики кадров >50/>100 мс.

Рельеф — радиальное смещение центров и общих углов: угол получает
среднее смещение трёх инцидентных ячеек, поэтому соседние гексы не
разъезжаются трещинами. GPU-шум в географии не участвует.

### `site/planet-globe/planet-globe-worker.js`

Worker на главном потоке ничего тяжёлого не оставляет:

- строит или читает из общего IndexedDB бинарную сетку
  `goldberg-gp-v1`;
- асинхронно генерирует `PlanetSurface`;
- строит transferable GPU-геометрию;
- хранит полную поверхность у себя и отвечает на pick и смену слоя
  без перегенерации;
- при ручной смене планеты страница перезапускает worker, поэтому
  устаревшая генерация не может догнать и перезаписать новую планету.

Нормы профиля заданы для канонической частоты. Для render-LOD worker
масштабирует `continent_mean_cells`, `ocean_basin_mean_cells` и
`drainage_mean_cells` пропорционально квадрату отношения частот, а
soft-width — линейно. Поэтому прокси сохраняет физический масштаб
континентов и рек, а не просто рисует ту же норму «в крупных клетках».

### `site/planet-globe/`

Страница боевого глобуса:

- семь поверхностных пресетов из
  `data/planet-archetypes-template.csv` (`gas_giant_bands` сознательно
  исключён: у газового гиганта нет твёрдой поверхности этого этапа);
- seed текстом или ровно 16 hex-цифрами, радиус, класс поверхности;
- авто-LOD: на десктопе сначала прокси, затем 100% канонической
  частоты; на coarse/small-screen авто-финал ограничен 50% (Земля
  v=64 после прокси v=24), вручную доступны 100/75/50% и только прокси;
- восемь карт-слоёв без перегенерации географии;
- клик/касание по глобусу: канонический адрес, координаты, площадь,
  биом top-2, климат, мягкий берег, континент/бассейн, сток,
  дренажный регион, озеро и горы;
- сводка планеты и журнал завершённых смен в сессии;
- кнопка следующей планеты и автосмена каждые ~5 секунд после финала
  как ручной браузерный стресс-тест;
- URL-параметры выбранной планеты для воспроизводимой ссылки;
- 2D equirectangular fallback, если WebGL2 недоступен.

Страница пока не читает `planet_generation.csv` и не связана с
галактикой/сектором/системой. Это граница Этапа 7, а не скрытый долг
рендера.

## CPU-гейт Этапа 6

`tools/bench_planet_stage6.mjs` добавлен в `Planet CPU performance`.
Последовательный локальный gate на канонической Земле `v=128`, три seed:

| Метрика | Результат | Порог bench |
|---|---:|---:|
| Ячеек | 163 842 | точная формула GP(v,0) |
| Треугольников ячеек | 983 040 | точная сумма сторон |
| Chunk-диапазонов | 200 | полное покрытие индексов |
| Mesh один раз | 567,4 мс | информативно |
| Геометрия, median | 129,2 мс | ≤ 2 500 мс |
| Поверхность + геометрия, median | 2 083,9 мс | ≤ 6 000 мс |
| Худший median цветового слоя | 74,6 мс | ≤ 1 000 мс |
| Pick p95 по seed, максимум | 0,0836 мс | ≤ 2 мс |
| GPU payload геометрии | 28,75 МиБ (исторический формат вершины 16 Б, до CR-01) | информативно; после CR-01 вершина 24 Б с нормалями и payload 37,50 МиБ — см. `planet-core-audit-2026-10-23.md` §8.3 |
| Typed grid + surface + geometry | 77,36 МиБ | ≤ 96 МиБ |

Все проверки gate — `true`. Worker дополнительно удерживает
`vertexCellId`, поэтому его retained geometry для быстрой перекраски
слоёв составляет 33,75 МиБ вместо одних только GPU-массивов.

Отдельный последовательный стресс `--mode=switches --switches=14
--v=48` прошёл два полных круга по семи пресетам:

- поверхность: median 443,0 мс;
- геометрия: median 32,9 мс;
- полная смена: median 478,7 мс, max 571,2 мс;
- все поверхности валидны;
- RSS Node колебался в коридоре 114,9–131,4 МиБ и не рос монотонно.

RSS Node не доказывает отсутствие утечек GPU-ресурсов браузера. Для
этого на странице есть автосмена планет и счётчик завершённых финалов:
браузерный прогон должен подтвердить стабильность heap/FPS на реальном
устройстве.
