# Stage-8.12d: волна «стенд вместо карточек» (24.10.2026)

## Зачем эта волна

Пять волн подряд закрывались по схеме «снимок владельца → находка → карточка →
починка». Схема даёт зелёные тесты при видимом браке: проверка мерила то, что
назвал дефект, а не то, что видит глаз. A-17b и A-29 — два случая подряд.

Меняем правило: **источник задач — измерительная таблица, а не кадр**. Снимки
владельца остаются только финальной приёмкой.

Вторая проблема — параллельная работа. Два дефекта (`A-30` реки и `A-31` фактура
гекса) живут в одной функции `local-map-worker.ts` (2 283 строки). Пока файл
один, два воркера не могут работать независимо: конфликт не разрешается мёрджем,
победитель переписывает работу проигравшего.

Поэтому волна начинается с **распила шва**, а не с починки.

## База

Все ветки волны растут от **`a678096`** — вершины PR #227 (8.12b + A-29).
Причина: без единой семантики воды и батиметрии воротника чинить реки и фактуру
гекса не на чем. `main` (`c950179`) для этой волны базой не является.

## Шов распила

~~~~text
сейчас:  один цикл на 2 283 строки — рельеф, врез русла, воротник, юбка

после:   buildBaseRelief()          → local-map-heightfield.ts
         carveRivers(field, segments) → local-map-rivers.ts   (второй проход)
         blendCollar(…)             → остаётся в worker.ts
~~~~

Шов выбран не по вкусу: врез русла **и так должен стать вторым проходом**.
Сегодня он вычитается внутри цикла на сетке 19,53 м (`2 · 2500 / 256`) — отсюда
лестница на кромке русла. Вынесенный проход можно растеризовать на подтексельной
точности и сгладить кромку. Распил — предусловие починки, а не рефакторинг
ради красоты.

Врез не зависит от высоты: `carve = riverCarveFactor(wx, wy, segments, halfWidth)`
считается только от координат и отрезков, поэтому перенос обязан быть побитовым.

### W18 — стенд: ПРИНЯТ

Коммит `44f3335`, база `a678096`, два файла — ровно по карточке.

Воспроизведено мной в worktree на `a678096`: таблица совпала строка в строку
(FAIL 8 / PASS 15 / N/A 19), `--gate` → exit 1, `node --test tests/local-map-stand.test.mjs`
→ 11/11. Прогон 2,4 с.

**Стенд увидел ровно то, что владелец видел глазами** — впервые за серию:

| Ячейка | Метрика | Значение | Порог |
|---|---|---:|---|
| 137436 | глубина воды в центре русла | **0 м** | ≥ 3 м |
| 137436 | непрерывность русла через грань | **0/16** | 16/16 |
| 137436 | ступень кромки русла | **3,33 м** | ≤ 2 м |
| 137436 | перепад вершин на суше | **7,68 м** | ≤ 6 м |
| 137390 | фактура рельефа (RMS колец) | **5,27×** | 0,70…1,30 |
| 137390 | перепад `waterDepthM` патч/юбка | **10,33 м** | ≤ 0,5 м |
| 137363 | фактура рельефа | **3,26×** | 0,70…1,30 |

Русло 137436 не прорублено: `streamWeight = 0`, канонический outlet есть,
вреза нет. Это ровно кадр владельца, где голубая полоса обрывается на грани.

**Новая находка, которой не было ни в одной карточке:** на 137390 остаточный
уступ батиметрии в воротнике — **10,33 м** (на азимутах 10/12/14 воротник
мельче патча на 6…9,6 м). Это дефект класса A-29, который A-29 не закрыл:
профиль мерился на четырёх ячейках, а дефект живёт на других.

**Замечание по `package.json`:** новый тест не включён в `npm test` — список
файлов в скрипте. Добавляет W21 при интеграции.

### W19 — распил: ОТКЛОНЁН (неверная база)

Коммит `6e07384` в ветке `arena/84532a3d…`. Проверено:

| Проверка | Результат |
|---|---|
| `git merge-base --is-ancestor a678096 origin/w19` | **НЕТ** |
| База ветки | `c950179` (`main`) |
| `grep -c "A-29"` в `local-map-worker.ts` ветки | **0** |

Воркер сам заметил симптомы и не понял их: «`a678096` не существует»,
«`npm test` 133, а не 137», «таблиц A-17/A-29 нет». Всё сходится: он работал
на `main` без PR #227. 133 теста — это `main`, 137 — `a678096`.

Следствие: распил сделан поверх кода **без** 8.12b и A-29. Перенос побитово
верен для старого дерева, но это не то дерево, которое мы принимаем.

**Что не выбрасывается:** оракул (SHA-256 по всем буферам ответа, 184 строки,
эталон `1cc4043a…`) — хорошая находка, лучше моей заготовки. Его надо перенести
на правильную базу. И находка про двойное округление `Float64 → Float32` верна.
