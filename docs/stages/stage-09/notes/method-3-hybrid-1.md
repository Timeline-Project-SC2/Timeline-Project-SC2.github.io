### 2.3. Метод 3 — гибрид: морфологические архетипы + климатический колорит + height-modulated blending

#### 2.3.1. Состав каналов одного тайла растительности

Предлагается **две карты на архетип** (а не «одна RGBA на всё»):

**Карта A — `albedo` (RGB, sRGB, `SRGB8_ALPHA8`).** Нейтрально-нормализованное
альбедо («delit», без направленного света):

- средняя яркость `L*≈62…68`, разброс по кадру `±10 %` — чтобы климатический
  тинт не «выжигал» полутона;
- нейтральный цветовой баланс (`R≈G≈B` в среднем, допустимый сдвиг не более
  `±0,03`), кроме специального архетипа `T7 (Xeno)`, где гамма задана каноном;
- отсутствие крупномасштабного градиента (проверка: после `GaussianBlur(r=64)`
  разброс яркости `< 8 %`) — иначе тайл «прибит» к одной стороне света и при
  повторе даёт полосы.

**Карта B — `masks` (RGBA, линейное пространство, `RGBA8`):**

| Канал | Поле | Кодирование | Зачем |
|---|---|---|---|
| `R` | `Height` | `h = sqrt(hNorm)` (гамма-компрессия поднимает детализацию в нижней части) | `heightBlend()` без двоения на стыках биомов; bump/normal из `dFdx/dFdy` |
| `G` | `FoliageMask` | `0…255` = доля биомассы в пикселе | раздельное окрашивание растительности и просвечивающего грунта планеты |
| `B` | `Roughness` (+ контактный AO в старших битах не нужен: AO считается из `Height`) | `rough = 255·(0.62 + 0.38·(1−m))` | разница «восковой лист / сухая трава / влажный ил» на блике |
| `A` | `OpticalDepth` (толщина/плотность кроны) | `255·clamp(0.4·m + 0.6·h)` | самозатенение полога и затухание подмешивания грунта |

Почему **не** «всё в одной RGBA»: альбедо требует sRGB-декодирования и
`3 канала`, а `Height/FoliageMask` — линейного и точного `8 бит` без гаммы.
Смешивание sRGB-альбедо и линейных масок в одной текстуре вынуждает либо
терять точность масок на гамма-кривой, либо держать альбедо в линейном
пространстве (хуже сжимается WebP и «сереет»). Две карты = две разные
цветовые политики, каждая без компромисса.

Почему **`Height` обязателен**: без него смешивание двух биомов — это
кросс-фейд (§2.2.3). С ним граница проходит по **гребню более высокого
покрова**, и крона одного биома физически «перекрывает» другой, как в природе.
Ключевое требование: `Height` всех архетипов нормируется к **общей мировой
шкале**, а не «0…1 на свой вкус»:

```text
Height_world_m = h_norm · heightAmplitudeM[архетип]
heightAmplitudeM:  T1a 0.45 | T1b 0.35 | T2 1.8 | T3 0.5
                   T4 0.8  | T5 22   | T6 35  | T7 12
```

Только при общей шкале `tundra (0,5 м)` никогда не «победит» `rainforest (35 м)`
в неправильном месте, а на стыке тайги и луга граница пойдёт по опушке.

#### 2.3.2. Математика смешивания двух биомов и подстилающего грунта

Обозначения: `w1, w2` — нормированные веса top-2 (`w1 + w2 = 1`), `m_k` —
`FoliageMask` архетипа `k`, `h_k` — нормированная высота `k`,
`cov_k` — скалярное покрытие от климата (`FoliageCoverage`, §3), `A_k` — альбедо.

**Шаг 1. Height-biased weight (замена линейного `mix`):**

```text
Δw = (w2 − w1)                       // ∈ [−1, 1]
Δh = (h1 − h2) · heightAmplitudeM[1] / max(heightAmplitudeM[1], heightAmplitudeM[2])
s  = clamp(Δw · C + Δh · S · (1 − |Δw|^γ), −1, 1)
a2 = smoothstep(−β, +β, s)           // доля второго биома
a1 = 1 − a2
```

где `C` — контраст границы (`1,4…2,2`), `S` — «сила высоты» (`0,6…1,0`),
`γ` — подавление высоты вдали от границы (`2…3`), `β` — полуширина мягкой
зоны (`0,06…0,18`; увеличивается с дистанцией, имитируя мип-переход).

Свойства:
- при `w1 = 1`: `Δw = −1` → `(1 − |Δw|^γ) = 0` → высота не влияет, `s ≤ −1`,
  `a2 = 0`. Биом не «протекает» в чужую зону;
- при `w1 = w2 = 0,5`: `Δw = 0`, решение принимает **рельеф покрова**
  (`Δh`), то есть граница идёт по гребням/опушкам, а не по середине;
- `a2` — непрерывная функция: нет разрывов, нет «двойной экспозиции».

**Шаг 2. Покрытие и вытеснение грунта:**

```text
α_k = smoothstep(0, 1, m_k · cov_k)          // 0 = только грунт, 1 = плотный покров
```

**Шаг 3. Композиция по приоритету высоты** (порядок сортируется по
`h_k · cov_k` по убыванию; в шейдере — два сравнения, без сортировки):

```text
acc = groundAlbedo(zone, moisture, slope)                 // подстилающая порода планеты
acc = mix(acc, tint(A_1) · shade(h_1), α_1)               // ниже
acc = mix(acc, tint(A_2) · shade(h_2), α_2 · (1 − α_1·shadow)) // выше
```

где `shadow = 0.35…0.6` — самозатенение от верхнего яруса (`OpticalDepth`),
`shade(h)` — микроосвещение от `Height` (bump + AO).

**Шаг 4. Климатический колорит (`tint`)** применяется **только к биомассе**,
не к грунту:

```text
tint(A) = A · (1 + saturShift) · hueRot(dHue) · valueShift
dHue      = f(moisture, temperatureBase, volcanism, biomeEntropy)
saturShift= 0.25·(wetScore − 0.5) − 0.2·volcPow + 0.1·(1 − iceScore)
valueShift= 1 + 0.12·(wetScore − 0.5) − 0.15·volcPow − 0.10·slopeScore
```

Грунт получает свой колорит от `biomeTop*` соседних «безрастительных» биомов
(11/12/13/14) и от `terraformBlend` — так зелёный никогда не «протекает» в
каменную крошку тундры.

**Шаг 5. Техногенное вытаптывание** — прямо по существующей карте
`t_terraform` (`R8`, `TERRAFORM_RES = 256`, `GL_LINEAR`):

```text
trample = smoothstep(0.15, 0.85, terraform)
cov_k  *= (1 − 0.9·trample)
groundTint = mix(groundTint, DIRT, 0.7·trample)
```

Это бесплатно: `u_terraform_map` уже сэмплируется в `TERRAIN_FRAGMENT_SHADER`.

#### 2.3.3. Подавление периодического тайлинга

Два независимых механизма, оба обязательны.

**(а) Stochastic Hex-Tiling** (Heitz & Deliot, JCGT) — 3 тапа с поворотом и
сдвигом по гексагональной решётке, веса по барицентрическим координатам
треугольника:

```glsl
// uv01 — тайловые координаты (повторяются), N — число шестиугольников
vec2  p  = uv01 * float(N);
vec2  hp = vec2(p.x * 0.5, p.y * 0.8660254);   // hex-центры
ivec2 id = ivec2(floor(hp));
vec4  rnd = hash4(id);                          // 4 случайных числа на ячейку
vec2  off = rnd.xy * 2.0 - 1.0;                 // сдвиг
float ang = rnd.z * 6.2831853;                  // поворот
// 3 тапа по вершинам треугольника, покрывающего точку, + smoothstep-веса
```

Стоимость: `3 fetch` вместо `1` на карту. Для двух биомов и двух карт —
`12` текстурных выборок на террейн-фрагмент (плюс `1` на грунт). Мобильный
профиль: `2` тапа (dual-scale без hex) + отключение второго биома при
`biomeEntropy < 0.15`.

**(б) Dual-Scale Macro-Micro Sampling.** Крупномасштабная модуляция в мировых
координатах (не в UV) — 2 октавы value-noise `8…64 км`:

```text
macro    = noise2(worldXY / 24000.0)            // 0…1
macroTint= 0.86 + 0.28·macro                     // ±14 % яркости
macroCov = 0.80 + 0.40·macro                     // ±20 % сомкнутости
uvWarp   = (noise2(worldXY / 6000.0) − 0.5) · 0.06  // в единицах тайла
```

`uvWarp` смещает `uv01` на `±6 %` тайла — этого достаточно, чтобы соседние
повторы перестали совпадать по фазе, но шов не появляется, потому что шум
непрерывен. Дополнительно `macroCov` ломает «идеальную сетку» повторов,
превращая её в пятна сомкнутости, как на реальном ландшафте.

#### 2.3.4. UV-лестница на диапазоне `1250 → 1,2 км`

Требования, которые надо удовлетворить одновременно:

1. **частота повторов** `N = W / L` (где `L` — период тайла в метрах) должна
   оставаться в окне `≈ 2…50`: меньше `2` — видна одна «простыня» и её швы
   на краях участка; больше `50` — появляется регулярный «муар» повторов;
2. **texel-per-pixel** `tpp = px_size / (L/1024)` должен быть `0,7…6`: меньше
   `0,7` — текстура мылится вплотную (не хватает разрешения), больше `6` —
   работает мип, детализация теряется впустую;
3. деталь не должна «прыгать» при переключении ступени лестницы.

Оба условия выполняются при одном периоде только внутри узкого окна, поэтому
вводится **четыре уровня периода** (все — один и тот же тайл `1024²`):

| Уровень | Период `L` | Применим на `W` | `N = W/L` | `tpp` (px 1200) | mip |
|---|---:|---|---:|---:|---:|
| `M0` | `25 км` | `1250 … 156 км` | `50 … 6,2` | `42,7 … 5,3` | `5,4 … 2,4` |
| `M1` | `6,25 км` | `312 … 39 км` (*) | `50 … 6,2` | `42,6 … 5,3` | `5,4 … 2,4` |
| `M2` | `1,25 км` | `78 … 5 км` | `62 … 4` | `53,3 … 3,4` | `5,7 … 1,8` |
| `M3` | `312 м` | `20 … 1,2 км` | `64 … 3,8` | `54,7 … 3,3` | `5,8 … 1,7` |

`(*)` на `1250 км` уровень `M1` уже не нужен: `mip 7,4` (текстура схлопывается
в среднее). Поэтому рабочие окна выбираются так, чтобы `tpp` оставался
`≤ 6`: `M0` для `1250–156`, `M1` для `156–39`, `M2` для `39–5`, `M3` для
`10–1,2`; на стыках (`156`, `39`, `10`) — кросс-фейд по одному шагу лестницы
(`w = clamp((W − W_switch)/W_switch, 0, 1)`), чтобы не было «прыжка
масштаба».

Физическая интерпретация на ближних ступенях: при `W = 1,2 км` и `L = 312 м`
один texel = `30,5 см`, один пиксель экрана (`1 м`) ≈ `3,3 texel`. Это ровно
то разрешение, на котором читаются кочки осоки и подушки ягеля. При
`W = 1250 км` текстура работает как крупномасштабная мозаика массивов
(`mip 5`: усреднение `32 × 32` texel ≈ `780 м`) — что физически корректно для
обзора, где `1 px ≈ 1 км`.
