# Модель данных и иерархия каталога

> Рабочие инструкции по редактированию Google Sheets собраны в [`ADMIN_GUIDE.md`](../ADMIN_GUIDE.md). Здесь оставлены краткая модель данных и актуальные правила, важные для кода.

## Источники и синхронизация

В `data/sources.json` заданы два опубликованных листа Google Sheets: `systems` и `places`. `tools/sync.py` скачивает каждый как CSV и обновляет соответствующий снимок в `data/`, манифест источников и `data/meta.json`. CSV-файлы в репозитории — результаты синхронизации; вручную их не редактируют.

Текущие заголовки синхронизированных снимков:

- `systems.csv`: `name,system_id,type,x,y,faction,description,source_url`
- `places.csv`: `name,ID,type,system_id,x,y,faction,description,source_url`

Шаблоны новых таблиц находятся в `data/systems-template.csv` и `data/places-template.csv`. Для системных шаблонов не нужны `x`,`y`: эти старые колонки опубликованной таблицы не задают положение на карте. Подробные требования к заголовкам, типам и публикации — в [`ADMIN_GUIDE.md`](../ADMIN_GUIDE.md).

## Сущности

### System (звёздная система)

| Поле | Тип | Описание |
|---|---|---|
| `id` / `system_id` | string (PK) | Стабильный уникальный ID системы. `systems.csv` сейчас использует заголовок `system_id`. |
| `name` | string | Отображаемое название. |
| `type` | enum | `none`, `capital` или `unknow`; `capital` — отдельная характеристика «Столица», а не тип места. |
| `x`, `y` | number | Устаревшие поля таблицы. Не задают положение узла и не используются для системных маркеров. |
| `faction` | string | Фракция, если указана. |
| `description` | string | Описание, если указано. |
| `source_url` | string | Ссылка на источник, если указана. |

Система отображается на карте только при наличии явной корректной привязки в `data/system-overrides.json`. Без неё система остаётся в каталоге.

### Place (место)

| Поле | Тип | Описание |
|---|---|---|
| `id` / `ID` | string (PK) | Стабильный уникальный ID; текущий лист использует `ID`. |
| `name` | string | Название места. |
| `type` | enum | `planet`, `moon`, `asteroid`, `station`, `platform` или `other`; пустой/отсутствующий тип трактуется как `planet`. |
| `system_id` | string (FK → System, nullable) | Связь места с системой. |
| `x`, `y` | number (nullable) | Координаты места на схеме. Для самостоятельной точки обе координаты обязательны; при указанном `system_id` отдельный маркер POI не создаётся. |
| `faction`, `description`, `source_url` | string | Дополнительные сведения, если указаны. |

Места со связанной системой показываются в её карточке. Самостоятельные точки интереса появляются только если `system_id` отсутствует и для места заданы допустимые координаты; пример — станция в открытом космосе. Без координат место остаётся доступно в каталоге.

## Разделы каталога

- `SYS` — системы.
- `PLN` — планеты.
- `STN` — станции.
- `PLT` — платформы.
- `ETC` — луны, астероиды и другие места.

Каталог поддерживает отсутствие `type` в старых или неполных данных: такие места рассматриваются как планеты. Текущие снимки CSV уже содержат колонку `type` в обоих листах.
