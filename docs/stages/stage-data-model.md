# Модель данных и иерархия каталога

> Рабочие инструкции по редактированию Google Sheets собраны в [`ADMIN_GUIDE.md`](../ADMIN_GUIDE.md). Здесь оставлены краткая модель данных и актуальные правила, важные для кода.

## Источники и синхронизация

В `data/sources.json` включены три листа одной опубликованной целиком книги Google Sheets: `systems`, `places` и `planet_generation` (`gid=1183479406`); каждый CSV-URL выбирает вкладку своим `gid`. Источник `planet_generation` хранит профили процедурных планет. `tools/sync.py` сначала скачивает и проверяет все URL-листы в памяти, включая перекрёстную проверку профилей против `places`, и только потом атомарно обновляет снимки в `data/`, манифест источников и `data/meta.json`. CSV-файлы в репозитории — результаты синхронизации; вручную их не редактируют.

Текущие заголовки синхронизированных снимков:

- `systems.csv`: `name,system_id,type,x,y,faction,description,source_url`
- `places.csv`: `name,ID,type,system_id,x,y,faction,description,source_url`
- `planet-generation.csv`: пока только канонический заголовок из 37 колонок, профилей нет

Шаблоны новых таблиц находятся в `data/systems-template.csv`, `data/places-template.csv` и `data/planet-generation-template.csv`. В листе систем `x`,`y` задают явное положение: маркер появляется только при полной корректной паре координат; без неё система остаётся в каталоге. Подробные требования к заголовкам, типам и публикации — в [`ADMIN_GUIDE.md`](../ADMIN_GUIDE.md), контракт профилей — в [`stage-2-data-and-sync.md`](stage-2-data-and-sync.md).

## Сущности

### System (звёздная система)

| Поле | Тип | Описание |
|---|---|---|
| `id` / `system_id` | string (PK) | Стабильный уникальный ID системы. `systems.csv` сейчас использует заголовок `system_id`. |
| `name` | string | Отображаемое название. |
| `type` | enum | Пустое значение или legacy `none` — стандартная система; `capital` — отдельная характеристика «Столица», а не тип места; `unknow` — неизвестный тип. |
| `x`, `y` | number | Явное положение системы на схеме. Маркер появляется только для полной пары координат внутри карты; предполагаемые/нечисловые/вне диапазона значения не используются. |
| `faction` | string | Фракция, если указана. |
| `description` | string | Описание, если указано. |
| `source_url` | string | Ссылка на источник, если указана. |

Система отображается на карте при полной корректной паре явных `x`,`y` в CSV либо при явной корректной привязке в `data/system-overrides.json`. Без такой пары она остаётся в каталоге; fallback-координаты не используются.

### Place (место)

| Поле | Тип | Описание |
|---|---|---|
| `id` / `ID` | string (PK) | Стабильный уникальный ID; текущий лист использует `ID`. |
| `name` | string | Название места. |
| `type` | enum | `planet`, `moon`, `asteroid`, `station`, `platform` или `other`; пустой/отсутствующий тип и legacy `none` трактуются как `planet`. |
| `system_id` | string (FK → System, nullable) | Связь места с системой. |
| `x`, `y` | number (nullable) | Координаты места на схеме. Для самостоятельной точки обе координаты обязательны; при указанном `system_id` отдельный маркер POI не создаётся. |
| `faction`, `description`, `source_url` | string | Дополнительные сведения, если указаны. |

Места со связанной системой показываются в её карточке. Самостоятельные точки интереса появляются только если `system_id` отсутствует и для места заданы допустимые координаты; пример — станция в открытом космосе. Без координат место остаётся доступно в каталоге.

### PlanetGenerationProfile (профиль генерации поверхности)

Источник — будущий лист `planet_generation`, снимок — `data/planet-generation.csv`. Это отдельная сущность рецепта поверхности, а не расширение карточки места.

| Группа полей | Смысл |
|---|---|
| `place_id` | PK профиля и FK → `Place.ID`; не более одного профиля на место |
| `profile_status`, `profile_revision` | `draft` / `review` / `frozen` / `disabled` и редакционная ревизия |
| `preset_id`, `surface_class` | Стартовый шаблон мира и тип поверхности |
| `radius_km`, `axial_tilt_deg`, `rotation_period_hours`, `palette_id` | Физические и render-параметры; радиус влияет на географию и число ячеек, остальные три не входят в географический ключ |
| `master_seed_hex`, версии, `generation_key` | Служебный контур детерминированной заморозки; заполняет только `tools/planet_generation.py` |
| Масштабы, процентили и переходы | Необязательные переопределения пресета; пустая ячейка раскрывается из пресета в эффективный манифест |

Профиль допустим для `planet` и `moon`; `other` принимается как ручное указание тела с поверхностью с предупреждением. Для `station` и `platform` профиль запрещён, для `asteroid` в MVP отклоняется до отдельного контракта. Отсутствие профиля означает, что утверждённого глобуса у места пока нет. Публичная замороженная поверхность в будущих этапах должна требовать `profile_status=frozen` и валидный `generation_key`.

## Разделы каталога

- `SYS` — системы.
- `PLN` — планеты.
- `STN` — станции.
- `PLT` — платформы.
- `ETC` — луны, астероиды и другие места.

Каталог поддерживает отсутствие `type` в старых или неполных данных: такие места рассматриваются как планеты. Текущие снимки CSV уже содержат колонку `type` в обоих листах.
