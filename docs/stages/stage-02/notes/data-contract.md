Обзор этапа данных и контракт синхронизации.

## Обзор этапа

### Что реализовано

| Артефакт | Назначение |
|---|---|
| `tools/planet_generation.py` | Единый контракт профилей: 37 колонок, 8 пресетов, валидатор, эффективный манифест, `generation_key`, CLI для seed/draft/manifest/key/freeze-row |
| `data/planet-generation.csv` | Начальный снимок нового листа: пока только канонический заголовок, профилей нет |
| `data/planet-generation-template.csv` | Шаблон для создания вкладки Google Sheets и два безопасных примера черновиков для существующих `places.ID` 2 и 5 |
| `data/sources.json` | Третий источник `planet-generation-sheet` включён; его CSV-URL собран из общего опубликованного токена книги и `gid=1183479406`. На момент включения живой лист содержит только заголовок |
| `tools/sync.py` | URL-источники переведены на двухфазную синхронизацию: скачать и проверить всё в памяти → только потом атомарно заменить снимки |
| `tests/test_planet_generation.py` | 26 автоматических тестов схемы, пресетов, ключа, валидатора и интеграционного гейта синка |
| `.github/workflows/check.yml` | Валидатор снимка и Python-тесты выполняются в каждом PR; наличие `data/planet-generation.csv` проверяется в публикации |

Боевые страницы пока не читают новый CSV. Это соответствует плану: Этап 2
закладывает данные и безопасную доставку, а страница планеты появится на
Этапах 6–7.

## Контракт данных

### Принятый контракт

#### Схема

Канонический заголовок — ровно 37 колонок из полного плана, в порядке
административной версии:

- идентичность и редакционный статус;
- физические и render-параметры;
- seed, версии и ключ заморозки;
- целевые масштабы C100-soft;
- 11 процентильных порогов;
- ширины мягких переходов и порог энтропии;
- служебная заметка.

Порядок колонок в Google Sheets может отличаться: валидатор читает по именам,
а снимок при синхронизации записывается в каноническом порядке. Пропущенные,
лишние и дублирующиеся заголовки — ошибка.

#### Пресеты

Зафиксированы стартовые идентификаторы из плана:

- `earthlike_balanced`;
- `earthlike_archipelago`;
- `ocean_world`;
- `desert_dry`;
- `ice_world`;
- `volcanic_active`;
- `barren_moon`;
- `gas_giant_bands`.

Пустая необязательная числовая ячейка означает значение пресета. В ключ
попадают не только имя и версия пресета, а все раскрытые эффективные значения,
поэтому будущая правка пресета не изменит уже замороженную планету молча.

Текущая версия набора — `planet-presets-v0`. Значения `continent_mean_cells`
пока следуют базовому плану (100 для сбалансированной Земли). После выбора
канонической плотности 64/128/192 их нужно перекалибровать новой версией
пресетов до массовой заморозки реальных планет.

#### Эффективный манифест и ключ

Географический манифест `PG1` включает:

- `place_id` и `profile_revision`;
- `surface_class`, `preset_id` и все раскрытые географические числа;
- `radius_km` и `master_seed_hex`;
- `grid_version`, `noise_version`, `geography_version`, `preset_version`;
- служебные `manifest_format=PG1` и `schema_version`.

Канонизация: UTF-8, ключи JSON отсортированы, числа предварительно округлены
до зафиксированной по полям точности и записываются без экспоненты.

```text
generation_key = PG1-<Base32 без padding от первых 128 бит SHA-256 манифеста>
```

В географический ключ сознательно не входят:

- название, фракция, описание и источник из `places`;
- `palette_id`, `axial_tilt_deg`, `rotation_period_hours` — отдельный
  render-манифест;
- `profile_status`, `approved_by`, `approved_at`, `notes_admin` —
  редакционные поля.

Golden-ключ тестового профиля Корхала IV (`place_id=2`, радиус 6371,
seed `0123456789abcdef`, ревизия 1, `earthlike_balanced`) закреплён тестом:

```text
PG1-YMXJZFKO73QBCK35LIYZ7DQAQU
```

#### Версии генератора

На Этапе 2 поддерживаются только честные прототипные версии после спайка:

| Поле | Значение |
|---|---|
| `grid_version` | `goldberg-gp-v0` |
| `noise_version` | `planet-noise-spike-1` |
| `geography_version` | `c100-soft-v0` |
| `preset_version` | `planet-presets-v0` |

Это позволяет уже сейчас проверять полный freeze-контур, но не выдаёт
прототип за боевой генератор. Массово замораживать реальные планеты следует
после Этапов 3–4, когда появятся канонические адреса и полноценные поля/C100
версий v1.

#### Правила валидации

Валидатор блокирует снимок при любой из следующих проблем:

- нет места с таким `place_id`, либо профиль дублируется;
- профиль создан для станции/платформы; астероиды пока отклоняются как
  отдельный будущий упрощённый контракт;
- неизвестный статус, класс поверхности или пресет;
- число вне диапазона, запятая вместо точки, NaN/Infinity;
- нарушен порядок процентилей (`shelf_below <= ocean <= shelf_above`,
  `highland <= mountain`, `arid <= wet`, `cold <= hot`,
  `stream <= major_river`);
- seed не содержит ровно 16 hex-цифр;
- у `frozen` нет радиуса, seed, явных поддерживаемых версий, утверждающего,
  даты или ключа;
- `generation_key` не совпадает с пересчитанным эффективным манифестом;
- заголовок CSV не соответствует схеме.

Особые случаи:

- `places.type=other` допускается как ручное указание тела с поверхностью,
  но с предупреждением;
- `surface_class=gas_giant` требует `gas_giant_bands`;
- `surface_class=no_surface` — только явный отказ от генерации при
  `profile_status=disabled`, без ключа местности.

## Каркас фронтенда

Статус: частично. Реализованы элементы, не ломающие текущий tile-рендер:
- Разбор параметра `?fresh=1` → `state.fresh`.
- Заглушка карты `#mapPlaceholder` с кнопкой «Повторить» + стили.
- Чтение версии из `meta.json` уже есть через `assetVersion()`/`fetchJSON`.
