# Синк, живой лист и автосинхронизация

> Назад: [паспорт этапа](../plan.md) · [шаг 0 консолидации](../../../consolidation/README.md) · [документация](../../../README.md)

Гейт синхронизации, живой лист Google Sheets и скелет автосинка.

## Гейт синхронизации

### Синхронизация и гейт этапа

Раньше URL-листы записывались по одному по мере загрузки. Теперь `sync.py`:

1. Скачивает все включённые URL-источники.
2. Нормализует их в памяти.
3. Для `planet_generation` разбирает исходный CSV строгим парсером с
   номерами строк.
4. Проверяет профили против именно той версии `places`, которая пришла в том
   же запуске.
5. Только при отсутствии ошибок атомарно заменяет CSV-снимки, `meta.json` и
   манифест источников; при сбое записи восстанавливает прежние файлы.

Интеграционный тест с фейковой загрузкой доказывает гейт этапа: при профиле
на несуществующее место синк завершается ошибкой, а прежние `places.csv` и
`planet-generation.csv` остаются байт-в-байт неизменными. Валидный frozen-
профиль, наоборот, применяется и попадает в манифест.

Если третий источник когда-либо выключить, синк читает локальный
`data/planet-generation.csv` и всё равно проверяет его против нового
`places` перед применением остальных URL-снимков. В текущей конфигурации
источник включён и после мержа PR будет скачивать живой лист в том же
двухфазном контуре.

### Инструмент администратора и разработчика

Основные команды:

```bash
# Проверить текущий снимок
python3 tools/planet_generation.py validate

# Новый seed (16 hex-цифр)
python3 tools/planet_generation.py seed

# Черновая строка для существующего места
python3 tools/planet_generation.py draft-row \
  --place-id 2 --preset earthlike_balanced --surface-class terrestrial

# Эффективный манифест и ключ уже заполненного профиля
python3 tools/planet_generation.py manifest --place-id 2
python3 tools/planet_generation.py key --place-id 2

# Полная frozen-строка после утверждения; исходный CSV не изменяется
python3 tools/planet_generation.py freeze-row \
  --place-id 2 --approved-by owner --approved-at 2026-10-19
```

Для вставки только служебного блока в Google Sheets удобен TSV-вывод —
`master_seed_hex`, четыре версии и ключ идут подряд в том же порядке колонок:

```bash
python3 tools/planet_generation.py key --place-id 2 --format tsv
```

### Включение живого листа

1. 20 октября 2026 владелец создал вкладку `planet_generation`
   (`gid=1183479406`) и импортировал заголовок из шаблона Этапа 2. Строк
   профилей в живом листе пока нет; два draft-примера шаблона туда не попали.
2. Перед добавлением профилей колонки `place_id`, `master_seed_hex` и
   `generation_key` должны быть обычным текстом; служебные колонки
   желательно защитить от ручных правок.
3. Книга опубликована целиком с автопубликацией изменений; токен `2PACX-…`
   сверен со ссылкой из окна публикации и не сменился. CSV-URL составлен
   из этого токена и `gid=1183479406`.
4. В этом PR URL вписан в `data/sources.json`, у `planet-generation-sheet`
   поставлено `enabled: true`.
5. После мержа PR нужно запустить или дождаться workflow **Sync upstream
   map data** и проверить успешный запуск. Так как живой лист и текущий
   снимок пока содержат только заголовок, содержательного изменения
   `planet-generation.csv` не ожидается.

До мержа PR живой workflow новую конфигурацию ещё не применяет:
`sync.yml` всегда чекаутит `main`. Конфигурация, валидатор и гейт синка при
этом полностью проверяются в PR.

### Открытые вопросы, не блокирующие код Этапа 2

- Каноническая плотность Земли и размер C100 в ячейках всё ещё зависят от FPS
  владельца на v=128/192 и телефоне. Это влияет на будущую версию пресетов,
  но не на схему таблицы.
- Этап 1.5 и полная визуальная часть гейта G1 не закрыты; владелец направил
  работу сразу на Этап 2. К переходу глобус → плоскость нужно вернуться до
  локальной карты.
- OpenSimplex2S против текущего simplex нужно решить до выпуска
  `noise_version` v1 на Этапе 4.
- Астероиды и разломанные тела не получают frozen-профиль в текущем MVP:
  сначала нужен отдельный упрощённый/расширенный контракт геометрии, а не
  молчаливое повторное использование сферического профиля.

## Скелет автосинхронизации

Статус: скелет реализован. Требует реальных `owner/repo` и путей в `data/sources.json`.

### Реализовано
- `tools/sync.py` — синк: SHA через GitHub API, сравнение с `data/upstream/manifest.json`, скачивание через raw.githubusercontent.com, валидация размера/формата, чтение размеров PNG/JPEG, transform CSV (flipY/scale/offset), валидация координат и уникальности id, запись `meta.json`/`manifest.json`, сохранение оригиналов в `data/upstream/`.
- `.github/workflows/sync.yml` — cron каждые 6 ч + `workflow_dispatch`, запуск синка, создание Issue при падении, коммит/пуш при изменениях.

### Не реализовано (TODO)
- Автоконвертация PNG >15 МБ → JPG (нужен libvips/Pillow).
- Автоопределение разделителя/кодировки (частично: ; → , и utf-8/cp1251).
- Мерж лор-колонок по id (разделение ответственности).
- Discord-вебхук алерт.
- Негативный сценарий-тест (несуществующий путь → Issue, данные не затёрты).
