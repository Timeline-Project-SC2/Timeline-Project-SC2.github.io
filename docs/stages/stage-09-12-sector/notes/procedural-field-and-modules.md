Процедурное поле сектора, модульная структура и тестовое покрытие.

## Процедурное поле

### 8. Процедурная замена растровой подложки

#### 8.1. Слои сцены

| Слой | Содержимое | Техника | Уровни |
|---|---|---|---|
| `field.nebula` | двух-трёхоктавный `fBm` по нормированному полю сектора, `domain warp`, палитра скина | WebGL2 `fullscreen quad`, шейдер; seed `hash("KP")` | `L0…L12` |
| `field.dust` | пылевые полосы поверх туманности | тот же шейдер, второй проход, анизотропия `1:4` | `L0…L9` |
| `field.stars` | звёздная пыль: `Power-law` яркость, пуассоновское распределение | инстансы точек, `≤ 40 000`, размер `1–2 px` | `L0…L12` |
| `field.heat` | тепловая карта плотности систем (гауссово ядро `σ = 250 св.г.`) + изолинии | CPU-превью `256 × 256`, билинейная текстура | `L0…L4` |
| `territory` | мягкие поля фракций (ядро + радиус + `alpha-shape` по системам); заливка и контур сетей, альфа по `layerFillAlpha`/`layerLineAlpha` | Canvas2D `Path2D`, `globalCompositeOperation = 'lighter'` | `L2…L12` |
| `address.grid` | **фактическая** сетка: старший тир `t` + ровно один вложенный `t+1`, одна толщина `1 px`, буквы в углу ячейки | Canvas2D | `L0…L12` |
| `systems` | точка `2,5 px` → глиф (фракция + тип) → диск звезды с короной `40 px`; размер строго по §6.2 | Canvas2D + аддитивные градиенты | `L0…L12` |
| `labels` | подписи с приоритетом (столица → фракция → плотность), антиколлизия | Canvas2D, бюджет `120` | `L3…L12` |
| `aperture` | кольцо-превью системы и «Войти» | Canvas2D | `L12` |
| `flight` | рамка-прицел, сжатие/захват, вложенные кадры, прогресс перехода | Canvas2D поверх сцены, один `rAF`-драйвер (`sector-flight.ts`) | `L0…L12` |
| `arrows` | шевроны на ближайшие системы по краям свободной области | Canvas2D + DOM-слой для фокуса и `aria-label` | `L0…L12` |
| `system.*` | звезда, орбиты, тела, статусы | отдельный слой кадра `O` (Canvas2D в MVP, WebGL2 — при необходимости) | `S0…S2` |

#### 8.2. Почему гибрид `WebGL2 + Canvas2D`

- Поле туманности — единственный слой, требующий попиксельного шума на всех масштабах;
  Canvas2D здесь даёт `> 40 мс` на кадр и «шумовую кашу» при зуме.
- Всё остальное (173 маркера, подписи, сетка, территории) — это векторы, где Canvas2D
  проще, доступнее и уже реализован в `canvas-renderer.ts` (1011 строк, проверен).
- Поэтому: **нижний слой — отдельный `<canvas>` с WebGL2**, верхний слой — существующий
  `#mapCanvas` с Canvas2D. Без WebGL2 — статичное поле (одна текстура `1024²`, собранная
  тем же шумом на CPU при первой загрузке, `≈ 30–60 мс`) и всё остальное как обычно.
- Никаких внешних зависимостей (правило репозитория), собственные GLSL-исходники
  по образцу `src/local-map/local-map-shaders.ts`.

#### 8.3. Детерминизм и стиль

- Seed: `xxHash32("KP")` + версия поля (`sector-field-v1`), по правилам §7.3 плана
  (`seed → подseed`). Одинаковый seed → одинаковое поле на всех устройствах.
- Палитра берётся из CSS-переменных скина (`--bg`, `--accent`, `--accent-2`), поэтому
  `sector` и `minimal` выглядят по-разному без второй реализации шума.
- Октавы: `4` при `L0…L4`, `5` при `L5…L12` с плавным появлением (fade по `log2(zoom)`),
  чтобы не было «вскипания» шума.
- Обязательный dither `±0,5/255` — иначе на тёмном фоне видны полосы квантования.
- `prefers-reduced-motion`: без параллакса звёздной пыли и без пульсации короны.

#### 8.4. Бюджеты

| Параметр | Бюджет |
|---|---:|
| Время кадра `L0` (desktop) | `≤ 8 мс` CPU + `≤ 8 мс` GPU |
| Время кадра `L12` | `≤ 16 мс` |
| GPU-память поля | `≤ 32 МБ` |
| CPU-память поля | `≤ 8 МБ` |
| Инстансы звёздной пыли | `≤ 40 000` |
| Запросы растра в рантайме | **`0`** (гейт `G7.3`) |
| Размер JS-бандла сектора | `≤ 120 КБ` gzip (текущий + новые модули) |

#### 8.5. Вывод растра из эксплуатации — сразу, одной волной

Решение владельца: **без переходных стадий и без растрового эталона** (`C-08`).
Обоснование — §2.2: эталон на глубине кратно размыт, а его пирамида требует
`3,69…381 млн` файлов (`166 ГБ…17 ТБ`). Поэтому поле и удаление растра входят
**в одну волну** — `SW-2`.

| Шаг | Что делается |
|---|---|
| 1 | `sector-field.ts` + сцена рисуют поле на всех уровнях `L0…L12` |
| 2 | удаляются `src/atlas/tile-pyramid.ts`, `state.rasterMode`, ветка `drawRaster`, `CONFIG.tiles`, `loadPreview` |
| 3 | `data-loader.ts` больше не запрашивает `assets/tiles.json`; `site/shared/links.ts` теряет `sectorMapPreview` |
| 4 | `tools/build_assets.py`: убираются `build_tiles`, `TILE_*`, `PREVIEW_*`, `update_meta` без `assets.*`; `.gitignore` и `.github/workflows/pages.yml` — без кэша тайлов |
| 5 | `assets/src/koprulu-sector.jpg` **удаляется** (не архивируется: эталон не нужен, `D-11`) |
| 6 | `data/meta.json`: поля `assets.*` удаляются; `mapSize` остаётся `10 000` |
| 7 | `verify:publish` `7/7`, `assets:check` зелёный, в публикации нет `tiles*`/`map-preview*` (гейт `G7.3`) |

Откат — обычный `git revert` волны: код поля и удаление растра в одном PR,
поэтому «полуудалённого» состояния не существует.

### 10. Архитектура модулей и контракты

#### 10.3. Инварианты под-уровня

| ID | Инвариант |
|---|---|
| **И-7** | Адрес — **производная биекция** координат. Ни одна запись данных не хранит адрес. Расстояния считаются только по `x`,`y` c `float64`. |
| **И-8** | Пороги уровней существуют **только** в `level-ladder.ts`. Ни один модуль не сравнивает `px/св.г.` со своими константами. |
| **И-9** | Секториальный кадр не рисует объекты мельче `0,25 px` (иначе — агрегат или скрытие); системный кадр не использует `св.г.` как единицу отрисовки. |
| **И-10** | После волны `SW-2` рантайм не запрашивает ни одного растрового ассета сектора; в `.publish` нет `tiles*` и `map-preview*`; в репозитории нет `assets/src/koprulu-sector.jpg`. |
| **И-11** | Планетарный контур не редактируется: файлы `site/planet-globe/*`, `site/shared/planet-*`, `src/planet/*`, `src/local-map/*`, `data/planet-generation.csv` вне `OWNED_FILES` под-уровня. |
| **И-12** | Положение систем — только `x`,`y` из `data/systems.csv`; никакой репроекции, «привязки к картинке» и ручной подгонки под фон. Размер маркера — только в пикселях по `markerDiameter(visibleWidth)`. |
| **И-13** | Во время полёта камерой владеет **только** `sector-flight.ts`: `animateTo`, колесо и пан не запускают параллельных циклов. Любой пользовательский ввод отменяет полёт за `≤ 1` кадр. |
| **И-14** | Полёт укладывается в `1 500 мс` при любых `Δ` уровня и любом устройстве; тайминги — только в `FLIGHT_TIMING`, ни одна фаза не задаёт длительность своей константой. |
| **И-15** | Стрелки — производная состояния камеры: отбор по расстоянию от центра свободной области и углу `θ = atan2(Δy, Δx)`. Никакого «случайного» или кэшированного выбора между кадрами при неизменной камере. |
| **И-16** | Расстояние в интерфейсе печатается **только** через `formatDistanceLy` из `sector-units.ts`: запятая вместо точки, неразрывный пробел перед `св.г.`, единица никогда не опускается. Ни один модуль не форматирует расстояние своей строкой. |
