## 1. Что сделано

Реализован **шаг 1 плана** (§11 части 2): чистое ядро без UI и рендера, затем
слой команд редактора (шаг 3, модель без интерфейса). Плюс закрыты пункты 1–2
порядка работ части 3: области действия (scope) с адаптерами к существующим
границам и пограничный мир на уровне систем.

Модули — `src/atlas/sector-areas-*`:

| Модуль | Что делает |
|---|---|
| `sector-areas-contract.ts` | Типы `Area`/`State`/`Mode`, схема версии 1, разбор и валидация документа, поиск циклов |
| `sector-areas-geometry.ts` | Кольца, площадь, центр, принадлежность точки, самопересечения, RDP и Шайкин с сохранением параметра пути |
| `sector-areas-lod.ts` | Эффективный уровень, допуск упрощения, пресеты `−1 L`/`0`/`+1 L`, кэш |
| `sector-areas-color.ts` | Палитра фракций, режим, задача, `stroke-safe`, настраиваемый фокус-режим |
| `sector-areas-gradient.ts` | Градиент `auto`/`custom`/`hybrid`, `splitAt`, шов, раскраска вершин |
| `sector-areas-cascade.ts` | Наследование по `parentId`, приоритет состояний, отсечка по глубине, проверка вложенности |
| `sector-areas-force.ts` | Форс-закрашивание как отдельный override-слой |
| `sector-areas-scope.ts` | Области действия, адаптер `sector-bounds.json`, детализация, правила пар |
| `sector-areas-border-world.ts` | Пограничный мир: полосы от центральных систем |
| `sector-areas-journal.ts` | Записи журнала, счётчики «веса», фильтры, выгрузка |
| `sector-areas-editor.ts` | Команды редактора: кисть, секторный снап, вершины, состояния, история и экспорт |

Счётчик тест-файлов в self-тесте стража карантина
(`tests/check-test-baseline.test.mjs`) обновлён: 40 → 44 — иначе `npm test`
считает новый файл «новым падением».

Данные: `data/sector-areas.json` — каркас схемы версии 1 (областей нет).
Тесты: `tests/sector-areas.test.mjs` (31 тест), `tests/sector-areas-scope.test.mjs`
(11), `tests/sector-areas-border-world.test.mjs` (8), `tests/sector-areas-editor.test.mjs`
(14); все подключены в `test:raw`.

**Слой команд редактора** (`sector-areas-editor.ts`): свободная кисть строит
контур в мировых координатах (штрих раздувается по ширине, переведённой из px в
мировые по масштабу), адрес вычисляется справочно; секторный снап берёт ячейку
через `prefixOf`/`rectOf` на глубине 5–7 букв, родителем становится существующая
область ячейки предыдущего тира. Правка вершин идёт по уникальным вершинам:
замыкающая точка восстанавливается, минимум замкнутого кольца — три вершины.
История — `past`/`future` с событиями в журнале документа; экспорт и импорт
идут через `parseSectorAreas`, поэтому импорт валидируется.

## 2. Решения владельца, заложенные в код

| Вопрос §12 | Решение |
|---|---|
| Режим кисти | Свободная кисть по умолчанию: геометрия в мировых координатах, адрес справочный; секторный снап — отдельный режим инструмента |
| Фокус-режим | Настраивается: приглушение (по умолчанию) или скрытие; данные не фильтруются |
| Форс-закрашивание | Мазок коммитится сразу в `overrides`, исходные состояния сохраняются, снятие — отдельным действием |
| Состояний на режим | Несколько, выбор по приоритету; при равном приоритете — по идентификатору |
| Родитель каскада | Явный `parentId` плюс проверка вложенности по геометрии (предупреждение) |
| Журнал | Полный состав: записи, фильтры по режиму/фракции/глубине, счётчики и выгрузка |

## 3. Что сознательно не сделано

- **Рендер.** Ни один модуль не рисует: нет канвы, DOM и WebGL. Порядок
  отрисовки подготовлен функцией `paintOrder` (мазки форс-закрашивания —
  последними), но не подключён к `sector-scene.ts`.
- **Интерфейс редактора.** Панель админской копии сектора заполнена (модули,
  свойства, изменения), кисть работает на канве, `undo/redo` — кнопками и
  клавиатурой, экспорт — файлом и буфером обмена. **Не сделано:** правка вершин
  мышью, выбор фракции и задачи в свойствах состояния, анимации режимов,
  публикация и PR-workflow (заявку в GitHub оформляет владелец).
- **Анимации.** Военные снаряды, импульсы экономики и пульсация тэншен
  описаны только как `animation` в стиле режима. Пул частиц, лимит,
  `prefers-reduced-motion` и сид — следующий шаг.
- **Публикация.** Нет разделения «черновик/опубликованный JSON» и PR-workflow.
- **Миграции.** Схема версии 1 — первая; правила перехода с будущих версий
  появятся вместе с первой правкой формата.

## 4. Замечания по геометрии

- Упрощение и сглаживание сохраняют **параметр исходного пути** (`0…1`) в
  каждой вершине. Поэтому градиент считается по исходной ломаной и не плывёт
  ни при панорамировании, ни при смене LOD; точка `splitAt` остаётся на месте.
- Catmull-Rom не используется: он может выходить за исходную геометрию.
  Сглаживание — Шайкин, не более двух проходов.
- Самопересечение замкнутого контура — предупреждение валидатора, а не
  автоисправление: геометрия админа не переписывается сама.
- Проверки принадлежности в `sector-bounds.ts` по-прежнему считают по исходной
  ломаной, а не по видимой кривой; согласование с `sector-areas-scope.ts`
  остаётся открытым пунктом TODO этапа.

## 5. Слой отрисовки и интерфейс (шаг 2, сделано)

- `src/atlas/sector-areas-render.ts` — чистый слой: документ, уровень кадра и
  настройки фокуса → список красок (`AreaPaint`). Порядок готов к отрисовке:
  по `z`, затем по режиму, затем по идентификатору; мазки форс-закрашивания —
  последними. Фокус-режим либо приглушает состояние (`dim` уменьшает альфу),
  либо убирает его из списка (`hide`).
- `sector-scene.ts` — примитив `kind: 'brush'` (`SceneArea`): экранные точки,
  цвета вершин строками CSS, альфы, пунктир, признак мазка. Области ставятся
  после сетки адресов и до маркеров; в `counts` добавлен счётчик `areas`.
- `canvas-renderer.ts` строит краски на каждом кадре (кэш LOD один на рендер,
  палитра фракций — из `data/factions.csv`) и рисует заливку по правилу
  «чётность», а обводку — по сегментам, если градиент дал цвета вершин.
- `data-loader.ts` и `config.ts` читают тот же `data/sector-areas.json`, что и
  публичный `/sector/`; у админской копии нет отдельного снимка данных.
- `src/atlas/sector-areas-editor-ui.ts` — панель и ввод; подключается только
  при наличии `[data-admin-editor]`. Черновик — в локальном хранилище,
  выгрузка — JSON-файлом, материал заявки — Markdown с журналом и документом.
