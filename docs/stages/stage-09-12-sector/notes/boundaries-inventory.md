## 1. Границы под-уровня

### 1.1. Входит

| Область | Что именно |
|---|---|
| Маршрут `/sector/` | замена растровой подложки процедурным полем, векторный слой систем, 13-ступенчатая лестница глубины |
| Маршрут `/minimal/` | тот же рантайм с минимальным скином; координатный readout заменяется адресным |
| Маршрут `/planet-globe/` | **только приём** перехода из системного кадра (`?place=&system=&cell=`) — сам контур не правится |
| Данные | новые правила адресации поверх `data/systems.csv`; изменения схемы CSV **не требуются** |
| Сборка | **немедленный** вывод из эксплуатации тайлового конвейера и исходного растра сектора, правки `tools/build_assets.py`, `.github/workflows/pages.yml`, `.gitignore` |
| Админ-конвейер | новый `Shift+клик` («карточка точки», §7.8) и режим `?coords=1`; `tools/sync.py` не меняется |
| Навигация | клик-полёт к системе (§6.4), интерактивные стрелки на ближайшие к центру камеры системы (§6.5) с переходом «откат → рефокус → смещение → приближение» (§6.6) |
| Документация | этот документ, `PREPARATION_PLAN` §9.6/§12, `PREPARATION_PLAN_ADMINS`, `ADMIN_GUIDE` §3.1 (примечание про адрес) |

### 1.2. Не входит

- Планетарная генерация, глобус, локальная карта, атлас растительности — **параллельный контур**.
- Растровая карта галактики `assets/src/galaxy-map.jpg` и `/` (галактический экран) — отдельный уровень, не трогаем.
- Google Sheets как источник (никаких новых колонок на этом под-уровне — см. `D-01`).
- Физика перелётов и скорости (travel planner) — сохраняется как есть, меняются только подписи.
- 3D-модели планет в системном кадре (сфера-прокси допустима, полноценный глобус — планетарный контур).

### 2.2. Растровый конвейер (то, что убирается)

| Артефакт | Объём / параметр |
|---|---|
| `assets/src/koprulu-sector.jpg` | исходник `10 000 × 10 000` |
| `assets/tiles/<level>/<x>_<y>.webp` | уровни `1250 / 2500 / 5000 / 10000`, тайл `512 px`, качество `82` |
| `assets/tiles.json` | манифест + `version` для `?v=` |
| `assets/map-preview.webp` | подложка первого кадра, ребро `2500`, качество `82` |
| `data/meta.json` `assets.hasRaster / preview / tiles / version` | флаги включения растра |
| `site/shared/links.ts` `sectorMapPreview` | ручная ссылка на превью |
| `.gitignore` (4 строки), `pages.yml` (кэш ассетов), `tools/build_assets.py` `build_tiles` | сборочная обвязка |

**Почему растровый эталон не сохраняется (замер).** Даже текущая четырёхуровневая пирамида
(`1250 / 2500 / 5000 / 10000`) покрывает только `≈ 4,2 px/св.г.` — это уровень `L4`, а не `L9`.
Если продолжать пирамиду до глубины, получается:

| Глубина пирамиды | Пикселей на ось | Тайлов `512²` | Объём при `≈ 45 КБ/тайл` |
|---|---:|---:|---:|
| `L4` (`4,2 px/св.г.`) — сейчас | `42 000` | `6 900` | `≈ 0,3 ГБ` |
| `L9` (`98,3 px/св.г.`) | `983 040` | **`3 686 400`** | **`≈ 166 ГБ`** |
| `L9` + младшие уровни пирамиды | — | `4 896 000` | `≈ 220 ГБ` |
| «1 000 px/св.г.» из запроса | `10 000 000` | **`381 499 024`** | **`≈ 17 ТБ`** |

Отсюда решение владельца: **не строить ориентир вообще**. Один и тот же источник истины —
математическое поле `10 000 × 10 000`; любая «копия картинки» на глубине кратно размыта
и не даёт ничего, кроме гигабайтов артефактов до окончания полного рендера.

### 2.3. Текущая глубина погружения

> **Историческая справка (снимок 24.10.2026, до `Z-4b/Z-5`).** Таблица оставлена как след
> исходного состояния: строки про `L9` и `2,23 px/св.г.` больше не действуют — предел
> приближения и лестница пересчитаны в §16 и §6. Актуальны только строки про пан/зум и
> «вся карта».

| Параметр | Значение | Следствие |
|---|---|---|
| `CONFIG.view.fitInset` | `0.94` | «вся карта» = `min(vw,vh)·0.94/10 000` px/св.г. |
| `CONFIG.view.maxFactor` | `22` | предел приближения относительно «вся карта» |
| Фактический предел на `1920 × 1080` | `≈ 0.1015 · 22 =` **`2.23 px/св.г.`**, в кадре `≈ 860 св.г.` | текущая глубина ≈ уровень `L3.5` новой лестницы |
| Требуемая глубина `L9` | `98.3 px/св.г.` | **×44** от текущего предела |
| Системный кадр `S0` | `1,21 · 10⁶ px/св.г.` (1 а.е. = 19,2 px) | **×5,4 · 10⁵** от текущего предела |
| Пан/зум | `clamp` по `panMargin 0.25`, `animate 340 мс` | сохраняется, пороги меняются |
| Маркер | `CONFIG.markerLod`: `worldRadius 30`, `minRadius 7`, `maxRadius 46` в координатах `10k` | заменяется на размер в пикселях по глубине (§6.2) |
| «Вся карта» | `min(vw,vh) · 0.94` | заменяется на «вся карта по ширине» + отъезд до `16 000 св.г.` (§6.3) |

## 3. Проверка расчётной базы владельца

Пересчёт выполнен по `data/systems.csv` (173 строки, снимок 24.10.2026), единица —
координатная единица поля, принятая за 1 св.г. (допущение `A-1`, §13). Решением владельца
26.10.2026 допущение стало фактом (§16.2): `1` единица карты = `1` св.г., поэтому все числа
§3.1–§3.3 читаются как световые годы без пересчёта (`403,7` — это `403,7 св.г.`).
