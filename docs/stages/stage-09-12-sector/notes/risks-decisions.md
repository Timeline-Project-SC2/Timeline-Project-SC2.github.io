## 13. Риски и открытые решения

### 13.1. Риски

| № | Риск | Смягчение |
|---|---|---|
| `R-1` | Процедурное поле визуально «хуже» исходной карты, а эталона для сравнения нет | два пресета стиля (`field.nebula` и «тактический тёмный», `D-08`) выбираются флагом `?style=`; поле и удаление растра в одном PR — откат одним `git revert`; приёмка до merge |
| `R-2` | Адреса `A…Y` нечитаемы («KP·REQHC» выглядит случайно) | уровневая запись в крошках, подсказка расшифровки, возможность назвать квадранты вручную (пост-MVP) |
| `R-3` | Дрожание на `L12` из-за `float32` | камеро-относительные матрицы, гейт `G7.5`, тест с координатой `9 233` |
| `R-4` | «Мёртвая зона» `S → O` воспринимается как баг | явная анимация 1,4 с, индикатор масштаба, подсказка, отмена по `Esc` |
| `R-5` | Системный кадр пуст (167/173) | честное пустое состояние, задача наполнения (§9.3), не выдумывать лор |
| `R-6` | Удаление растра ломает `verify:publish`, `assets:check` или CI-кэш | правки `pages.yml`, `.gitignore`, `build_assets.py` и `meta.json` — в том же PR `SW-2`; `verify:publish` и `assets:check` в гейте `G7.3` |
| `R-7` | Расхождение с планетарным контуром из-за одновременных правок | `И-11`, матрица `OWNED_FILES`, ежедневная сверка `git diff --name-only` |
| `R-8` | `mapSize` изменится и адреса «съедут» | верификатор падает при `mapSize ≠ 10 000`, `--regen` печатает новые golden vectors |
| `R-9` | Полёт на длинную дистанцию «рвёт» кадр или выходит за `1 500 мс` из-за подписей и антиколлизии | антиколлизия в фазе `C` считается не чаще `1` раза в `100 мс`; бюджет времени в `FLIGHT_TIMING`, тест по матрице `Δ = 0…12`; при перерасходе режется число вложенных кадров, а не время |
| `R-10` | Стрелки дёргаются на границе видимости | **снят решением владельца**: отбор идёт по расстоянию до центра камеры, а не по видимости, поэтому пересечение края кадра список не меняет; пересчёт — только при сдвиге камеры больше `0,5 px` |
| `R-10′` | На `L0` все `173` системы видимы, и стрелки выглядят лишними | «внутренний» вид стрелки (непрозрачность `0,6`), сдвиг вдоль рамки, проверка визуально (`D-19`); при отказе — скрывать «внутренние» стрелки на `L0–L1` (одна константа в `ARROW_CONFIG`) |
| `R-11` | Подпись у каждой из `5` стрелок перегружает край кадра, особенно на телефоне | подпись — одна строка «имя · расстояние», `11 px`, максимум `5` штук, обрезка имени до `12` символов с `ellipsis`; на телефоне подписи только двух ближайших, остальные — по нажатию (`D-19`) |
| `R-12` | Фактическая сетка на глубине даёт «кашу»: два тира в каждой ячейке читаются как шум, особенно при панорамировании | одна толщина `1 px`, старший тир ярче (`0,16` против `0,07`), подписи только в старшем тире, предохранители `MAX_GRID_LINES = 512` / `MAX_GRID_LABELS = 64` не поднимаются; фактический максимум `171` линия (`L3`) и `≤ 64` подписи оставляют запас `3×`; при провале приёмки — деградация до одного тира `t` (одна константа) |
| `R-13` | Смена `MARKER_EXPONENT` (`1,1374 → 0,3544`) «уменьшает» маркеры на средних уровнях и ломает привычный вид | пересчёт по концам ряда `2,5 → 40 px`; значения §6.2 сверяются тестом на `0,1 px`; на `L4` диаметр падает `8,0 → 6,3 px` — это ожидаемо, но требует визуальной приёмки владельцем (`D-21`) |
| `R-14` | Тиры `T6/T7` в кодеке ломают поиск, `parseAddress` и golden-тесты | канон адреса остаётся пятибуквенным (`addressOf` не меняется), `prefixOf` расширяется до `0…7`, `parseAddress` принимает `5…7` букв, golden vectors §7.5 не трогаются; `verify:address` проверяет round-trip на `1 000` точках |
| `R-15` | Территории на `L8…L12` превращаются в плотное пятно под маркером | альфа по `layerFillAlpha` (нижняя граница `0,25`) и `layerLineAlpha` (`0,45`), заливка не ярче маркера, проверка на `L8`/`L10`/`L12`; при отказе — гасить заливку глубже `L10`, оставляя контур |
| `R-16` | С 13 уровнями бюджет полёта `1 500 мс` упирается в кламп при `Δ ≥ 10`, и переход с `L0` на `L12` перестаёт «расти» | принято как рабочее поведение: `Δ = 0…9` даёт `760…1 480`, `Δ = 10…12` — ровно `1 500`; дальнейшее наращивание глубины требует либо `Δ`-независимой формулы, либо пересмотра бюджета — отдельным решением владельца, не «тихой» правкой `FLIGHT_TIMING` |

### 13.2. Решения владельца (`D-01…D-18`) — рекомендации по умолчанию

| № | Вопрос | Рекомендация |
|---|---|---|
| `D-01` | Хранить адрес в CSV? | **Нет**: производный адрес; CSV не меняется (иначе второй источник истины и правки синка) |
| `D-02` | Код сектора | `KP` (Копрулу); резерв `TS`, `UJ`, `CH`, `AY`, `SL`, `SH` |
| `D-03` | Алфавит и ориентация | `A…Y`, `5 × 5`, `y` вниз (зафиксировано данными, `flipY = false`), строка `A…E` — полоса `y ∈ [0…2 000)` |
| `D-04` | 5 тиров `2000/400/80/16/3,2` | **Принять**: уникальность на `T4` доказана данными |
| `D-05` | Состав 13 уровней | **уточнено владельцем 26.10.2026**: 13 секторных `L0…L12` + `S0…S2` с номерами `13…15` (§16.4) |
| `D-06` | Мост `S → O` | смена кадра `1 400 мс`, вход по выбору, `Esc` — отмена |
| `D-07` | Судьба растра | **решено владельцем**: удалить сразу, без эталона и без `?raster=1` |
| `D-08` | Стиль поля | туманность + пыль + тепловая карта (рекомендуется); альтернатива — «тактический тёмный» |
| `D-09` | Системный кадр | overlay в `/sector/` (рекомендуется), не новый маршрут |
| `D-10` | Орбиты без данных | «условная схема» + честный статус; `orbital_index` — отдельным решением |
| `D-11` | `assets/src/koprulu-sector.jpg` | **решено владельцем**: удалить вместе с тайловым конвейером (эталон не нужен) |
| `D-12` | Растр галактики | не трогать в этом под-уровне |
| `D-13` | `Shift+клик` | **решено**: карточка точки (§7.8) вместо слепого копирования `x⇥y`; `?coords=1` сохраняет старое поведение |
| `D-14` | Маркеры | **решено**: непрерывный размер `2,5…40 px` по видимой ширине (§6.2); мировые радиусы `markerLod` удаляются |
| `D-15` | Положение систем | **решено**: без репроекции, `x`,`y` из CSV не меняются; фон рисуется процедурно |
| `D-16` | Кадры полёта | **согласовано владельцем 24.10**: жёсткий предел — `3` промежуточных кадра; цель оптимизации — `≤ 2`, но это ориентир, а не гарантия на каждом устройстве |
| `D-17` | Стрелки и подписи | **согласовано владельцем 24.10**: отбор по близости к центру камеры (не по видимости), каждая стрелка — отдельный объект, лишние в `+n`; подпись видна всегда, `hover` — только акцент; на телефоне допустим сдвиг стрелки по вертикали и расхождение направления |
| `D-18` | «Отдаление на 2 сектора» | **согласовано владельцем 24.10**: основной вариант `×25` (два тира адреса) с клампом `16 000 св.г.` и добором `2,2 · d`; `×4` сохраняется как запасной режим `?recede=levels` |
| `D-19` | Стрелки на цели внутри кадра и плотность подписей | рекомендация: «внутренний» шеврон `0,6` непрозрачности; на телефоне подписи только у двух ближайших; проверить визуально на `L0`/`L4`/`L12` |
| `D-20` | Единица длины и предел зума | **решено владельцем 26.10.2026**: `1` единица карты = `1` св.г.; предел `0,002` св.г. на CSS-пиксель (`500` px/св.г.), не зависит от экрана (§16.2, §16.3) |
| `D-21` | Размер маркера на новой лестнице | рекомендация Гайдлайнера: сохранить концы `2,5` и `40 px`, показатель `0,3544`; средние уровни становятся мельче (на `L4` `6,3` вместо `8,0 px`) — приёмка визуальная, при отказе меняется один показатель |
| `D-22` | Глубина адреса | рекомендация: канон `5` букв, `6–7` букв — только подпись ячейки сетки и лупа; в поиск до отдельного решения не вводить (§7.2) |
| `D-23` | Сетка на `L0` | **согласовано владельцем 26.10.2026**: «надо добавить сетку, как сейчас фон, — но фактическую… состояние в зависимости от глубины»; сетка есть на всех уровнях `L0…L12`, декоративная `80 px` удаляется (`§17.3`, `Z-4f`) |

### 13.3. Допущения

- `A-1`: 1 координатная единица = 1 световой год (утверждение владельца; из данных не выводится).
- `A-2`: эталонный viewport `1920 × 1080`; мобильный — `1080 × 2340`, пороги пересчитываются по `C-11`.
- `A-3`: канонический `mapSize = 10 000` сохраняется на весь под-уровень.
- `A-4`: порядок строк `places.csv` — допустимый суррогат орбитального порядка до появления `orbital_index`.
