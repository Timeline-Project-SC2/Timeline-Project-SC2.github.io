>
> Статус: **наблюдение, причина не доказана.** На момент проверки карантин не менялся;
> впоследствии реестр удалён, известные пропуски отслеживаются в [issue #374](https://github.com/Timeline-Project-SC2/Timeline-Project-SC2.github.io/issues/374).

## Тест `A-31 / Stage-8.12d` падает только в комбинированном прогоне

**Симптом.** `A-31 / Stage-8.12d: все 7 контрольных ячеек A-29 держат фактуру RMS,
перепад суши и waterDepthM воротника` (`tests/local-map-texture-812d.test.mjs`) зелёный
при одиночном запуске и красный, когда файл идёт вместе с другими тестами планетарного
контура. Тест **не входит** в реестр карантина, поэтому страж его падение считает новым.

**Воспроизведение (10.11.2026, HEAD `c9f06c95c85009fca00f656c19cca69ce5e7d4a2`, база
`b1dbe2937ab3ed1238bb680606711f3e2ddabcf7`).** Среда: Linux x86_64, 2 vCPU, Node
`22.22.3`, npm `10.9.8`, Git `2.39.5` (не среда CI с Node 24).

```
node --test tests/local-map-texture-812d.test.mjs
  → pass 2, fail 0

node --test tests/local-map-stand.test.mjs tests/local-map-stage8.test.mjs
  → tests 65, pass 58, fail 7

node --test tests/local-map-texture-812d.test.mjs tests/local-map-stand.test.mjs tests/local-map-stage8.test.mjs
  → три прогона подряд: pass 60, fail 7 (детерминированно, без A-31)

node --test --test-concurrency=1 <те же три файла>
  → pass 60, fail 7 (без A-31)

node tools/check_fast.mjs --all --run
  → три прогона подряд: 605/9, 606/8, 606/8 — в первом прогоне девятым падением был A-31
```

**Что известно.** Падение наблюдалось только в полном наборе (`--all --run`: 628 тестов), где файл идёт
рядом с остальными планетарными тестами; повторно получить его в узкой комбинации не
удалось. Отличие узкого прогона от полного — состав соседних файлов и общая нагрузка на
2 vCPU; какая из причин (порядок, разделяемое состояние, таймаут под нагрузкой) действует,
**не доказано**.

**Почему внесено.** Гейт `--all --run` запускает набор без карантинного стража, и
нестабильное падение вне реестра делает красный результат неотличимым от настоящей
регрессии. Пока причина не найдена, `--all --run` не годится как доказательство зелёного
набора.

**Что делать.** При воспроизведении фиксировать полный вывод и состав файлов; решение о
карантине — отдельным решением владельца (правка реестра `known-test-failures.json`
и `meta` карточки `CI-2`), а не попутно в другом PR.

**Источник и атрибуция.** Наблюдение зафиксировано исполнителем 10.11.2026 при доработке
#373 (серия `check_fast --all --run`). Независимое ревью того же PR (10.11.2026) полного
прогона **606/8** не показало падения `A-31`; его прогон дал ровно восемь реестровых
падений. Поэтому запись выше — **наблюдение исполнителя**, а не подтверждённый независимо
факт, и причина не считается доказанной.
