### 8.20. Замечено при приёмке A-12b (запись 23.10)

Наблюдения, которые не входили в карточки приёмки. Два из них стоят отдельного
пункта бэклога, остальные записаны, чтобы не потерялись, и действий не требуют.

**A-24. Гейт G4 нестабилен на самом `main`.** Проверка
`genMs <= 150 мс` живёт в двух местах: `tests/local-map-stage8.test.mjs:380`
(Stage-8) и `:1911` (Stage-8.5, перебор радиусов). На чистом `origin/main`,
без правок A-12b, при трёх параллельных прогонах гейт падает: 150,9 мс против
порога 150. В A-12b то же поведение — 156,5 мс. Значит, это не регрессия волны,
а **пограничный порог плюс зависимость от нагрузки**. Опасность не в самом
флейке, а в привычке: зелёный прогон перестаёт что-либо доказывать, и настоящая
деградация пройдёт незамеченной.

Требование: либо замер перестаёт зависеть от фона (фиксация окружения, медиана
из N прогонов вместо одного), либо порог пересматривается по данным, а не
подкручивается до зелёного. Порог нельзя поднимать «пока не упало».

**A-25. Публикация не отличает используемое от сирот.** `TimelinePublishPipeline`
публикует каждый `site/**/*.ts` отдельным ассетом — сейчас в `site/` 19 таких
файлов. Отсюда два следствия, проверенных на A-12a и A-12b:
`shared/planet-globe-pack-*.js` (152 357 Б) и `shared/planet-geography-*.js`
(178 091 Б) лежат в `.publish/`, хотя ни один JS на них не ссылается; счётчик
`verify:publish` растёт от любого нового файла (31 → 32 → 34), даже если файл
никем не востребован. Браузер их не скачивает — в `index.html` нет ни `preload`,
ни `<script>`, — то есть **пользователь не страдает, страдает сигнал**: число
ассетов перестаёт быть индикатором состояния сборки.

Требование: `verify:publish` сообщает о сиротах отдельным списком, а рост общего
счётчика перестаёт быть поводом для тревоги. Удалять файлы из `.publish/` не
обязательно: важно, чтобы сирота была названа, а не тонула в общем числе.

**Замечено, действий не требует:**

- `fetchFirst` и `fetchCSV` глушат сетевые ошибки — уже вынесено в A-20.
- Два парсера CSV расходятся по многострочным полям — уже вынесено в A-21.
- Подпись соседей «река» по `streamWeight > 0` — уже вынесено в A-17.
- `neighborCompassLabel` использует восьмирумбовую шкалу для шести соседей.
  Проверено: 60°-шаг даёт шесть различных меток (`С`, `СВ`, `ЮВ`, `Ю`, `ЮЗ`,
  `СЗ`), дублей нет — дефекта нет, менять не нужно.
- `?debug=local` читается один раз при загрузке (`planet-globe.ts:287`), смена
  параметра без перезагрузки не подхватывается. Для инструмента приёмки это
  нормально, записано как свойство, а не как задача.

### 8.21. A-16: первый реальный замер перехода (24.10)

Инструмент построен (Stage-8.10c, PR #223) и впервые применён владельцем
на живой странице. Записаны два файла — один пустой по фазам, один с полным
переходом. Это первые цифры, полученные не из бенчмарка, а из настоящего клика.

**Полный переход, ячейка `#146276`, seed `2057781644`:**

| Метка | Время, мс | Δ, мс | Событие |
|---|---:|---:|---|
| `t0` | 11 903,2 | — | нажатие «Старт логирования» |
| `t1` | 14 985,6 | **3 082,4** | Dive-in (реакция человека) |
| `t2` | 14 986,0 | 0,4 | Patch7 готов |
| `t3` | 14 986,0 | 0,0 | `import()` ленивого чанка |
| `t4` | 14 986,5 | 0,5 | `generateLocalMap` завершён |
| `t5` | 15 009,7 | 23,2 | юбка горизонта завершена |
| `t6` | 15 226,3 | **216,6** | GPU-заливка завершена |
| `t7` | 15 246,2 | 19,9 | первый показанный кадр |
| `t8` | 15 326,0 | 79,8 | успокоение |

`maxFrameGapMs = 189`, `alarming = true` (порог 100 мс).

**Что из этого следует.**

1. **Переход `t1 → t8` = 340,4 мс.** CPU-часть (`t1 → t5`) — **24,1 мс**,
   то есть генерация и юбка почти бесплатны. **GPU-заливка — 216,6 мс,
   64 % всего времени.** Главный источник задержки находится не в генерации,
   а в передаче геометрии на GPU.
2. **Порог тревоги сработал честно.** `max frame gap` = 189 мс значит, что
   заливка, названная в интерфейсе «порционной GPU-заливкой без блокировки
   кадров», один кадр всё-таки заблокировала почти на 0,2 с. Это прямой вход
   для A-15 / 8.11b: ограничение угловой скорости камеры и пре-рендер должны
   закрывать именно этот участок, а не генерацию.
3. **Замер «тёплый».** `t2 → t3` = 0 мс (ленивый чанк уже загружен),
   `t2 → t4` = 1 мс (патч пришёл из префетча). Холодный первый переход
   в сессии ещё не измерен — его цифры будут выше, и мерить его нужно
   отдельно, иначе первый вход выглядит лучше, чем он есть.
4. **`t0 → t1` = 3 082 мс — это человек, а не система.** В сырой таблице
   `t0` соседствует с `t8`, и разница читается как «переход длиной 3,4 с».
   Нужна производная метрика `totalMs = t8 − t1`, иначе отчёт будет врать
   при чтении глазами.

**Дефекты инструмента, найденные на первом же замере (A-26).**

| Что | Факт | Требование |
|---|---|---|
| Плейсхолдер ячейки | В коде `finalRecord.cell ?? '?'`, в имени файла пришло `tl-2057781644-_-…json` — браузер заменил `?` на `_` | не использовать символы, недопустимые в имени файла; писать `null` или `na` |
| Запись без перехода | Первый файл: заполнен только `t0`, `cell: null`, но запись легла в кольцевой буфер как обычный переход | признак `complete`/`aborted`; такие записи не должны искажать статистику |
| `debug=local` в адресе | `syncBrowserUrl` (`planet-globe.ts:2397`) собирает URL с нуля и не переносит `debug` — после первого Dive-in режим пропадает из адресной строки, F5 его теряет | переносить `debug`, если он был |
| Производные метрики | `console.table` печатает только сырые `t0…t8` | добавить `totalMs` (и, если недорого, `cpuMs` / `gpuMs`) |

**Что подтверждено и работает.** Кнопка живёт только при `?debug=local`;
`t1` ставится на Dive-in и не перезаписывается; буфер и скачивание файла
работают; `alarming` — отдельный флаг, а не смешан с итогом; в Network
`local-map-worker-lazy-38b22d8a2f.js` появился при Dive-in с initiator
`planet-globe-*.js:5370`, то есть через динамический `import()`, как задумано
в A-12b.

### 8.21. A-12b и A-16 закрыты (PR #223 `5c4ba45`, 24.10)

Обе волны слиты одним PR после визуальной приёмки владельцем.

**A-12b — цепочка локальной карты разорвана.** Главный чанк: `549 854 → 325 119 Б`
на момент слияния A-12b, `AGFzbQ` `2 → 0`. С лог-замером (A-16) главный чанк
дорос до 327 356 Б, `AGFzbQ` остаётся `0`. `local-map-worker-lazy-38b22d8a2f.js`
(252 537 Б) грузится при первом Dive-in через динамический `import()` — проверено
в браузере: initiator `planet-globe-*.js:5370`, чанк не предзагружается из HTML.

**A-16 — тестер-лог построен и применён.** Кнопка «Старт логирования» в
`#patchInspector` над Dive-in, только при `?debug=local`. Пять коммитов:
базовая реализация → полировка (читаемость, типы, `els`-кнопка, `.json`,
`revokeObjectURL`) → перенос кнопки и `t1` на пути Dive-in → правки по живым
замерам (A-26: `null` вместо `?` в имени, флаг `aborted`, `debug=local` в URL,
`totalMs` / `gpuMs`).

**Первый реальный замер** (ячейка `#146276`, seed `2057781644`):

| Метка | Δ, мс |
|---|---:|
| `t0 → t1` | 3 082,4 (реакция человека) |
| `t1 → t2` | 0,4 |
| `t2 → t3` | 0,0 (чанк уже загружен) |
| `t3 → t4` | 0,5 |
| `t4 → t5` | 23,2 |
| `t5 → t6` | **216,6 (GPU-заливка)** |
| `t6 → t7` | 19,9 |
| `t7 → t8` | 79,8 |

`t1 → t8` = **340,4 мс**, `max frame gap` = **189 мс** (`alarming = true`).

**Вывод для следующей волны.** CPU-часть перехода — 24 мс, GPU-заливка —
216,6 мс, то есть **64 % времени**. Оптимизировать генерацию дальше
бессмысленно: узкое место переехало в передачу геометрии на GPU и в блокировку
кадра. Это прямой вход для **8.11b (A-15)**: пре-рендер и ограничение угловой
скорости камеры должны закрывать участок `t5 → t6 → t7`, а не генерацию.

**Ограничение метода.** Замер «тёплый»: чанк загружен, патч пришёл из
префетча (`t2 → t3` и `t3 → t4` близки к нулю). Холодный первый переход
в сессии ещё не измерен — его надо снимать отдельно, иначе первый вход
выглядит лучше, чем он есть.

**Порог бюджета главного чанка** был расширен дважды: +2 КБ (вынудил
экономить на читаемости — ошибка Гайдлайнера) и +4 КБ после правок A-26.
Текущий предел — **331 266 Б**. Дальше расширять только под измеримую
функциональность, а не под форматирование кода.
