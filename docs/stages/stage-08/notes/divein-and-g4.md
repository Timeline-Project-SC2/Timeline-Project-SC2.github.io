## 3. Порционная (staged) GPU-догрузка `StructureRenderer` без пересоздания VAO (Патч 8)

Одномоментная синхронная заливка рельефа $256 \times 256$ и всех VBO инстансов в
одном кадре могла вызывать пик кадрового времени на мобильных GPU при входе в
локальную карту. В рамках Патча 8 (`docs/stages/stage_patches.md`)
`src/local-map/local-map-renderer.ts` переведён на порционный конвейер:

- **Предвыделение VAO и буферов один раз при инициализации:**
  - `terrainVAO` создаётся заранее со статическим индексным буфером `Uint32Array`
    (`gl.STATIC_DRAW`) и предвыделенными динамическими буферами позиций и нормалей
    (`posBuf`, `normBuf`, `gl.DYNAMIC_DRAW`);
  - для всех 12 модулей `meshLibrary` заранее выделяются и привязываются к VAO
    динамические буферы `instanceVBOs` на бюджет инстансов — при приходе нового
    участка или смене масштаба **ни один VAO не пересоздаётся**.
- **Кадровый бюджет догрузки (`<= 3 мс`):**
  - метод `enqueueWorkerData(data, budgetMs?)` ставит принятый `LocalMapWorkerResponse`
    в очередь подготовки, а `processPendingUpload(budgetMs?)` порциями обновляет
    срезы вершин/нормалей террейна и буферы инстансов через `gl.bufferSubData`
    в пределах кадрового бюджета времени;
  - состояние заливки отслеживается методами `isUploading()` и `getUploadProgress()`;
    шейдерные программы и цикл кадра инкапсулированы в `compilePrograms()`,
    `renderFrame(viewProj, lightDir, options?)` и `dispose()`;
  - синхронный метод `onWorkerData(data)` сохранён для обратной совместимости и
    мгновенного fallback-пути.

## 4. Dive-in Flow на странице `/planet-globe/`, лестница масштабов и кольцо соседей

На странице планеты (`site/planet-globe/{index.html,planet-globe.css,planet-globe.ts}`)
глобус и 3D-экран локального участка объединены в единый бесшовный сценарий:

1. **Точки входа и глубокие ссылки:**
   - в инспекторе выбранного участка `#patchInspector` добавлена кнопка
     `#diveLocalMapBtn` («Погрузиться на локальную карту участка →»);
   - состояние локального экрана кодируется воспроизводимым URL
     `/planet-globe/?place=<id>&system=<systemId>&cell=<address|cell>&view=local`,
     поэтому прямая ссылка открывает сразу тот же участок и масштаб.
2. **Хореография Dive-in без блокировки камеры:**
   - генерация локального участка по активному срезу `Patch7` стартует на **первом
     кадре** подлёта камеры к выбранной ячейке;
   - камера глобуса не останавливается в ожидании воркера: по мере готовности буферы
     догружаются в `#localMapCanvas` (`#localMapStage`) порциями через
     `enqueueWorkerData` / `processPendingUpload` (с fallback на `onWorkerData`),
     после чего 3D-сцена локальной карты плавно проявляется (`fade-in`);
   - управление 3D-камерой локальной карты поддерживает орбитальное вращение,
     наклон (pitch), панорамирование и зум мышью/тачем с соблюдением общих правил
     кнопок мыши (`event.button > 1` игнорируется) и `prefers-reduced-motion`.
3. **Лестница видимой ширины `1250 … 1.2 км` (§9.4):**
   - селектор `#localScaleSel` и зум камеры проводят участок по всем 11 ступеням
     мастер-плана:
     `1250 → 625 → 312 → 156 → 78 → 39 → 20 → 10 → 5 → 2.5 → 1.2 км`;
   - HUD `#localMapHud` отображает текущий диаметр области, канонический адрес
     центра, ключ участка `patch_key`, долю суши под застройку, число активных
     3D-инстансов и прогресс GPU-догрузки.
4. **Перецентровка по 6 соседям кольца и выход на глобус:**
   - навигатор кольца `#localNeighborNav` (слоты `0..5` вокруг центральной ячейки
     `Patch7`) позволяет в один клик перецентровать локальную проекцию на любую из
     6 соседних гексагональных ячеек, запрашивая новый `extract-patch` на `canonicalV`;
  - кнопка `#exitLocalMapBtn` («← На глобус планеты») плавно возвращает пользователя
    на 3D-глобус без потери ракурса и выбранной ячейки.

> **Примечание (эволюция в Stage-8.2 … Stage-8.6):** начиная со `Stage-8.5` /
> `Stage-8.5.2` (`PR #188`, `#191`) физический радиус генерируемого участка
> зафиксирован (`LOCAL_PATCH_BASE_RADIUS_M = 2500 м`), а селектор `#localScaleSel`
> меняет только дистанцию и наклон камеры по 11-ступенчатой логарифмической шкале
> `1.2 … 1250 км` без перегенерации меша; в `Stage-8.4` / `Stage-8.6` (`PR #186`,
> `#190`, `#193`) переходы по соседям переведены на непрерывное 820-мс скольжение
> без промежуточного кадра сброса, а точка покоя камеры выровнена строго по
> Северу (`LOCAL_REST_YAW = -Math.PI / 2`) — см. раздел 7 и
> [`STAGE_8_PLANETARY_HORIZON.md`](../../STAGE_8_PLANETARY_HORIZON.md).

## 5. Фактические замеры гейта G4 (`tools/bench_local_map_stage8.mjs`)

CLI-бенчмарк `tools/bench_local_map_stage8.mjs` проверяет CPU-часть гейта **G4**
на ансамбле из 3 детерминированных seed пресета `earthlike_balanced` ($R = 6\,371$ км),
4 канонических шестиугольных архетипов (`dry_plain` — сухая равнина,
`river_junction` — речной узел со слиянием притоков, `lake_basin` — затопленная
озёрная впадина, `coastline` — морское побережье) и 4 опорных ступеней масштаба
(`1250 км`, `78 км`, `10 км`, `1.2 км`) по 3 холодных прогона на каждую точку
матрицы (`144` холодные генерации локальной карты на каждую частоту сетки).

Ключевые выводы по цифрам:
- Время `generateLocalMap` практически не зависит от глобальной частоты глобуса
  (`27,4 мс` на `v=64` и `26,5 мс` на `v=128`), поскольку срез `Patch7` сжимает
  вход воркера ровно до 7 канонических ячеек (`buildPatch7 + verifyPatchInvariants`
  укладывается в `~0,07–0,08 мс` по медиане).
- На крупном масштабе (`1250 км`) радиус окна `boxBlurSeparable` достигает
  верхнего порога `32`, поэтому медиана составляет `~28,8–29,4 мс`; на детальном
  масштабе урбанистики (`1.2 км`) медиана снижается до `~21,6–22,4 мс` (при
  пороге гейта **G4** `<= 150 мс`).
- На речных узлах и озёрных впадинах маска `buildingSpawnMask` оставляет постройки
  строго на сухих береговых ячейках кольца (`~21–53` инстанса), на морском
  побережье — строго на континентальной половине участка (`~400–455` инстансов),
  на сухой равнине — `~501–578` инстансов при **0 нарушений** маски застройки во
  всех `288` проверенных генерациях (`144` на `v=64` + `144` на `v=128`).

## 6. Проверки волны и что остаётся за владельцем

Проверки, выполняемые на ветках волны Stage-8:

```bash
npm run typecheck                           # tsc --noEmit
npm run lint                                # eslint site src
npm test                                    # модульные тесты Node (+ local-map-stage8.test.mjs в потоке Воркера 1)
npm run build                               # tsc --noEmit + Vite -> .publish/
npm run verify:publish                      # проверка 7 маршрутов, build-manifest.json и паритета экспортов
npm run verify:contract                     # кросс-проверка Python ↔ TS контракта planet_generation и PG1
node tools/bench_local_map_stage8.mjs       # гейт G4 на v=64 (<= 150 мс, 0 нарушений spawnMask)
node tools/bench_local_map_stage8.mjs --v=128
git diff --check
```

Что остаётся на визуальной и устройственной приёмке владельца (браузерная часть **G4**):
- плавность Dive-in перехода `/planet-globe/` → `#localMapStage` (первый интерактивный
  кадр `<= 1000 мс` без остановки камеры, отсутствие кадров `> 50 мс` во время
  порционной догрузки `StructureRenderer`);
- кадровая телеметрия steady-рендера локальной карты (`p95 <= 20 мс` на десктопе и
  `p95 <= 33,3 мс` на Redmi Note 10, `0` кадров `> 100 мс`);
- визуальная сшивка береговой линии, озёр `filledElevation`, русел рек на гранях
  кольца `0..5`, кругового тумана и посадки 12 модулей построек на терраформированные
  площадки на ступенях `1250 … 1.2 км`.
