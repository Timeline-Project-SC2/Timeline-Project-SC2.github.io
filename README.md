# Timeline Project — карта вселенной StarCraft

Неофициальный фан-проект: интерактивная карта вселенной StarCraft II в духе брифингов
кампании. Посетитель открывает карту галактики, выбирает область и «проваливается»
в подробную карту сектора Копрулу — со справочником систем и мест.

Сайт: **https://timelineprojectsc2.github.io/**

Интерфейс на русском, работает на компьютере и телефоне. Сведения об объектах и ссылки
на источники приводятся в их карточках; на карте отмечаются только системы с явной
привязкой, а схема служит для общего обзора. StarCraft и связанные названия принадлежат
Blizzard Entertainment; проект любительский и некоммерческий.

## Что видит посетитель

### 1. Карта галактики — стартовая страница

Экран оформлен как защищённый терминал. После загрузки печатается «консоль входа», затем
открывается карта Млечного Пути. Карту можно перетаскивать и приближать, звёздный фон
сдвигается с параллаксом, по картинке время от времени пробегают помехи.

На карте три области сканирования. Их же можно выбрать из списка (кнопка слева в шапке):

| Область | Первый клик — выбор | Второй клик — переход |
|---|---|---|
| **Сектор Копрулу** (зелёная) | рамка выделяет блок области на карте, справа открывается панель с превью | рамка сужается до квадрата, приближение до 1200 % и 2000 %, в квадрате проявляется превью — и открывается атлас сектора |
| **Пространство Зеруса** (красная) | панель «no-data available» | приближение, захват срывается — «Ошибка. Нет данных» |
| **Пространство Директората** (синяя, на карте — UED SPACE) | панель с превью | отказ: прицел краснеет, строки «ОТКАЗ ДОСТУПА.», область блокируется до перезагрузки страницы |

Выделение и переходы нарисованы в стиле брифингов StarCraft II: перекрестие, рамка захвата,
вспышки, приближение камеры.

### 2. Атлас сектора Копрулу

Подробная карта сектора: исходник 10 000 × 10 000 px, подгружается частями по мере
приближения. Рядом — справочник:

- поиск по местам и системам (клавиша `/`), фильтр по фракции, подписи систем на карте;
- каталог по разделам: системы (SYS), планеты (PLN), станции (STN), платформы (PLT),
  иное (ETC);
- карточка-досье системы или места: описание, фракция, состав системы, источник;
- кнопка «← К ГАЛАКТИКЕ» и справка «О карте».

Есть и минимальная версия атласа — только карта, поиск и досье.

### 3. Курсор

На всех страницах вместо обычной стрелки — свой курсор в том же стиле: зелёная стрелка,
по краям которой раз в 2,25 с бегут синие соты — из острия к концам крыльев и обратно
к выемке, где они сходятся во вспышке. Над всем, что можно нажать, — стопка из четырёх
непрозрачных треугольников с бегущей заливкой. Зажатая карта — крестовина из четырёх пар
шевронов остриями к центру: появляется сразу при нажатии левой кнопкой или колесом и
проявляется за 0,2 с, заливка бежит снаружи внутрь, а сам крест чуть смещается в сторону
движения. Правой кнопкой карты не тащатся. Недоступное (ОЗД после отказа) — приглушённая
стрелка. Курсор рисует сама система, поэтому он
не отстаёт от мыши; на телефонах и в режиме высокой контрастности остаётся обычный.
Проверить вид, точку клика и варианты вывода в своём браузере — страница `/cursor-test/`.

## Как это устроено

Сайт полностью статический: HTML, CSS и чистый JavaScript. Сервера, базы данных и
сборщика фронтенда нет. Всё, что нужно сайту, готовится заранее, тремя потоками:

```
Google-таблица ── tools/sync.py, раз в 6 ч ──► data/   ──┐
assets/src/    ── tools/build_assets.py    ──► assets/ ──┼──► GitHub Pages
site/          ── страницы, стили, скрипты ──────────────┘
```

- **Данные.** Системы и места ведутся в Google-таблице (вкладки `systems` и `places`).
  Для будущих 3D-планет подготовлена третья вкладка `planet_generation` с профилями
  генерации; её источник включится после создания и публикации вкладки. Воркфлоу синка
  раз в 6 часов забирает опубликованные CSV, проверяет их все вместе (профили — строгим
  валидатором против `places`) и только после успеха заменяет снимки в `data/`. Если в
  таблице ошибка, синк падает, на сайте остаются прежние данные, а в репозитории
  появляется issue «Sync failed».
- **Картинки.** В Git хранятся только исходники (`assets/src/`). Тайлы карты сектора и
  WebP-версии карты галактики, логотипа и превью собирает `tools/build_assets.py` при
  деплое (если исходники не менялись — берёт из кэша); готовые файлы в Git не попадают.
- **Публикация.** Пуш в `main` запускает деплой: собрать картинки (с кэшем), сложить
  `site/`, `data/` и `assets/` вместе и выложить на GitHub Pages. Каждый PR проверяется
  той же сборкой на Ubuntu 24.04 и 26.04, плюс синтаксис скриптов и ESLint.

## Структура репозитория

```
site/                     корень сайта — именно он публикуется
├── index.html            карта галактики (стартовая страница)
├── galaxy.js, galaxy.css   логика и оформление карты галактики
├── sector/sector.html    атлас сектора Копрулу
├── minimal/              минимальная версия атласа
├── cursor-test/          страница проверки курсора (ссылок на неё на сайте нет)
└── shared/               общее для всех страниц
    ├── app.js              атлас: карта на canvas, поиск, каталог, досье
    ├── cursor-fx.js        курсор сайта: кадры стрелки и наведения
    ├── focus-fx.js         анимация выделения и перехода (прицел брифинга)
    ├── lag-fx.js           помехи на картинке
    ├── links.js            адреса страниц и картинок — в одном месте
    ├── timeline-loader.js  экран загрузки
    └── *.css               стили и скины
data/                     данные сайта (пишет синк) и список источников (sources.json)
assets/src/               исходники картинок (в Git, на сайт не попадают)
tools/                    sync.py — синк данных, planet_generation.py — профили/ключи планет,
                          build_assets.py — сборка картинок
docs/                     инструкции и заметки
.github/workflows/        pages.yml — деплой, check.yml — проверка PR,
                          sync.yml — синк, assets.yml — картинки артефактом
```

Все ссылки внутри сайта — от корня: `/shared/…`, `/sector/sector.html`, `/data/…`,
`/assets/…`. Поэтому страницы можно переносить по папкам, не переписывая пути.

## Как что поменять

| Что | Где |
|---|---|
| Системы и места | в Google-таблице, не в CSV: [единые правила заполнения](docs/ADMIN_GUIDE.md) |
| Картинки: карты, логотип, превью | заменить файл в `assets/src/` — при деплое всё пересоберётся само |
| Адреса страниц и картинок | `site/shared/links.js` |
| Области на карте галактики | `site/index.html`, у квадрата: `data-cx`, `data-cy`, `data-size` — центр и размер, `data-frame` — рамка выделения; всё в процентах карты |
| Поведение карты галактики | `CONFIG` в `site/galaxy.js`: зум при выборе, уровни приближения при переходе |
| Длительности и вид анимации | настройки `T` и `G` в `site/shared/focus-fx.js` (как подключить модуль — в начале файла) |
| Курсор: вид, цвета, что считается кликабельным | `CONFIG` в `site/shared/cursor-fx.js` (устройство и ограничения — в начале файла); проверка — страница `/cursor-test/` |

## Текущее состояние

- Работают карта галактики с тремя областями и переходами, атлас сектора на тайлах,
  каталог и досье.
- **Данные пока тестовые:** в текущем снимке — 11 систем и 5 мест; в обоих CSV есть
  колонка `type`. Системы с полной корректной парой `x`,`y` отмечаются на карте; без
  явных координат система остаётся в каталоге без маркера.
- **Синхронизация работает:** последний запуск 18.10.2026 завершился успешно и не обнаружил
  новых изменений в опубликованных листах. Ошибки в Issues #66, #67 и #69 относятся к
  прежним запускам.
- Зерус и Директорат — заглушки без своих страниц. Описание сектора в панели — тоже
  заглушка.

## Что дальше

- Наполнить каталог настоящими системами и местами; отображать системы на карте только при наличии явной привязки.
- Починить доставку данных: например, забирать таблицу прямо при деплое, без коммита бота.
- Картинки и надписи блоков на карте галактики (сейчас они нарисованы на самой карте)
  сделать отдельным содержимым сайта.

## Запуск локально

Открывать через HTTP-сервер, а не `file://`. Корнем сервера должен быть собранный сайт —
страницы плюс `data/` и `assets/`:

```bash
python3 -m pip install -r tools/requirements.txt    # Pillow — для сборки картинок
python3 tools/build_assets.py                        # тайлы и WebP в assets/

rm -rf .publish && mkdir -p .publish
cp -R site/. .publish/ && cp -R data assets .publish/ && rm -rf .publish/assets/src
python3 -m http.server 8080 --bind 0.0.0.0 --directory .publish
```

Проверки перед PR — те же, что в `check.yml`:

```bash
for f in site/*.js site/shared/*.js; do node --check "$f"; done
npm install --no-save --no-package-lock eslint@10 globals@17 && npx eslint site
python3 -m py_compile tools/build_assets.py tools/sync.py tools/planet_generation.py
python3 tools/planet_generation.py validate
python3 -m unittest discover -s tests -p 'test_*.py'
python3 tools/build_assets.py --check
```

## Публикация и картинки — подробности

- В настройках репозитория (**Settings → Pages → Build and deployment → Source**) должен
  стоять **GitHub Actions**. При «Deploy from a branch» Pages публикует корень репозитория
  через Jekyll, сайт оказывается под `/site/`, и ссылки ломаются.
- Ключи `build_assets.py`: без ключей — собрать то, что устарело; `--force` — пересобрать
  всё; `--check` — только проверить свежесть; `--sync-only` — обновить версии ссылок и
  `data/meta.json` по уже собранным файлам (так деплой работает, когда картинки взяты из кэша).
- Свежесть сборки считается по SHA-256 исходников: подменили файл — сборка сама поймёт,
  что устарела.
- Pages кэширует файлы на 10 минут, поэтому в адресах картинок есть версии (`?v=…` от хэша
  исходников); их расставляет сам `build_assets.py`. У скриптов и стилей сайта `?v=` в HTML
  поднимают вручную после правок.

Что из чего собирается:

| Исходник в `assets/src/` | Результат в `assets/` |
|---|---|
| `koprulu-sector.jpg` (10 000²) | `tiles/` — пирамида WebP 512×512 на четырёх уровнях, манифест `tiles.json`, подложка `map-preview.webp` |
| `galaxy-map.jpg` | `galaxy-map-1200/2000/3000.webp` под `srcset` |
| `timeline-project-logo.png` | `timeline-project-logo.webp` — логотип экрана загрузки |
| `koprulu-macket.jpg`, `ozd-macket.png` | `koprulu-macket.webp`, `ozd-macket.webp` — превью областей |
